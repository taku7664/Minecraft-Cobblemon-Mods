# Better Cobblemon Music 재로드와 확장 경계 보강

| 항목 | 값 |
|---|---|
| Status | `shared` |
| Effective | 2026-08-22 |

| 대상 | 외부 설정 재로드, 생성 리소스팩, 음원 검증, 검사 주기, 선택형 콘텐츠 제공자 |
| 주 독자 | 빡대리님과 이후 구현·검증 담당자 |

## 1. 재로드 원자성

- `/bcm reload`는 새 `music.json`을 후보 스냅샷으로 읽되 즉시 활성화해서는 안 된다 **MUST NOT**.
- 생성 리소스팩은 게임 폴더의 별도 임시 디렉터리에서 완성한 뒤 디렉터리 단위로 게시해야 **MUST** 한다.
- Minecraft 리소스 재로드가 성공한 뒤에만 후보 설정을 활성화하고 이전 팩 백업을 정리해야 **MUST** 한다.
- 팩 게시 또는 Minecraft 리소스 재로드가 실패하면 이전 생성팩을 복원하고 후보 설정을 폐기해야 **MUST** 한다.
- 명령 성공 메시지는 비동기 Minecraft 리소스 재로드가 실제로 끝나기 전에 보내서는 안 된다 **MUST NOT**.
- 동시에 두 재로드를 실행해서는 안 된다 **MUST NOT**. 이미 재로드 중이면 후속 요청은 기존 설정을 건드리지 않고 실패 결과를 반환해야 한다 **MUST**.

제자리에서 음원과 `sounds.json`을 차례로 덮어쓰는 방식은 설정·디스크·Minecraft 리소스 상태가 갈라질 수 있어 폐기한다.

## 2. 음원과 경로 검증

- 설정 음원 경로는 소문자 Minecraft 리소스 경로 문자와 `.ogg` 확장자만 허용해야 **MUST** 한다.
- 존재하는 음원은 생성팩 게시 전에 `OggS` 컨테이너와 Vorbis 식별 패킷을 확인해야 **MUST** 한다.
- 파일이 없으면 기존 누락곡 폴백을 유지할 수 있다 **MAY**. 파일은 있지만 형식이 잘못됐으면 재로드 전체를 거부해야 **MUST** 한다.
- 검증 실패는 정확한 상대 음원 경로를 사용자 오류에 포함해야 **MUST** 한다.

확장자만 `.ogg`인 FLAC·임의 바이트 파일을 생성팩에 포함하는 방식은 Minecraft 리소스 실패를 늦게 발견하므로 폐기한다.

## 3. 검사 비용

- `scanIntervalSeconds`는 최소 `0.25`초여야 **MUST** 한다. 더 작은 값은 매 틱 검사로 수렴하므로 설정 오류로 거부한다.
- 기본값 `1.0`초는 유지해야 **MUST** 한다.
- RCT 역할은 같은 월드와 actor UUID에서 확인된 결과를 제한된 크기로 캐시해야 **SHOULD** 한다.
- 엔티티가 아직 보이지 않거나 RCT 데이터가 아직 도착하지 않은 상태는 빈 결과로 고정 캐시해서는 안 된다 **MUST NOT**.

## 4. 선택형 콘텐츠 제공자

- 제공자 등록 맵의 잠금은 등록 목록 스냅샷을 만드는 동안에만 보유해야 **MUST** 한다.
- 외부 제공자 코드는 전역 등록 잠금 밖에서 호출해야 **MUST** 한다.
- `RuntimeException`, `LinkageError`, null과 잘못된 콘텐츠 ID는 해당 제공자만 건너뛰고 다음 제공자 또는 기본 선곡을 유지해야 **MUST** 한다.
- 같은 제공자의 첫 실패는 제공자 ID와 함께 한 번 기록해야 **MUST** 하며 매 검사마다 같은 경고를 반복해서는 안 된다 **MUST NOT**.
- 공개 `BattleMusicContentProvider` 메서드 형식은 이번 보강에서 변경하지 않는다 **MUST NOT**.

## 5. 애드온 버전 계약 정정

Obsoletes: `BETTER_COBBLEMON_MUSIC_MBC_INTEGRATION_DECISION.md` §1의 “같은 제품 버전” 요구

- 음악 본체와 MBC는 독립 제품 버전을 유지해야 **MUST** 한다.
- 연동 애드온은 실제 공개 API 호환 범위를 `fabric.mod.json`에 선언해야 **MUST** 하며, 단순히 세 모듈 버전 문자열이 같다는 이유로 호환을 판정해서는 안 된다 **MUST NOT**.
- 같은 제품 버전 요구는 2026-08-22부로 종료하며 후속 구현에서 다시 도입해서는 안 된다 **MUST NOT**.

## 6. 스키마 1에서 유지하는 항목

- 기존 사용자 `music.json`과 저장소 기본 JSON은 이번 보강에서 자동 수정하지 않는다 **MUST NOT**.
- `biomePathContains`와 바이옴 태그 객체는 스키마 1에서 선언 순서 우선 계약을 유지한다 **MUST**.
- 객체 순서에 의존하지 않는 배열·명시적 우선순위 형식은 빡대리님이 별도 데이터 쓰기 계획의 정확한 형식을 승인한 뒤에만 후속 스키마로 도입할 수 있다 **MAY**. 결정자는 빡대리님이며, 기존 설정의 선곡 결과를 바꿀 수 있어 이번 안정성 수정에서 분리한다.

## 7. 검증 경계

- 구현 단위 테스트는 후보 설정 비활성, 생성팩 게시·원복, 가짜 OGG 거부, 검사 주기 하한, 역할 키 제한, 제공자 재진입과 바이너리 불일치를 포함해야 **MUST** 한다.
- 빌드와 단위 테스트 성공은 실제 Minecraft 리소스 재로드·장시간 프레임·음악 청감 성공으로 간주해서는 안 된다 **MUST NOT**.
