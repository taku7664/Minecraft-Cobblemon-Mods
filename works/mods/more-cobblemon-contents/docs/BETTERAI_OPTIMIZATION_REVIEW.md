## 2026-10-23 기술 최적화 1~4 구현

사용자가 결과 보존 기술 최적화만 승인했다. 아래 최신 우선순위 표의 1~4를 대상으로 했으며, 점수식·상수 가격·근사 옵션·JSON 로더를 추가하지 않았다.

1. `EngineRuntimeDex.digest`의 SHA-256 입력 순서와 문자열 사이 0 바이트를 유지하고 `HexFormat.of().formatHex(bytes, 0, 8)`로 같은 앞 16자를 만든다.
2. `MatchupPairs`는 공격 기술과 요청한 대면만 제공하는 별도 인터페이스다. `MatchupScores`는 기존 전체 표를 제공한다. 공통 `buildPairs`에서 기존 아군→상대 순서와 합산 순서를 유지한다. 회복 후에는 양 팀의 CURRENT 대면 전체, 비독 디버프 후에는 해당 상대에 대한 CURRENT 대면만, 잔류 선공 뒤 후속 진입에는 벤치×깎인 상대 CURRENT 대면만 만든다. 독의 반복 잔여 피해·전체 기본 표의 스윕/저지/상태기/진입 계산은 유지한다. 부분 표가 전체 파생 표까지 완성했다고 표시하지 않는다.
3. `LocalDecisionCalculationScope`가 한 판단 동안 같은 상태/점수표 객체와 같은 튜닝의 포켓몬 가치 읽기를 공유한다. 기존 정규화 결과를 한 번 구하고 호출자가 요청한 기존 flat 단위로 곱하므로 가치·위협·standing 계산을 반복하지 않는다. 같은 컨텍스트의 만피 판/표도 공유한다. 입력 객체는 참조 동일성으로 구분하며 기존 전역 만피 표의 공유 범위를 넓히지 않는다. 새 임시 캐시는 128항목까지 보관하며 초과 시 버린 값을 같은 식으로 재계산한다. 이 수는 점수 기준값이 아니다.

예를 들어 평균 피해 KO 표는 다음처럼 만들 수 있다. `d`는 명중 시 평균 피해, `H`는 남은 HP, `p`는 실제 명중 확률이다.

- 필요한 명중 횟수: `k = ceil(H / d)`.
- 기대 사용 횟수: `k / p`. `d=0` 또는 `p=0`이면 KO까지 무한대.
- `n`번 사용 뒤 KO 확률: `Pr(Binomial(n, p) >= k)`. HP 1000칸 대신 0~6회 명중의 작은 표만 필요하다.
- 옹골참/기합의띠가 첫 KO급 타격을 막으면 첫 타격 상한을 적용하고 필요한 다음 타격을 센다. 연속 사용 금지의 사용 간격, 1회 자폭, 다단히트는 별도 기계 규칙을 유지한다.
- 미공개 특성은 현재 정책대로 후보별 간단식을 각각 계산한 뒤 균등 평균한다. 옹골참/깨어진갑옷의 피해량을 먼저 평균해 다시 확정 KO로 만드는 방식은 이번에 바로잡은 테스트의 취지를 잃는다.

랭크 변화 간단식도 `명상=고정 200점`으로 돌아갈 필요는 없다. 현재 피해 `D`와 전후 능력치 배율의 비 `r`로 `min(남은 HP, D*r) - min(남은 HP, D)`를 계산하고 기존 HP 점수 단위로 바꾸는 방식이면 된다. `r`은 실제 적용되는 배율이다. 랭크 상한·천진·능력치 무시 효과 등으로 변하지 않는 항은 1이어야 한다. KO 항과 스피드 항은 각각 자기 변화분을 더한다. 단순화로 경계 판정이 거칠어지는 것은 옵션의 명시적인 비용이다.

## JSON 형태와 연결 위치 제안

  "simpleDebuffValue": false,
  "meanDamageKoProfile": false,
  "simpleSwitchEntry": false,
  "simpleActingChance": false,
  "simpleHealing": false

### 추가 발견: 미공개 옹골참의 공개 사실과 대면 KO 표가 다름 (미수정)

이번에 기대값을 갱신한 테스트의 입력을 그대로 만들어 공개 사실과 `LocalMatchupScoreCalculator.moveMatchups`를 교차검증했다.

| 입력 | 공개 KO 사실 | 대면 표의 1회 KO 확률 |
|---|---:|---:|
| 옹골참/깨어진갑옷 미확정, HP 100% | 0.5 | **1.0** |
| 옹골참 공개, HP 100% | 0 | 0 |
| 깨어진갑옷 공개, HP 100% | 1 | 1 |

공개 사실은 `abilityBoards`가 후보별 `facts`의 생존 판정을 계산하고 `mixedDamage`에서 KO 확률을 평균하므로 0.5가 맞다. 대면 표의 피해 롤 가설 혼합은 옹골참의 **생존 효과**를 피해 롤에 담지 못한다. 이후 첫 타격 생존 상한은 원래 미확정 상태를 보고 옹골참이 확실할 때만 적용하므로 KO 확률 1이 남는다. 공개된 옹골참을 반영한 직전 수정과는 다른, 미공개 후보 혼합 경로의 누락이다.

근거는 `full-review-20261023/ability-crosscheck.json`, `ability-run.log`, `AbilityCrosscheck.kt`다. 이번 작업은 기존 테스트 갱신·검수·병목 정리이므로 AI 계산 소스는 추가로 바꾸지 않았다. 테스트 277개 통과가 이 불일치까지 해결됐다는 뜻은 아니다.

후속 수정은 특성 이름으로 고정 KO 확률을 덮어쓰는 방식보다, 후보별 KO 누적표를 만든 뒤 균등하게 합치는 공통 경로가 맞다. 생존 확률은 후보별 생존 확률의 평균이고, 살아 있는 경우의 누적 피해는 생존 확률로 가중해 합쳐야 한다. 이 문제는 최적화 옵션의 근사 오차와 구분해 다뤄야 한다.

**같은 경로의 추가 검증:** 지면 기술, 미공개 부유/내열 두 후보, 내열이면 확정 KO인 입력도 대조했다. 공개 사실은 0.5인데 대면 표의 1회 KO는 **0.9375**, 2회 이내 KO는 **0.99609375**였다. 공개 부유는 두 값 모두 0, 공개 내열은 모두 1이므로 후보가 유지된다면 균등 평균은 사용 횟수와 관계없이 0.5가 맞다.

피해 롤 혼합의 추가 문제는 다음과 같다. 부유 분기는 `[0]` 하나, 내열 분기는 `[1, ..., 1]` 16개를 반환한다. 현재 `rollsWorkedOut`은 `each.flatten()`으로 17개를 이어 붙인 뒤 16개로 다시 고르므로 면역을 1/2이 아니라 1/16처럼 읽는다. 이후 KO 누적에서는 그 혼합 피해를 사용마다 다시 뽑는 형태가 되어, 계속 같은 특성을 가진다는 조건도 유지되지 않는다. 단순히 면역 배열 길이만 맞춰도 여러 번 사용 시의 고정 특성 조건은 별도로 해결해야 한다. 근거는 `worlds-crosscheck.json`, `worlds-run.log`, `WorldsCrosscheck.kt`다. 가설별 누적표를 만든 뒤 가설 확률로 합치는 수정 방향은 이 경우에도 해당한다.
