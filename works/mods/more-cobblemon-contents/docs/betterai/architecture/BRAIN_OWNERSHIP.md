## 1. 결정

- `BattleBrain`은 한 판단 요청의 최종 행동을 선택하는 유일한 주체여야 한다(MUST).
- Better AI 로컬 Brain과 OpenRouter Brain은 동일 인터페이스를 구현하는 독립된 판단 주체여야 한다(MUST). OpenRouter가 로컬 Brain의 결정을 재평가하는 감독 계층이 되어서는 안 된다(MUST NOT).
- API 키·모델이 유효해 OpenRouter Brain이 선택된 배틀에서는 합법 행동이 둘 이상인 모든 판단 요청을 Router에 보내야 한다(MUST).
- 합법 행동이 하나뿐이면 선택의 여지가 없으므로 HTTP 요청 없이 그 행동을 반환할 수 있다(MAY).
- Router가 반환한 합법 `actionId`는 로컬 점수, 추천, 계획 또는 신뢰도 때문에 교체되어서는 안 된다(MUST NOT).
- API 키가 없거나 외부 Brain이 비활성인 배틀은 Better AI 로컬 Brain이 판단해야 한다(MUST).
- 외부 실패·시간 초과·잘못된 `actionId`는 해당 응답을 실패로 처리하고 외부 폴백 조정기가 같은 공개 컨텍스트로 준비한 Better AI 로컬 Brain 결과를 사용해야 한다(MUST).
- 빠른 폴백을 위해 Router와 Local 판단 계산을 동시에 시작할 수 있다(MAY). Router가 성공하면 Local 결과는 행동·조언·기억 어느 곳에도 반영해서는 안 된다(MUST NOT).
- 전체 폴백 순서는 `OpenRouter Brain → Better AI 로컬 Brain → 본체 Cobblemon 기준선 → 비상 안전 행동`이어야 한다(MUST).

## 2. 계산 자료의 책임

- 공통 계산기는 판단 주체가 아니라 공개 관측과 확정된 게임 규칙에서 계산 가능한 사실 공급자여야 한다(MUST).
- 공통 계산기는 기본 명중률, 공개 타입 상성, 공개 자속, 정확히 계산 가능한 피해 범위·난수 KO 확률·행동 순서·회복·반동·진입 피해를 후보별 자료로 제공할 수 있다(MAY).
- 계산기는 효용 점수, 후보 순위, 추천 행동, 교체 권고, 트레이너 성격 가중치 또는 계획 가중치를 만들거나 전달해서는 안 된다(MUST NOT).
- 정확한 값을 공정한 정보만으로 계산할 수 없으면 중립값을 꾸며 넣지 말고 `null`과 `UNKNOWN` 사유를 전달해야 한다(MUST).
- 기본 명중률은 명중·회피 랭크, 특성, 날씨와 기술 효과까지 반영한 최종 적중 확률로 표현해서는 안 된다(MUST NOT). 각 값의 계산 범위가 응답 자료에서 구분되어야 한다(MUST).
- 상대의 미공개 기술·특성·도구·EV·성격이나 대기 포켓몬 내부 값을 계산 입력으로 사용해서는 안 된다(MUST NOT).
- 로컬 Brain과 OpenRouter Brain은 같은 공정 정보 경계와 같은 계산 사실을 받을 수 있어야 한다(MUST).

## 3. Router 요청과 응답

- Router 요청은 전체 합법 후보와 후보별 사실, 공개 보드, 공개 이벤트·추론, NPC 난도·성격과 전투 기억을 전달해야 한다(MUST).
- 프롬프트는 계산 사실이 추천이나 순위가 아니며 `UNKNOWN`을 추측으로 메우지 말라고 명시해야 한다(MUST).
- Router는 후보의 `actionId` 하나를 최종 선택해야 한다(MUST).
- 예측·계획·이유·심리전 표시는 다음 판단을 돕는 구조화 기억으로 받을 수 있다(MAY). 이 보조 필드가 잘못됐더라도 `actionId`가 합법이면 행동 자체를 로컬 판단으로 교체해서는 안 된다(MUST NOT).
- 자유 텍스트를 게임 채팅에 직접 노출해서는 안 된다(MUST NOT).
- 늦게 도착한 응답은 현재 턴과 기억 양쪽에서 폐기해야 한다(MUST).

## 4. 설정 호환

- 스키마 1의 `maximumCallsPerBattle`은 기존 서버 설정을 깨지 않기 위해 읽기와 범위 검증만 유지한다(MUST).
- `maximumCallsPerBattle`은 Router 판단 횟수를 제한해서는 안 된다(MUST NOT).
- 기존 설정 파일을 자동 재작성하거나 마이그레이션해서는 안 된다(MUST NOT).
- 다음 설정 스키마에서 이 필드를 제거하려면 별도 설정 쓰기 계획과 빡대리님 확인이 필요하다(MUST).

## 5. 현재 구현 범위와 미완료 경계

- 현재 계산기는 공개 기술 템플릿의 기본 명중률, 공개 활성 타입의 상성 배수와 자속 여부를 계산한다.
- 현재 공개 DTO에는 공정한 공격·방어 실수치 범위와 대상 현재 HP 실수치가 없고, Cobblemon의 기존 `StrongBattleAI.calculateDamage`는 실제 전투 내부 객체를 입력으로 받아 숨은 값 접근 위험이 있다.
- 따라서 정확한 피해 범위, 난수 KO 확률, 최종 적중률과 행동 순서는 현재 `UNKNOWN`이다. 이 상태는 완성된 피해 계산기로 간주하지 않는다(MUST NOT).
- 후속 구현은 숨은 값과 분리된 공개 스탯 가설 범위와 부작용 없는 Cobblemon 1.7.3 피해 계산 호환 계층을 먼저 확정해야 한다(SHOULD).

## 6. 검증 계약

- Router Brain은 합법 후보가 둘 이상인 연속 20회 요청에서 20회 외부 전송해야 한다(MUST).
- `maximumCallsPerBattle = 1`인 기존 설정도 위 동작을 제한하지 않아야 한다(MUST).
- Router가 로컬 Brain과 다른 합법 행동을 선택하면 Router 행동이 그대로 반환되어야 한다(MUST).
- Router 실패는 내부에서 로컬 선택으로 숨기지 않고 외부 폴백 조정기로 전달되어야 한다(MUST).
- 합법 후보 하나인 요청은 외부 전송 없이 완료되어야 한다(MUST).
- 계산 자료에 효용·순위·추천 필드가 추가되지 않는지 계약 테스트로 검증해야 한다(MUST).
- 동일한 공개 관측에서 숨은 상대 세트만 바꿔도 계산 자료와 Router 요청이 달라지지 않아야 한다(MUST).
- 로컬 Brain의 고정 시드 10,000회 회귀는 결정성, 합법성, 비포기를 검증해야 한다(MUST).

## 7. 폐기한 대안과 종료 선언

- 결정 지점에서만 Router를 호출하고 일반 턴은 로컬 Brain이 외부 계획을 집행하는 코치/선수 구조는 판단 소유권이 섞이고, API 키가 있는 서버에서도 대부분의 턴을 로컬이 결정하므로 폐기한다.
- 로컬 점수 상위 후보만 Router에 전달하는 방식은 Router의 선택 공간에 로컬 판단이 개입하므로 폐기한다.
- 계산 자료에 `expectedUtility`, `localRank`, `recommendedAction`을 넣는 방식은 사실 공급과 판단을 섞으므로 폐기한다.
- 2026-08-18 이후 이 제품 계열에서 결정 지점 호출 정책과 `maximumCallsPerBattle` 실행 제한은 다시 구현하지 않는다. 다시 검토하려면 이 문서를 명시적으로 `Obsoletes`하는 후속 결정이 필요하다.
