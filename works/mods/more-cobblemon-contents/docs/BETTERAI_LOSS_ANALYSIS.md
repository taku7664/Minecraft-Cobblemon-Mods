## 3. 현재 보스의 실제 잘못: 교체 피격에서 다른 기술을 누락

### 15번 조합, CURRENT=p1, 14턴

패리퍼 HP 59.56%, 벤치 빠르모트 55.48%, 잠든 나이킹 40.41%다. 상대 마지막 브리두라스는 스텔스록 진입 후 HP 17%다. 실제 세트는 용성군·드래곤테일·러스터캐논·10만볼트다.

`LocalTurnCostScoreCalculator.switchIn`은 **나가는 패리퍼를 상대로 가장 좋은 기술**인 10만볼트를 고른다. 동점인 기술들만 추가로 고려한다. 용성군은 명중률을 포함한 대면 점수가 0.9여서 10만볼트의 1.0과 동점이 아니므로 빠진다.

들어오는 빠르모트는 축전이라 10만볼트가 무효다. 무효 공격은 피해 대면 목록에 없으므로 `predicted=null`, 빈 선택을 `entry(null)`로 계산해 **진입 생존율 1.0·피해0**이 된다. 전기 무효 자체는 맞지만, 이미 예상하는 용성군 등 나머지 선택의 위험을 함께 지운 것이 문제다. 모든 면역 교체가 잘못이라는 뜻은 아니다.

진단 재구성의 일반 상대 의도 예측은 10만볼트 57.4613%, 용성군 38.5175%, 러스터캐논 2.9688%, 추정 지진 1.0524%였다. 이 확률과 진입 대상별 생존율(1, 0.1, 1, 0)을 단순 대조하면 약 **64.28%**로, 교체 표의 100%와 차이가 있다. 이는 누락을 보여 주는 진단값이며 적용한 새 식이나 최종 교체 점수가 아니다. 공격 행동의 `actingHit`에서는 별도 조건부 분포(10만볼트 약78.73%, 용성군 약19.26% 등)를 쓰므로 이 두 분포도 동일하다고 취급하지 않는다.

실제 판단의 `stages.internals["switch:switch 3"]`과 현재 식을 대조하면 다음과 같다.

```text
switchGoesOn = stayGoesOn = 0.7773972602739726
falls = 1.0, survival = 1.0
standingKept = 0.41500000000000004
standingLost = 3.9473972602739726
kept = falls * standingKept - (1 - survival) * standingLost
     = 0.415 - 0 = 0.415
gain = switchGoesOn - stayGoesOn + kept - reentryHpLoss
     = 0 + 0.415 - 0 = 0.415
switchAnchor 적용 후 최종값 = gain * 100 + simulationBlindAdjustment
                          = 41.5 - 5 = 36.5
```

빠르모트의 남은 가치 `standingLost`는 약3.947로 크게 읽고 있었다. 그 가치를 몰랐던 것이 아니라 **생존율을1로 처리해 잃을 위험에0을 곱했다.** `gain`은 기존 `SWITCH_MARGIN=0.5` 미만이라 직접 가산되지 않고 `uncreditedGains`를 통해 같은 교체 값으로 전달된다. 고정 기준값 제거는 별도 보류 범위이며 이번에 변경하지 않았다.

실제로는 상대가 용성군을 써서 빠르모트가 바로 쓰러졌고, 다음 교체로 나온 패리퍼도 10만볼트에 쓰러져 17턴에 패했다.

```text

진입 교환 점수 = sum(q_i × E_i)

```
