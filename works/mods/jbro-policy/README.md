# jbro Policy

jbro 포켓몬 서버에 적용하는 정책과 다듬기 기능을 하나로 모은 Fabric 모드입니다. 예전 서버의 `cobblemon-server-policy`, `cobleserver-legendary-policy`, `minecraft-policy`와 전설 스폰 데이터팩을 이 모드로 합쳤습니다.

- Mod ID: `jbro_policy`
- 실행 환경: 서버와 클라이언트 모두 필요
- 필요 모드: Fabric API, Fabric Language Kotlin, Cobblemon 1.8.1
- 선택 모드: More Cobblemon Contents: League Challenge(채팅 등급), Cobblenav(`/pokenav`, `/포켓내비`), Simple MyRoom(`/마이룸`)
- 설정 파일: `config/jbro-policy.json`
- 새 서버를 열 때 맞출 설정: [docs/SERVER_OPEN_CHECKLIST.md](docs/SERVER_OPEN_CHECKLIST.md)

## Xaero 웨이포인트

클라이언트에 Xaero's Minimap과 `jbro-policy`를 함께 설치하면
`/waypoint [이름]`(`/웨이포인트 [이름]`)으로 현재 위치에 영구 웨이포인트를 바로 저장합니다. 이름을 생략하면
`Waypoint`입니다. 명령은 클라이언트에서 실행하며 이름의 줄바꿈·콜론은 허용하지 않습니다.
접속 중 새로 생성된 Xaero 월드의 웨이포인트 텔레포트 설정은 끄고 저장합니다.
기존 월드의 설정·기본 키를 게임 시작 전에 준비하는 코드는 `ppakemon-client-setup`에 있습니다.

## 광장

`/plaza enter`(`/광장 들어가기`)로 광장 차원(`jbro_policy:plaza`)에 가고, `/plaza exit`(`/광장 나가기`)로 들어오기 전 위치에 돌아옵니다.

- 이동 대기시간과 피해 후 대기시간은 없습니다. 포켓몬 배틀 중에는 오갈 수 없습니다.
- 복귀 위치는 월드 데이터에 저장되므로 광장에서 접속을 끊어도 나중에 돌아갈 수 있습니다.
- 날거나 무언가를 타고 들어왔다면 그 아래 땅을 복귀 위치로 저장합니다. 돌아갈 때 그 자리가 막혔으면 근처 4칸 안의 설 자리(마른 바닥 우선)로 보내고, 그마저 없거나 복귀 위치나 원래 차원이 없으면 리스폰 지점, 그다음 월드 스폰으로 보냅니다.
- 마이룸 같은 다른 허브와 오가도 됩니다. 다른 허브에서 광장에 들어오면 이미 저장된 복귀 위치를 그대로 두고, 허브를 모두 벗어나면(다른 이동 수단 포함) 복귀 위치를 지웁니다. 그래서 `/plaza exit`는 허브 나들이를 시작하기 전 자리로 돌아갑니다. 다른 허브 차원은 설정 파일의 `plaza.otherHubDimensions`(기본값 `["myroom:rooms"]`)에 적습니다.
- 광장 아래로 떨어지거나 치명적인 피해를 받으면 원래 위치로 돌려보냅니다.
- 처음 열린 광장에는 착지 지점 아래에 9×9 석재 벽돌 발판을 깝니다. 착지 좌표는 설정 파일의 `plaza`에서 바꿉니다.
- 광장 바이옴(`jbro_policy:plaza`)에는 비가 오지 않고 몹이 스폰되지 않습니다. 광장 바이옴이 생기기 전에 만들어진 광장 청크는 서버 시작 때 한 번 광장 바이옴으로 바꿉니다(청크 X/Z −24~23).
- 마이룸(`myroom:rooms`)과 광장(`jbro_policy:plaza`)에서는 OP를 포함해 침대를 사용할 수 없습니다. 침대로 스폰 지점을 바꾸는 것을 막는 정책이며, `jbro-policy`가 두 차원에 적용합니다. 이미 저장된 스폰 지점은 변경하지 않습니다.

### 광장 보호

OP(권한 2 이상)가 아닌 플레이어에게 적용합니다.

| 막는 것 | 허용하는 것 |
| --- | --- |
| 블록 부수기와 설치 | 음식 먹기, 볼 던지기 같은 아이템 사용 |
| 아이템을 블록에 쓰기(괭이질, 뼛가루, 부싯돌, 스폰 알 등) | 문, 상자, PC, 회복장치 같은 블록 사용 |
| 양동이 쓰기 | 포켓몬과 NPC 상호작용 |
| 엔티티 공격, 갑옷 거치대·액자 조작 | |

광장 안의 생명체는 피해를 받지 않습니다(OP의 공격 제외). 폭발, 불 번짐, 유체 흐름, 피스톤은 광장의 블록을 바꾸지 못합니다.

## 야생 포켓몬

- 야생 포켓몬의 IV를 구간 가중치로 뽑습니다. 기본값은 0~9가 20, 10~19가 45, 20~29가 25, 30~31이 10입니다.
- 새로 스폰되는 우두머리는 최소 2V(서로 다른 능력치 두 개 이상이 IV 31)를 보장합니다. 구간 추첨 뒤 31인 능력치가 두 개보다 적으면 부족한 개수만 무작위로 31로 올립니다. 이미 3V 이상이면 유지하며, 나머지 IV는 바꾸지 않습니다. 일반 야생 IV 구간 추첨을 꺼도 우두머리 2V 보장은 적용됩니다. 기존 포켓몬을 일괄 보정하지 않습니다.
- 야생 우두머리는 Cobblemon이 가까이 온 플레이어의 파티 최고 레벨보다 4~20 높게 레벨을 맞춥니다. 이 레벨을 그 플레이어가 우두머리 위치에서 일으키는 일반 야생 스폰 범위(리그 레벨캡·구역 기준 중 낮은 값의 −15~−5, 최저 1) 안으로 맞춥니다. 리그 챌린지가 없으면 Cobblemon 계산을 그대로 둡니다. 이때 진화 최소 레벨보다 낮아질 수 있습니다(예: 레벨캡 16이면 우두머리 레트라도 11).
- 야생 스폰, 화석 복원, `/givepokemon`, `/spawnpokemon`으로 생긴 포켓몬은 1/30 확률로 숨겨진 특성을 받습니다.

## 편의 기능

- **첫 접속 키트:** 처음 접속한 플레이어에게 몬스터볼 20개와 상처약 10개를 주고 환영 메시지를 보냅니다. `config/jbro-policy-discord.json`의 `inviteUrl`이 있으면 눌러서 여는 디스코드 초대 링크도 함께 보냅니다(`/디코인증`과 같은 링크). 이 모드를 넣기 전에 접속한 적이 있는 플레이어는 받지 않습니다.
- **`/wiki` (`/위키`):** 서버 위키가 켜져 있을 때 내 정보와 함께 위키를 여는 링크를 줍니다. `/wiki reset`은 새 링크를 주고 예전 링크를 막으며, `/wiki link <플레이어>`는 OP가 다른 사람의 링크를 받습니다. 위키 서버 자체는 More Cobblemon Contents가 띄우므로, 그 모드가 있을 때만 생깁니다.
- **ESC 메뉴 버튼:** ESC 메뉴 왼쪽 위에 "피츄 도우미" 버튼 하나만 있습니다(Cobblemon UI가 있을 때). 광장 이동, 위키, 디스코드는 피츄 도우미 안에 있습니다.
- **`/피츄` (`/pichu`):** 피츄 도우미 화면을 엽니다(클라이언트 명령, Cobblemon UI 필요). ESC 메뉴의 "피츄 도우미" 버튼으로도 열립니다. 배경은 ESC처럼 흐려지고, 왼쪽 30%에 피츄 모델이 서서 Cobblemon 정보 화면처럼 커서를 따라 고개를 돌립니다(클릭하면 울음소리). 오른쪽 가운데에 Cobblemon UI 버튼 2열이 있습니다: 광장 가기/나가기, 마이룸 가기/나가기, BP 상점·PvP 룸(`/mcc`를 연 뒤 그 탭으로 이동), 문의하기(채팅에 `/문의 ` 입력), 구역 스폰 레벨(`/구역스폰레벨`), 그리고 맨 아래에 위키 열기·디스코드 열기. 포켓몬 아이템화·합성은 인벤토리 파티 사이드바(cobblemon-party-sidebar)에서 합니다. 서버에 없는 명령의 버튼은 꺼집니다. 아래 Cobblemon UI 대화창에서 피츄가 마우스를 올린 버튼을 설명하고, 아무것도 가리키지 않으면 파티 상태(기절·부상·빈자리)·장소·밤·비에 맞춘 말이나 혼잣말을 7초마다 바꿔 보여 줍니다. 서버에도 같은 이름의 명령이 있어서, NPC 대화의 `commands`에 `/피츄`를 넣으면 서버가 그 플레이어의 클라이언트에 화면을 열게 합니다(채팅으로 칠 때는 클라이언트 명령이 먼저 받습니다).
- **`/pokenav` (`/포켓내비`):** 포켓내비 아이템 없이 Cobblenav의 포켓내비 화면을 엽니다. Cobblenav의 `/pokenav` 하위 명령도 그대로 쓸 수 있습니다.
- **포켓내비 단축키:** 클라이언트에 Cobblenav가 있으면 Tab(키 설정의 "포켓내비 열기·닫기")으로 포켓내비를 열고, 열린 상태에서 다시 누르면 닫습니다. 서버의 `/pokenav`를 보내 여는 방식입니다. 포켓내비 아이템처럼, 손이 닿는 거리의 포케스낵을 바라보고 열면 그 스낵 기준 스폰 목록이 열립니다(`/pokenav`·`/포켓내비`를 직접 쳐도 같습니다). Cobblemon UI의 전투 정보도 Tab이고 마크는 한 키를 한 바인딩에만 넘기므로, 두 기능 모두 키 상태를 직접 읽습니다. 전투 중이거나 다른 화면이 열려 있으면 열지 않습니다.
- **`/마이룸`:** Simple MyRoom의 명령을 한국어로 씁니다. 각 하위 명령은 모드의 영어 명령(`/myroom`, 없으면 `/room`)을 그대로 실행하므로 권한·규칙·메시지는 모드 설정을 따릅니다. `들어가기 [플레이어]`(enter), `나가기`(exit), `공개`/`비공개`(public true/false), `권한허용`/`권한해제 <플레이어>`(trust/untrust), `차단`/`차단해제 <플레이어>`(ban/unban), `내보내기 <플레이어>`(kick), `상시활성 [켜기|끄기|상태]`(active), `스폰설정 [초기화]`(setspawn), `방문자`(visitors), `알림 [켜기|끄기]`(notify), `리로드`(reload, OP). `/마이룸`만 입력하면 모드의 방 정보와 도움말이 나오며, 도움말 문구는 서버의 `config/simple-myroom-messages.json`에서 한국어 명령으로 맞춥니다.
- **`/release <슬롯>`:** 파티 포켓몬을 놓아줍니다. 채팅의 [예]를 2분 안에 눌러야 확정되고, 마지막 포켓몬은 놓아줄 수 없습니다.
- **꺼낸 포켓몬 우클릭 정보창:** 내보낸 내 포켓몬을 우클릭하면 M키로 그 포켓몬을 고른 것과 같은 정보창이 열립니다. 상처약·사탕·진화 아이템처럼 Cobblemon이 그 클릭을 처리했다면 정보창은 열리지 않습니다. 몬스터볼·음식·활·도감처럼 우클릭 기능이 따로 있는 아이템은 어느 모드 것이든 그 기능을 그대로 쓰고, 그 밖의 아이템을 들었거나 맨손이면 정보창이 열립니다. 웅크리고 우클릭하면 원래처럼 상호작용 휠이 뜹니다.
- **`/test level set <1~6|all> <레벨|auto>`:** OP 전용 테스트 명령입니다. 내 파티의 그 슬롯(또는 전체) 레벨을 바꿉니다. `auto`는 League Challenge에서 지금까지 연 레벨 캡에 맞춥니다.
- **`/servercmd <콘솔 명령>`:** 현재 OP 권한 4인 접속자가 서버 콘솔 권한으로 마인크래프트 명령을 실행합니다. 예: `/servercmd list`, `/servercmd save-all flush`. 앞의 `/`는 생략하거나 한 번 넣어도 됩니다. 실행 직전에 접속·권한을 다시 확인하고 결과·오류를 요청자의 채팅에 표시합니다. 중첩된 `/servercmd` 호출은 차단합니다. 요청은 서버 틱에서 처리하므로 명령 자체의 반환값은 요청 접수 여부이며, 실제 반환값은 결과 메시지로 받습니다. 서버 셸 명령이나 정지 후 재시작은 실행하지 못합니다. 서버 모드만 업데이트하면 사용할 수 있습니다.
- **포케스낵:** 전설·환상·전설급 패러독스는 포케스낵으로 스폰되지 않습니다. 한 번도 쓰지 않은 포케스낵을 부수면 포케스낵 아이템으로 돌려받습니다.

## 전설 포켓몬

전설·환상·전설급 패러독스 103종의 스폰 조건, 필요 등급, 엔트리 조건, 등장 대사는 [docs/LEGENDARY_SPAWNS.md](docs/LEGENDARY_SPAWNS.md)에 있습니다.

모든 전설 스폰은 허용 차원을 명시합니다. 추위·하늘 같은 공통 바이옴 태그가 엔드까지 포함해도 프리져 등 오버월드 전용 종은 엔드에 나오지 않습니다. 물속·수면 스폰은 물·용암 전용 프리셋을 사용합니다. 전체 검수 범위와 종별 차원은 [docs/LEGENDARY_SPAWN_AUDIT.md](docs/LEGENDARY_SPAWN_AUDIT.md)에 있습니다.

- **내 전설:** 전설은 불러낸 플레이어만 배틀하거나 잡을 수 있습니다.
- **종마다 한 마리:** 야생에서 직접 잡은 기록만 남고, 교환이나 포켓몬 아이템으로 받은 포켓몬은 기록되지 않습니다. 이미 잡은 전설은 그 플레이어 주변에 스폰되지 않고 포켓내비 스폰표에서도 빠집니다.
- **엔트리 조건:** 32종은 파티에 특정 포켓몬이 있어야 스폰됩니다. 예를 들어 뮤츠는 파티에 뮤가 있어야 나옵니다. 포켓내비 스폰표에도 같은 조건이 적용됩니다.
- **등급 제한:** 하이퍼볼 등급은 일반 전설, 마스터볼 등급은 환상(아르세우스 제외), 챔피언은 전부 잡을 수 있습니다. 등급이 모자라면 그 플레이어 주변에 스폰되지 않고 포켓내비 스폰표에서도 빠집니다. 스폰된 뒤 등급이 바뀌는 경우에 대비해 포획할 때도 다시 확인합니다. League Challenge가 없으면 이 제한은 꺼집니다.
- **알림:** 전설이 스폰되면 종마다 다른 등장 대사와 함께 "뮤츠가 ○○ 근처에 나타났습니다!"를 서버 전체에 알립니다. 이름은 닉네임을 따르고 좌표는 알리지 않습니다.
- **`/legends <포켓몬> [플레이어]`:** 그 전설을 직접 잡았는지와 필요 등급, 엔트리 조건을 보여 줍니다. 포켓몬은 영어 ID로 입력하며 자동완성됩니다. 플레이어를 빼면 자기 자신입니다.
- **`/legends reset <포켓몬> <플레이어>`:** OP 전용입니다. 롤백 등으로 꼬인 포획 기록을 지웁니다.
- **`/spawnpokemonfor <플레이어> <포켓몬>`:** OP 전용입니다. 대상 플레이어 앞에 포켓몬을 스폰합니다. 전설이면 대상이 주인이 되고 알림이 나가며, 레벨을 지정하지 않으면 그 전설의 야생 스폰 레벨 범위에서 고릅니다. 대상이 이미 잡았거나 등급이 모자라 포획할 수 없으면 명령을 친 사람에게 알려 줍니다. Cobblemon의 `/spawnpokemon`으로 부른 전설은 주인이 없어 누구나 배틀하고 잡을 수 있습니다.

## 채팅

플레이어 채팅은 리그 챌린지 등급을 앞에 붙인 형식으로 보입니다.

```
[볼 아이콘 등급 이름] 닉네임: 대화
```

| 리그 등급 | 아이콘 | 등급 이름 색 |
| --- | --- | --- |
| 몬스터볼 (배지 0~2개) | 몬스터볼 | 빨강 |
| 수퍼볼 (배지 3~4개) | 수퍼볼 | 파랑 |
| 하이퍼볼 (배지 5~7개) | 하이퍼볼 | 노랑 |
| 마스터볼 (배지 8개) | 마스터볼 | 보라 |
| 챔피언 | 프레셔스볼 | 금색 |
| 하드 챔피언 (하드 리그 챔피언 격파) | 네더의 별 | 빨간색 그라데이션 애니메이션 |

플레이어 채팅에만 이 모드의 채팅 형식(`jbro_policy:chat`, `이름: 대화`)을 씁니다. 귓속말과 시스템 메시지, 머리 위 이름표, 탭 목록은 바뀌지 않습니다. League Challenge가 설치되지 않았거나 리그 카탈로그가 아직 로드되지 않았다면 `닉네임: 대화`로만 보입니다.

아이콘은 Cobblemon의 볼 아이템 텍스처(하드 챔피언은 마인크래프트 네더의 별 텍스처)를 `jbro_policy:rank_icons` 폰트 글리프로 불러와서 그립니다. 따라서 이 모드가 없는 클라이언트에서는 아이콘 자리에 빈 글자가 보입니다. 텍스처는 플레이어가 켠 리소스팩을 따르므로, 하드 챔피언 별은 Whimscape 팩을 쓰면 그 팩의 반짝이는 별로, 아니면 기본 네더의 별로 보입니다.

## 공지

`[공지] 내용` 형식으로 서버 전체에 공지합니다. `[공지]`는 파란색입니다.

- **명령:** `/announce <내용>` 또는 `/공지 <내용>`. 권한 레벨 3 이상(킥·밴과 같은 운영 권한)이 필요하고, 서버 콘솔에서도 쓸 수 있습니다.
- **API:** 다른 모드에서는 `jbro.cobblemon.policy.api.Announcements.broadcast(server, message)`를 호출합니다.

## 문의

플레이어가 운영자에게 문의를 보내면 디스코드 채널로 전달됩니다. 닉네임, 아이디, UUID, 경로(위키·명령어), 시각, 사유가 들어갑니다.

- **명령:** `/문의 <사유>` 또는 `/inquiry <사유>`. 모든 플레이어가 쓸 수 있습니다.
- **위키:** 서버 위키의 문의하기 페이지에서 보냅니다. `/wiki` 링크의 토큰으로 보낸 사람을 확인하므로 다른 사람 이름으로는 보낼 수 없습니다.
- **제한:** 사유는 100자 이내이고, 한 사람이 5분에 한 번 보낼 수 있습니다. 위키와 명령어가 같은 대기시간을 씁니다. 디스코드에 올리지 못하면 대기시간이 걸리지 않습니다.
- **설정:** `config/jbro-policy-discord.json`에 적습니다. 문의 채널과 웹훅이 모두 비어 있으면 문의 기능이 꺼지고 플레이어에게 그렇게 안내합니다. 봇 토큰과 웹훅 주소는 남에게 보이면 안 되는 값이라 주 설정 파일과 분리했습니다. 설정은 서버를 재시작해야 반영됩니다.

### 피츄에게 질문하기

디스코드에서 `/피츄 질문:피츄는 어떻게 진화해?`로 질문합니다. 답변은 질문한 채널에 공개됩니다.
`피츄-명령` 외의 일반 채팅방에서도 쓸 수 있으며, 해당 채널에서 유저에게 메시지 보내기와 애플리케이션 명령 사용 권한이 있어야 합니다.

- 유저마다 5분에 한 번입니다. 채널을 바꿔도 대기시간은 공유하며, AI 호출에 실패하면 다시 질문할 수 있습니다.
- 질문은 500자까지입니다. 동시에 최대 두 질문을 처리하고, 2분 안에 답을 만들지 못하면 실패 안내를 보냅니다.
- 기존 `config/jbro-policy-inquiry-review.json`의 `enabled`, `command`, `model`, `timeoutSeconds`를 사용합니다. 문의 채널·관리자 채널 설정과 계정 연동 여부는 질문 기능에 필요하지 않습니다.
- 서버를 켤 때 명령을 등록합니다. 로그인된 `agy`가 필요하며, 별도 Gemini API 키를 쓰지 않습니다.
- 질문 AI에는 파일 읽기·서버 명령·MCP·브라우저 도구를 주지 않습니다. 제한된 전용 프로필을 `~/.gemini/config/agents/jbro-pichu-chat/agent.md`에 설치하며, 다른 내용으로 바뀌면 호출하지 않습니다. 서버 로그나 플레이어 저장 자료도 전달하지 않습니다.
- 대신 서버 위키에서 질문과 관련된 부분만 골라 질문과 함께 넘깁니다. 서버 규칙·콘텐츠 질문은 위키에 근거해 답합니다. 위키 폴더는 MCC `config/more-cobblemon-contents/wiki.json`의 `directory`(기본 `config/more-cobblemon-contents/wiki`)이고, 질문마다 다시 읽으므로 위키를 고치면 재시작 없이 반영됩니다.
  - 문서를 `<h2>` 소제목 단위로 나눈 뒤, 질문과 두 글자씩 끊어 비교합니다(조사가 붙어도 맞도록). `assets/nav.js`의 문서 제목·검색 키워드가 가장 크게, 소제목이 그다음, 본문이 가장 작게 반영됩니다. 그래서 위키 본문에 없는 말("웜홀", "보상")은 `nav.js` 키워드에 넣으면 잡힙니다.
  - 가장 잘 맞는 문서 한두 개에서 점수 높은 구간을 6천 자까지 넣고, 위키 문서 목록을 늘 함께 넣습니다. 맞는 문서가 없으면(잡담 등) "자주 묻는 질문" 문서만 넣습니다.
  - 위키가 없으면 서버 규칙은 모른다고 답하고 `/문의`를 안내합니다. 위키에 없는 내용은 피츄도 모르니, 자주 묻는 내용은 위키에 적어 둡니다.
- 대기시간은 봇 실행 중에만 유지하며 서버를 재시작하면 초기화됩니다. 질문마다 독립적으로 답하므로 앞선 채팅 내용을 기억하지 않습니다.

### 디스코드

`config/jbro-policy-discord.json`에는 봇과 웹훅을 적습니다. 둘 중 하나만 써도 됩니다.

```json
{
  "webhookUrl": "",
  "botToken": "봇 토큰",
  "inquiryChannelId": "문의를 받을 채널 ID",
  "statusChannelId": "서버 상태를 보여 줄 채널 ID",
  "newsChannelId": "서버 소식을 올릴 채널 ID",
  "adminChannelId": "관리자 명령을 받을 채널 ID",
  "verifiedRoleId": "마크 인증을 마친 사람에게 줄 역할 ID",
  "syncNickname": true,
  "commandChannelId": "플레이어용 봇 명령을 받을 채널 ID",
  "inviteUrl": "https://discord.gg/초대코드",
  "rankRoleIds": {
    "POKE_BALL": "몬스터볼 역할 ID", "GREAT_BALL": "수퍼볼 역할 ID", "ULTRA_BALL": "하이퍼볼 역할 ID",
    "MASTER_BALL": "마스터볼 역할 ID", "CHAMPION": "챔피언 역할 ID"
  },
  "adminAccess": {
    "운영자 디스코드 사용자 ID": ["*"],
    "스태프 역할 ID": ["announce", "players"]
  }
}
```

- **봇(`botToken`):** 서버가 켜져 있는 동안 디스코드에 온라인으로 떠 있고 슬래시 명령에 답합니다. 연결이 끊기면 5초부터 최대 5분까지 간격을 늘려 가며 다시 접속하고, 디스코드가 토큰을 거부하면 멈춥니다. 서버를 끄면 함께 나갑니다.
- **문의 채널(`inquiryChannelId`):** 봇이 문의를 이 채널에 올립니다. 봇이 있고 채널이 정해져 있으면 웹훅 대신 봇이 올립니다. 봇은 문의마다 **비공개 스레드**(`문의 <ID> · 닉네임`)를 열어 카드를 올리고, 문의한 플레이어가 디스코드 계정을 연결해 두었으면 그 계정을 스레드에 넣습니다. 그래서 플레이어는 자기 문의만 보고, 운영진(스레드 관리 권한)은 전부 봅니다. 문의 검토의 답장도 그 스레드에 달립니다. 봇에게 비공개 스레드 만들기 권한이 없으면 예전처럼 채널에 바로 올립니다.
- **명령 채널(`commandChannelId`):** 정해 두면 `/접속자`, `/전적`, `/랭킹`, `/위키`, `/도감`은 그 채널에서만 답하고, 다른 채널에서 쓰면 본인에게만 보이는 안내로 그 채널을 알려 줍니다. `/피츄`는 일반 채팅방에서도 답합니다. `/verify`(인증 채널)와 관리자 명령(관리자 채널)은 각자의 채널을 따릅니다. 비워 두면 어디서나 답합니다. 디스코드 채널 권한에서 다른 채널의 "애플리케이션 명령 사용"을 꺼 두면 명령 목록부터 뜨지 않습니다.
- **마크 인증(`verifiedRoleId`, `syncNickname`):** 역할 ID를 적으면 켜집니다. 마크에서 `/디코인증`(`/discordverify`)을 입력하면 10분짜리 6자리 코드가 나오고(누르면 명령이 복사됨), 디스코드에서 `/verify 코드`를 입력하면 두 계정이 연결됩니다. 봇이 그 사람에게 인증 역할을 주고, `syncNickname`이 켜져 있으면 디스코드 서버 별명을 마크 닉네임으로 바꿉니다(서버 주인의 별명은 디스코드가 막아서 바뀌지 않습니다). `/verify` 답은 본인에게만 보입니다. 한 마크 계정과 한 디스코드 계정이 짝이 되고, 어느 쪽이든 다시 인증하면 예전 연결을 대신합니다. 연결은 월드의 `jbro_policy_discord_links`에 저장됩니다. 봇 역할이 인증 역할보다 위에 있어야 하고, 역할 관리·별명 관리 권한이 필요합니다. `inviteUrl`에 디스코드 초대 링크(`https://discord.gg/...` 또는 `https://discord.com/invite/...`)를 적으면 `/디코인증` 코드 아래에 눌러서 여는 초대 링크도 함께 보여 줍니다. 형식이 틀리면 설정 파일 전체가 무효가 되어 디스코드 기능이 꺼집니다.
- **리그 등급 역할(`rankRoleIds`):** 인증과 함께 켜지고 League Challenge가 있어야 합니다. 연결된 사람의 디스코드 역할을 게임 속 리그 등급과 같게 맞춥니다. 등급 역할은 한 사람에게 하나만 붙고, 등급이 없으면 하나도 붙지 않습니다. 맞추는 때는 `/verify`로 연결할 때, 승급이나 운영자 수정으로 등급이 바뀔 때, 마크에 접속할 때, 봇이 디스코드에 (다시) 연결될 때(봇이 꺼져 있던 동안 바뀐 것까지)입니다. 마크 계정을 다른 디스코드 계정에 다시 연결하면 예전 계정의 등급 역할은 뗍니다. 봇 역할이 등급 역할들보다 위에 있어야 합니다.
- **상태 채널(`statusChannelId`):** 서버가 시작을 마치면 봇이 이 채널에 "🟢 서버가 열렸어요!", 정상 종료할 때는 "🔴 서버가 닫혔어요."를 새 채팅 메시지로 보냅니다. 접속자 변화나 주기적인 갱신은 메시지를 보내지 않습니다. 종료 메시지는 전송을 최대 30초 기다린 뒤 봇 연결을 끊습니다. 강제 종료·프로세스 충돌처럼 종료 이벤트가 실행되지 않으면 닫힘 메시지를 보낼 수 없습니다. 예전 `config/jbro-policy-discord-status.json`은 더 이상 읽거나 쓰지 않습니다. 문구는 `message.jbro_policy.discord_status.open`과 `.closed` 번역 키로 관리합니다.
- **소식 채널(`newsChannelId`):** 봇이 서버 소식을 올립니다. 상태 채널과 같은 채널이어도 됩니다.
  - 🏆 리그 챔피언·하드 챔피언 등극(처음 한 번)
  - 🔥 배틀타워 개인 최고 연승이 10의 배수가 될 때, 🏭 배틀팩토리 개인 최고층이 7의 배수(라운드 클리어)가 될 때
  - ✨ 전설 포획, 🌟 이로치 포획
  - 📢 `/공지`로 보낸 서버 공지
  - PvP 결과는 올리지 않습니다.
- **슬래시 명령:** 봇이 들어간 디스코드 서버에 바로 등록됩니다. `/접속자`는 지금 접속한 사람을, `/전적 분류 닉네임`은 리그챌린지·배틀팩토리·배틀타워·PvP 중 고른 분류의 허브 대시보드 카드(접속하지 않은 사람도)를, `/랭킹 종류`는 배틀타워·배틀팩토리·PvP 순위 상위 10명을, `/위키`는 본인에게만 보이는 답으로 위키 주소를(`/디코인증`으로 계정을 연동했으면 내 정보까지 보이는 개인 링크를), `/도감 포켓몬`은 그 포켓몬의 위키 도감 페이지를 알려 줍니다. `/접속자` 밖의 명령은 More Cobblemon Contents가 있을 때만 생깁니다. 문구는 각 모드의 `ko_kr.json`으로 한국어로 바꿔 보냅니다.
- **관리자 명령(`adminChannelId`, `adminAccess`):** 관리자 채널을 정하면 아래 운영 명령이 생깁니다. 한국어 입력기 문제를 피하려고 명령 이름과 옵션 이름은 영어로 두고, 설명과 답은 한국어입니다. 플레이어는 마인크래프트 아이디나 UUID로 지정합니다.
  - `/announce message`: 게임 안에 `[공지]`를 띄웁니다. 소식 채널에도 올라갑니다.
  - `/players [page]`: 접속한 적 있는 모든 플레이어의 아이디·닉네임·UUID를 20명씩 보여 줍니다. ●는 지금 접속 중입니다.
  - `/ban player [reason]`, `/unban player`: 밴과 밴 해제입니다. 접속하지 않은 플레이어도 됩니다. 접속 중이면 바로 내보냅니다.
  - `/bp player amount [reason]`: BP를 지급합니다. 접속하지 않은 플레이어도 바로 들어갑니다. More Cobblemon Contents가 있을 때만 생깁니다.
  - `/give player item [count]`: `/give`와 같은 형식으로 아이템을 줍니다. 접속하지 않았으면 다음 접속 때 받고, 인벤토리에 안 들어가는 만큼은 발밑에 떨어집니다.
  - `/spawn player pokemon`: `/spawnpokemonfor`와 같습니다. 접속 중인 플레이어에게만 됩니다.
  - `/console command`: 서버 콘솔 권한(4)으로 명령을 실행하고 출력을 돌려줍니다.
  - **권한:** 세 겹으로 확인합니다. ① 디스코드에서는 관리자 명령이 서버 관리자에게만 보입니다. 다른 역할에 보이게 하려면 서버 설정 → 연동 → 봇 → 명령어 권한에서 엽니다. ② 관리자 채널이 아닌 곳에서 쓰면 거절합니다. ③ `adminAccess`에 사용자 ID나 역할 ID별로 쓸 수 있는 명령 이름을 적고, `*`는 전부입니다. 여기에 없는 사람은 명령이 보여도 실행되지 않습니다. 실행과 거절은 모두 서버 로그에 남습니다.
- **웹훅(`webhookUrl`):** 봇 없이 문의만 올릴 때 씁니다. 채널 편집 → 연동 → 웹후크에서 만들고 "웹후크 URL 복사"한 값입니다.

문의는 카드로 올라오고, 사유에 `@everyone` 같은 호출이 있어도 아무도 호출하지 않습니다. 카드 아래에 문의 번호(8자리)가 붙습니다.

봇 만들기:
1. [Discord Developer Portal](https://discord.com/developers/applications)에서 New Application을 만들고, Bot 메뉴에서 Reset Token으로 토큰을 복사해 `botToken`에 넣습니다. 특별한 권한(Privileged Gateway Intents)은 켜지 않아도 됩니다.
2. OAuth2 → URL Generator에서 scope는 `bot`, 권한은 View Channels, Send Messages, Embed Links를 골라 나온 주소로 봇을 서버에 초대합니다.
3. 디스코드 설정 → 고급에서 개발자 모드를 켜고, 문의 채널을 우클릭해 "채널 ID 복사"한 값을 `inquiryChannelId`에 넣습니다.

### 자동 검토

문의 카드가 올라가면 Antigravity CLI(`agy`)가 문의 내용과 서버 자료를 대조합니다. 질문과 건의를 구분하며, **자료로 답을 확인한 서버 사용법 질문만 답변으로 자동 종결**합니다. 근거가 없거나 조치할 일이 남으면 관리자에게 전달합니다.

- 문의 전후 로그: 기본 30분 전~5분 후이며, 검토 당시 존재하는 로그만 읽습니다. 미래 로그를 기다려 수집하는 기능은 없습니다. IP는 가립니다.
- 관련 위키와 현재 로드된 jbro-policy 정책, 아이템 레지스트리, 디스크의 BP 상점 항목, 활성 데이터 리소스의 레시피·스폰·전리품·구조물을 검색합니다. 디스크 설정과 실행 상태는 구분하며, 검색량·문서 크기 제한 때문에 검색 결과 없음은 부재를 뜻하지 않습니다.
- 접속 중인 문의자 본인의 파티·PC(박스 번호 포함)·인벤토리·엔더 상자, 알려진 아이템화 포맷의 종·UUID를 조회합니다. 현재 차원 96블록 안에서 로드된 가까운 야생 개체 최대 32마리도 제공합니다. PC는 관련 종을 우선해 최대 80마리이며 잘림 여부를 표시합니다. 일반 상자·목장·다른 플레이어 소유 자료·백업·오프라인 저장소는 조회하지 않습니다.
- MCC가 있으면 현재 BP·최근 지급 내역·승패·전설 해금 자료도 제공합니다. 현재 자료는 문의 발생 당시 상태를 증명하지 않습니다.
- 답변은 게임 내 운영자 귓말과 문의 스레드에 보내고, 관리자 카드에는 근거·미확인 범위·권장 조치를 남깁니다. 신고·건의·오류·복구·보상은 관리자 확인 대상입니다. 포획 등급과 내비 표시 조건을 같은 것으로 추정하지 않으며, 원본 없는 새 포켓몬 소환을 복구라고 제안하지 않습니다.

**보상·상점 복구:** `autoResolve`가 켜져 있고 MCC의 원거래 기록이 있으면, BP 미지급·상점 미전달 문의를 서버 코드로 검증합니다. AI가 제안한 금액·아이템·명령은 실행하지 않습니다. 문의 본문에 원거래 UUID가 있으면 그 건만, 없으면 문의 전후 로그 구간에 해당하는 본인·동일 종류의 원거래가 정확히 한 건일 때만 처리합니다. 여러 건이면 거래 번호를 요청하고 관리자에게 넘깁니다.

- BP는 원래 서버 보상 코드가 기록한 수령자·금액·거래 번호를 그대로 사용합니다. 원래 거래 내역을 전체 BP 저장소에서 검사하므로 최근 내역 잘림에 의존하지 않습니다.
- 상점은 이미 차감된 동일 거래와 아직 전달을 시작하지 않은 상태가 모두 확인돼야 원래 상품·수량을 전달합니다. 복구 문의로 추가 결제하지 않으며, 현재 상점 가격이나 목록으로 보상을 다시 계산하지 않습니다.
- 같은 원거래의 재문의·재시작은 원거래별 영속 상태로 중복 실행을 막습니다. 전달 중 중단·일부 전달·저장 실패·원거래 충돌·이후 운영자 BP 조정·원거래 없는 과거 사건은 관리자 확인 대상입니다. 이미 전달 완료된 상품이 안 보인다는 문의도 자동 재지급하지 않습니다.
- 인벤토리 공간 부족·오프라인 등으로 전달을 시작하지 못한 구매는 대기로 남습니다. 공간 확보·접속 후 같은 거래 번호로 다시 문의할 수 있습니다. 포켓몬 복구와 다른 상점·외부 보상은 자동 지원하지 않습니다.

원거래 기록은 MCC 월드의 `data/mcc-compensation-v1/`에 보존됩니다. 문의를 닫아도 이 기록은 지우지 않습니다. 기록은 이 기능 설치 후 처리한 건부터 생성되며 과거 로그에서 보상 권리를 추정해 만들지 않습니다. 기존 `autoMaxBpPerInquiry`·`autoMaxBpPerDay` 키는 사용하지 않습니다. 임의 금액 지급 대신 검증된 원거래 한 건을 처리하는 구조입니다.

수동 아이템 보상(`/give` 등) 전에는 OP 권한 2로 `/bp recoveryhold <플레이어UUID> <원거래UUID>`를 실행해 보류 성공을 확인합니다. 이후 자동 복구는 해당 거래를 다시 실행하지 않습니다. 외부 모드·명령으로 한 수동 아이템 지급은 BP 내역에 남지 않으므로 이 절차 없이 자동으로 감지할 수 없습니다. BP 운영자 조정은 원거래 이후 내역을 확인해 자동 차단합니다.


추가 설명은 게임에서 `/문의추가 <문의번호> <내용>` 또는 `/inquiryfollowup`으로 보냅니다. 본인의 열린 문의에 100자 이내, 문의당 최대 3회까지 보낼 수 있으며, 원래 문의 시각과 추가 설명을 함께 다시 검토합니다. 디스코드 일반 답글은 자동 재검토 입력으로 수집하지 않습니다.

`config/jbro-policy-inquiry-review.json`의 `enabled`로 AI 검토를 켜고, `autoResolve`로 근거 있는 질문의 자동 종결과 원거래로 검증된 BP·상점 복구를 켭니다. 봇·문의 채널·관리자 채널 설정도 필요합니다. Mod Menu의 피츄 문의 설정 화면에서는 이 컴퓨터의 두 옵션만 바꿀 수 있으며 서버 재시작 후 반영됩니다. 원격 서버 설정은 변경하지 않습니다. 서버 JAR 변경은 재시작이 필요합니다.

AI는 전용 `jbro-inquiry-review` 프로필에서 전달된 자료만 읽으며 파일·셸·MCP 도구를 사용할 수 없습니다. 전용 프로필 내용이 예상과 다르면 검토를 중단합니다. 운영자가 ‘처리 완료’를 누르거나 질문이 자동 종결되면 해당 문의의 CLI 대화와 열린 문의 기록을 지웁니다. 검토에 실패하면 관리자에게 실패 카드를 남깁니다.

## 로그

`jbro.cobblemon.policy.api.PlayerLog.send(player, message, color)`로 한 플레이어에게 색을 지정한 메시지를 보냅니다. 색을 빼면 회색입니다. 문의 대기시간 안내("문의는 N분 후에 다시 보낼 수 있습니다.")는 붉은색으로 보냅니다.

## 운영자 귓말

`jbro.cobblemon.policy.api.OperatorWhisper.send(server, playerId, message, quote)`로 한 플레이어에게 운영자 메시지를 보냅니다. 전부 회색으로, 첫 줄은 `[운영자로부터 메세지가 왔어요]`, 다음 줄은 답하는 문장(`quote`, 예: 문의 내용)을 밑줄 친 인용으로, 그다음 줄이 실제 메시지입니다. `quote`는 빼도 됩니다. 접속하지 않은 플레이어에게는 저장해 두었다가 다음 접속 때 보냅니다.

## 안내

접속자가 있으면 기본 1분(60초)마다 `[안내] 내용`을 서버 전체에 보냅니다. `[안내]`는 노란색이고, 내용은 목록에서 무작위로 고르되 같은 안내가 연달아 나오지 않습니다.

- **목록과 간격:** 설정 파일의 `tips`와 `tipIntervalSeconds`에서 바꿉니다. 간격을 0으로 하면 안내가 꺼집니다. 설정은 서버를 재시작해야 반영됩니다.
- **API:** 다른 모드에서는 `jbro.cobblemon.policy.api.Tips.add(message)`로 목록에 안내를 더하고, `Tips.broadcast(server, message)`로 즉시 보냅니다.

## 내장 데이터팩

아래 팩은 기본으로 켜지며, 월드마다 `/datapack disable`로 끌 수 있습니다.

- **`jbro_policy:legendary_spawns`:** 전설·환상·전설급 패러독스 103종이 전용 `legendary` 버킷으로 자연 스폰됩니다. Cobblemon은 버킷 가중치를 데이터팩이 아니라 자기 JAR에서 읽기 때문에, `LegendSpawnBucket`이 설정을 읽을 때마다 월드 버킷에 `legendary`(0.002, 전체 약 100 중)를 넣습니다. 그래서 전설 후보가 있는 자리면 바이옴과 상관없이 스폰 시도 약 5만 번에 1번 전설이 나옵니다. 내보낸 설정(`exportSpawnConfig`)에 `legendary` 값이 있으면 그 값을 씁니다. 코라이돈·미라이돈과 전설 패러독스 6종은 `cobblemon-dimensions`의 고대·미래 차원에만 나옵니다. 울트라비스트와 전설이 아닌 패러독스는 빠져 있고(나오면 `RareSpawnNotice`가 서버에 알림), Myths & Legends가 설치되어 있으면 꺼집니다. 예전 서버의 Cobblemon 1.7.3용 스폰표를 1.8 형식(`spawnablePositionType`)으로 옮겼습니다.
- **`jbro_policy:end_spawns`:** 엔드(`#cobblemon:is_end`)에 Cobblemon 기본 엔드 스폰 말고도 25종을 더합니다. common은 삐삐·루나톤·솔록·동미러·네이티·몽나·해골몽·어둠대신·깜까미, uncommon은 치렁·다크펫·동탁군·네이티오·미라몽·몽얌나·픽시, rare는 음뱃·음번·폴리곤, ultra-rare는 모노두·드라꼰 계열입니다. 레벨은 각 종의 Cobblemon 원본 값을 따릅니다. 원래 엔드는 common이 안농 무리뿐이고 ultra-rare 후보가 전설뿐이었습니다.
- **`jbro_policy:no_stat_candy_l_xl`:** 경험사탕 제작과 분할을 허용합니다. 모닥불 냄비에서 스컬크 1개와 벌집 조각 1개로 경험사탕 XS 6개를 만듭니다. Create가 설치된 경우 경험치 조각과 벌집 조각을 쓰는 XS 레시피도 6개를 만듭니다. 경험사탕 S·M·L·XL 합성과 조합대 분할은 Cobblemon 기본 레시피를 사용합니다. 개체값 사탕 6종(체력·공격·방어·특수공격·특수방어·스피드)은 경험사탕 L·XL을 재료로 쓰는 냄비 조합법 12개를 모두 차단합니다. 상점 구매 등 다른 획득 경로와 이미 보유한 사탕의 사용은 유지합니다. 기존 월드의 팩 활성화 설정을 유지하기 위해 팩 ID는 보존했습니다.
  - 실행 중인 서버에 JAR 교체 없이 적용하려면 이 팩의 `pack.mcmeta`와 `data/`를 월드 데이터팩 `world/datapacks/jbro-policy-xs-candy-six.zip`으로 배치하고 `/reload`로 인식시킵니다. 자동 활성화되지 않으면 `/datapack enable "file/jbro-policy-xs-candy-six.zip" last`로 활성화합니다. 같은 레시피 ID를 가장 높은 우선순위에서 덮어쓰므로 서버 재시작 없이 반영됩니다. 활성화 후 내용만 갱신할 때는 `/reload`를 사용합니다.

## 설정

`config/jbro-policy.json`이 없으면 기본값으로 만듭니다. 파일 내용이 잘못되었다면 파일은 그대로 두고 그 실행에서만 기본값을 씁니다.

```json
{
  "plaza": { "x": 0.5, "y": 80.0, "z": 0.5, "yaw": 0.0, "pitch": 0.0 },
  "wildHiddenAbilityOneIn": 30,
  "wildIvDistribution": {
    "enabled": true,
    "ranges": [
      { "min": 0, "max": 9, "chance": 20.0 },
      { "min": 10, "max": 19, "chance": 45.0 },
      { "min": 20, "max": 29, "chance": 25.0 },
      { "min": 30, "max": 31, "chance": 10.0 }
    ]
  },
  "tipIntervalSeconds": 60,
  "tips": ["/광장 들어가기로 광장에 갈 수 있습니다. 돌아올 때는 /광장 나가기를 입력하세요.", "..."]
}
```

`wildHiddenAbilityOneIn`은 숨겨진 특성이 몇 마리 중 1마리꼴로 붙는지 정합니다. 30이면 1/30이고 0이면 끕니다. 예전 퍼센트 키 `wildHiddenAbilityRate`는 읽지 않으므로, 설정 파일에 남아 있으면 기본값 1/30으로 돌아갑니다.

## 예전 월드에서 옮길 때

예전 광장은 `world/dimensions/cobblemon_policy/plaza`에 있습니다. 새 월드의 `dimensions/jbro_policy/plaza`로 옮기면 서버 시작 때 바이옴 마이그레이션이 한 번 실행됩니다. 예전 모드의 복귀 위치와 첫 접속 키트 기록은 옮겨지지 않습니다.
