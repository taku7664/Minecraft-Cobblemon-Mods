# README 바이옴 우선순위 수정

2026-10-03. 대상: 빡대리와 공식 음악팩 제작자.
Updates: [1.3.5 선곡 기록](POKEMUSIC_IMPORT_2026-10-03.md)의 필드 판정 우선순위. 곡·랜덤 재생 방식은 바꾸지 않습니다.

제공된 `pokemusic/readme.txt`의 바이옴 항목은 나열 순서가 우선순위입니다. 여러 조건이 동시에 맞으면 위의 항목을 사용해야 합니다(MUST).

엔드 / 네더는 차원 매핑으로 처리합니다. 그 밖의 우선순위는 고대 도시(Deep Dark) → 동굴 → 강 → 바다 → 늪지 → 정글 → 설원 → 산 → 숲 → 평원 → 사막 → 악지입니다. 마이룸·광장과 시간별 차원 매핑은 이 일반 바이옴 판정보다 우선합니다. 미지정 바이옴의 기본곡은 기존 평원 곡입니다. README에 없는 기존 해변 매핑은 나열된 조건에 해당하지 않을 때 유지합니다.

## 구현과 편집

`resource-pack/catalog-layout.json`의 `mappings.field.ruleOrder`는 기존 매핑 키를 참조하는 순서 배열입니다. `biome:<정확한 ID 또는 #태그>`, `path:<경로 포함 문자열>`, `underground`를 섞어서 적을 수 있습니다(MAY). 예: `biome:minecraft:deep_dark`, `underground`, `path:river`. 먼저 일치한 항목을 선택합니다. 실제 곡은 기존 `biomes`, `biomePathContains`, `underground`에서 가져오므로 개인 곡 변경이 우선순위를 바꾸지 않습니다.

중복·미등록 키·잘못된 형식은 로드 오류입니다. `ruleOrder`가 없는 옛 팩은 기존 정확한 바이옴 → 지하 → 태그 → 경로 → 기본곡 방식을 유지합니다. 새 순서에 적지 않은 개인 추가 규칙도 이 기존 방식으로 후순위 판정합니다. 기본 순서 자체를 바꾸려면 팩 제작자가 `ruleOrder`를 편집합니다. Mod Menu는 곡 매핑을 변경하며 순서를 재배열하지 않습니다.

## 확인한 겹침 사례

- 지하 벚꽃숲·돌 해안·바다 → 동굴. Deep Dark와 지하가 겹치면 Deep Dark.
- 설원 이름 + 산/숲 태그 → 설원. 산/숲 태그가 겹치면 산.
- 강+바다, 숲+사막, 평원+사막, 사막+악지 이름 → 각각 강, 숲, 평원, 사막.
- Minecraft 1.21.1의 `is_mountain` 태그에는 벚꽃숲도 들어 있습니다. 실제 태그가 전달된 지상 벚꽃숲은 산 음악이 우선합니다. 벚꽃숲이라는 정확한 이름만으로 산 태그를 무시하지 않습니다.
- 개인 지하·벚꽃숲 곡을 바꿔도 같은 순서가 유지되는 회귀 테스트를 추가했습니다.

`inspect` 추가 점검: 파서 → 카탈로그 컴파일 → 필드 설정 → 판정 → Mod Menu 개인 매핑 경로를 확인했습니다. 옛 팩/설정 읽기와 기존 개인 값 보존을 검증했습니다. 기존 JAR은 새 `ruleOrder` 속성을 모르므로 새 ZIP과 JAR을 함께 배포해야 합니다(MUST). 롤백은 기존 JAR·ZIP·설정 백업을 함께 복구합니다.
