## [2026-10-12 03:50] 재료 칸을 제작대처럼 아무 칸에나 (1.3.3)

- **사용자 지적:** 재료를 원하는 칸에 넣을 수 없고 앞에서부터 채워졌다. 제작대처럼 아무 데나 넣게 해 달라.
- **원인:** 메뉴가 재료를 빈칸 없는 목록(`materialInputs`)으로 들고 있어 누른 칸과 상관없이 끝에 붙였다.
- **수정:** `PokeFusionMenu.materialSlots`(9칸 배열)가 자리를 기억한다. 누른 칸에 넣고, 찬 칸을 들고 있는 포켓몬으로 누르면 맞바꾼다(베이스 칸도 맞바꿈). Shift+클릭은 베이스 → 첫 빈 재료 칸. IV 계산·저장에는 빈칸을 뺀 목록을 쓴다. 플레이어 저장 형식(`PokeFusionPlayerStateCodec`)은 순서 없는 목록 그대로이며, 화면이 열려 있는 동안만 자리를 기억한다(저장 입력은 닫거나 재접속하면 돌려주므로 자리 정보가 필요 없다).
- **검증:** 단위 테스트 39개, 빌드 성공. 실게임 미확인.
- **배포:** `a09f2350` 빌드본(SHA-256 `029434CC…`)을 로컬 운영 서버·PPakemon에 설치, 해시 일치. 운영 저장소 로컬 커밋 `e3e2324`(푸시 안 함). 개발 클라이언트·서버는 실행 중이라 1.3.2 그대로다.

## [2026-10-11 22:50] PokemonToItem 아이템 툴팁에 크기·우두머리 표시 (1.3.1)

- **사용자 요청:** PokemonToItem으로 만든 아이템까지 포함해 툴팁에 크기와 우두머리 여부를 보여 달라.
- **확인한 사실(JAR 바이트코드):** Cobblemon 1.8.1 저장 코덱은 크기를 `ScaleModifier`(필수 필드), 우두머리를 `Alpha`(선택, 기본 false)로 저장한다. PokemonToItem 0.2.0과 pokefusion 모두 `saveToNBT`/`loadFromNBT`로 통째로 저장하므로 두 값은 아이템화·합성·복원에서 유지된다. 다만 PokemonToItem 설명(lore)에는 두 값이 없다.
- **구현:** `client/PokeFusionTooltip`이 Fabric `ItemTooltipCallback`으로 `PTI_NBT`가 있는 아이템에만 이름 아래 `우두머리`(빨강 굵게), `크기: x.xx배`(금색)를 넣는다. 아이템 데이터는 바꾸지 않는다. 표시 값은 저장된 `ScaleModifier`이며 우두머리 배율을 곱한 실제 렌더 크기가 아니다.
- **검증:** 단위 테스트 39개 통과(크기·우두머리 읽기 테스트 추가), 빌드 성공. 실게임 툴팁은 미확인.
- **배포:** `56b25481` 빌드본(SHA-256 `6BB4DD84…`)을 개발 서버·개발 클라이언트·로컬 운영 서버·PPakemon 프로필에 설치, 해시 일치. 게임·서버가 모두 꺼진 상태였고 서버는 켜지 않았다. 이로써 PPakemon도 1.3.x가 됐다. 운영 저장소 커밋은 로컬에만 있다(푸시 안 함). `deploy-product/`, VPS는 그대로.

## [2026-10-11 21:30] 전용 합성 화면으로 칸을 실제로 나눔 (1.3.0)

- **사용자 지적:** 1.2.6은 9x6 상자 격자 안에 색 유리판을 깔아 구역만 표시한 것이었다. 요청은 장비칸처럼 칸 자체를 나누는 것이었고, 새 JAR을 클라이언트에 까는 것도 당연한 전제였다. Claude가 "옛 클라이언트 호환"을 이유로 요청을 임의로 바꾼 것이 잘못이다. **사용자가 클라이언트 적용까지 지시한 UI 작업은 클라이언트 전용 화면으로 만든다.**
- **구조:** 전용 `MenuType` `pokefusion:fusion`(`PokeFusionMenu.TYPE`), 컨테이너 11칸(베이스 0, 재료 1~9, 결과 10) + 플레이어 인벤토리. 합성 칸은 `FusionSlot`(집기·놓기 불가)이고 클릭은 서버 메뉴가 처리한다. 클라이언트 쪽 메뉴(serverPlayer=null)는 합성 칸 클릭을 예측하지 않는다. 확정 버튼은 바닐라 `clickMenuButton(0)`, 버튼 상태·미지급 수·재료 수는 `ContainerData` 3칸으로 동기화한다.
- **화면:** `client/PokeFusionScreen`. 바닐라 `generic_54.png` 제목줄 띠를 이어 붙여 배경을 만들고, 칸 테두리도 같은 텍스처 조각, 화살표는 `furnace.png`라 리소스팩 테마를 따른다. 결과 칸은 26x26. 좌표는 `PokeFusionLayout`.
- **호환:** 1.3.0부터 클라이언트에 이 모드가 필수다(메뉴 레지스트리 동기화). README 설치 절도 바꿨다.
- **빌드:** 다른 세션이 남긴 Loom 캐시 손상으로 `:jbro-policy` 설정이 실패해서 `--configure-on-demand`로 pokefusion만 설정해 빌드했다. 단위 테스트 38개 통과.
- **배포:** `0c90a1a0` 빌드본(SHA-256 `DA37D958…C55E`)을 개발 서버·개발 클라이언트·로컬 운영 서버 `mods/`에 설치했고 해시가 같다. 서버는 꺼진 채로 교체했고 켜지 않았다. 운영 저장소 커밋 `e40a907`(1.2.6 커밋 `3835946`과 함께)은 로컬에만 있고 푸시하지 않았다.
- **미적용:** PPakemon 프로필(실행 중이라 교체 안 함), `deploy-product/client`, VPS. 1.3.0 운영 서버에 접속하려면 PPakemon에도 1.3.0이 필요하다.
- **미확인:** 실게임 화면. 리소스팩 테마에서 제목줄 띠(`v=4~12`)를 이어 붙인 배경이 자연스러운지는 화면으로 봐야 한다.

## [2026-10-11 20:20] 합성 화면 칸 구분 (1.2.6, 1.3.0으로 대체)
