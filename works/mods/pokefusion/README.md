# PokemonFusion (Fabric)

Cobblemon To Item으로 아이템화한 포켓몬을 사용해, 키우는 포켓몬의 개체값(IV)을 높이는 Cobblemon 애드온입니다. 베이스 1마리에 같은 진화 계보의 재료를 최대 9마리 넣고, 결과를 미리 확인한 뒤 합성합니다.

**합성을 확정하면 재료 포켓몬은 소모됩니다.** 베이스의 외형이나 종을 섞는 기능이 아니라, 각 능력치의 IV 중 가장 높은 값을 베이스에 적용하는 기능입니다. 베이스의 기존 IV는 낮아지지 않습니다.

## 사용 방법

1. `/poke2item <파티 번호>` 또는 사이드바로 베이스와 재료 포켓몬을 아이템으로 만듭니다.
2. `/pokefusion`으로 합성 화면을 엽니다.
3. 베이스를 먼저 넣고 재료를 1~9마리 넣습니다. 인벤토리에서 Shift+클릭하면 이 순서대로 들어갑니다.
4. 결과 미리보기에서 IV를 확인하고 **결과 아이템을 직접 클릭**합니다. 이때 합성이 확정되고 결과가 커서에 들립니다. 원하는 인벤토리 칸에 직접 놓습니다. 커서에 다른 아이템이 있으면 합성하지 않습니다. 결과의 Shift+클릭은 처리하지 않습니다.
5. 결과 아이템을 들고 우클릭하거나, 일반 인벤토리 화면에서 Shift+클릭하여 포켓몬으로 복원합니다.

합성 화면은 전용 화면입니다. 왼쪽부터 **베이스 칸 1개 → 재료 칸 3×3 → 화살표 → 결과 칸(큰 칸)** 순서로 놓이고, 각 칸 위에 `베이스`, `재료 n/9`, `결과` 이름이 붙습니다. 빈 칸은 역할별 색(하늘색·연두색·노란색)으로 옅게 칠해지고, 마우스를 올리면 무엇을 넣는 칸인지 알려 줍니다. 제작대처럼 원하는 칸에 바로 넣을 수 있고, 이미 찬 칸을 누르면 들고 있던 포켓몬과 맞바꿉니다. Shift+클릭으로 넣으면 베이스가 비어 있을 때는 베이스에, 아니면 비어 있는 첫 재료 칸에 들어갑니다. 별도 확정 버튼은 없으며 결과 아이템을 집는 순간 합성합니다. 칸 테두리와 배경은 바닐라 상자 텍스처를 쓰므로 리소스팩 테마를 따릅니다.

최종 IV를 높이는 데 기여하는 재료에는 화면 안에서 광택이 표시됩니다. 광택이 없는 재료도 합성을 확정하면 소모되므로, 필요 없는 재료는 확정 전에 빼 주세요.

포켓몬 아이템의 상세 툴팁은 Cobblemon To Item이 제공합니다. 잡은 볼 아이콘, 레벨·이름·성별, HP, 성격·특성, XS/S/M/L/XL 크기 단계, 우두머리 여부, 기술·PP, 개체값·노력치를 표시합니다. 합성은 별도의 툴팁을 덧붙이지 않습니다.

예를 들어 베이스의 HP IV가 12, 재료들의 HP IV가 25와 18이면 결과는 25입니다. 공격·방어·특수공격·특수방어·스피드도 각각 같은 방식으로 계산합니다.

## 합성 조건과 반환

- 같은 종 또는 진화로 연결된 계보만 사용할 수 있습니다. 분기 진화도 해당 진화 그래프에서 연결되어 있으면 허용됩니다.
- 같은 종의 서로 다른 폼은 허용하지 않습니다. 다른 종은 종과 폼을 함께 구분하는 진화 그래프에서 연결되어 있어야 합니다.
- 베이스의 원본 저장 데이터에서 여섯 능력치의 기본 IV만 변경합니다. UUID·우두머리·이로치·성별·종·폼·성격·특성·크기·레벨·경험치·기술/PP·노력치·하이퍼트레이닝·지닌 물건·다른 모드의 추가 데이터와 아이템 컴포넌트는 유지합니다. 1.4.3에서 우두머리를 누락하던 인스턴스 로더를 교체하고 전체 데이터를 다시 저장하는 경로를 제거했습니다.
- 동일 UUID를 베이스와 재료에 중복으로 넣거나 재료 여러 칸에 넣으면 합성을 거부합니다. 수량이 1이 아니거나 저장 데이터가 손상된 아이템도 소모하지 않습니다.
- 재료 포켓몬이 들고 있던 아이템은 합성 후 반환합니다. 베이스의 지닌 아이템은 베이스에 남습니다.
- 합성하지 않고 화면을 닫으면 입력 아이템을 반환합니다.
- 합성 결과 본체는 빈 커서로 집으므로 인벤토리가 가득 차도 받을 수 있습니다. 결과를 집은 뒤 창을 닫으면 커서 아이템은 Minecraft의 기존 반환 규칙을 따릅니다.
- 인벤토리가 가득 차면 반환 아이템의 남은 수량은 기존대로 플레이어 위치에 떨어집니다.
- 인벤토리 지급과 바닥 드롭이 모두 실패한 아이템은 미지급 결과로 보관하고, 재접속이나 결과 칸의 상자 클릭으로 다시 지급을 시도합니다.

입력과 미지급 결과는 Minecraft의 플레이어 저장 데이터에 포함됩니다. 재접속 시 저장된 입력을 반환하고 미지급 결과를 다시 지급합니다. 갑작스러운 종료 전에 아직 디스크에 저장되지 않은 변경까지 복구한다고 보장하지는 않습니다.

1.4.3부터 인벤토리·드롭 전달 중 예외가 발생하면 실제 반영 여부를 확정할 수 없으므로 `deliveryBlocked`를 보관 데이터에 남기고 해당 플레이어의 합성·자동 반환·재지급을 중단합니다. 일반적인 공간 부족으로 남은 수량을 확인할 수 있는 경우에는 기존대로 다음에 재시도합니다. 보류 상태에서는 관리자 확인 안내를 표시하며, 자동 해제·보류 해제 명령은 없습니다. 관리자는 백업을 보존하고 로그·실제 소지품·드롭을 대조해 이미 받은 아이템과 남은 아이템을 구분해야 합니다. 보류 자료가 있는 상태에서 이 표식을 무시하는 구버전으로 되돌리면 안 됩니다.

**남은 한계:** 미지급 목록의 다음 상태를 저장한 뒤 실제 인벤토리·드롭을 반영하기 전 프로세스가 강제 종료되는 틈과, 월드·플레이어 파일의 저장 시점 차이는 원자적으로 처리하지 못합니다. 이 경우 유실 또는 이전 저장 상태 복귀에 따른 중복 가능성을 배제할 수 없습니다. 일반 예외의 보류 처리나 정상 재접속 검사가 전원 차단 안전성을 보장하는 것은 아닙니다.

결과를 집어 합성이 확정되면 서버의 기존 로그에 `[pokemon-transfer]`로 플레이어 이름/UUID, 결과 포켓몬 UUID·종과 소모한 재료 포켓몬 UUID를 기록합니다. 결과 UUID는 베이스 UUID를 유지합니다. 로그는 문의 추적용이며 아이템 복구 데이터가 아닙니다.

## 설치

| 항목 | 현재 모드가 선언하는 지원 범위 |
| --- | --- |
| Minecraft Java | 1.21.1 |
| Java | 21 이상 |
| Fabric Loader | 0.19.5 이상 |
| Cobblemon | 1.8.1 이상, 1.9.0 미만 |
| Cobblemon To Item | 0.1.0 이상 |
| 필수 라이브러리 | Fabric API, Fabric Language Kotlin |
| 선택 모드 | Mod Menu — 클라이언트 설정 화면 |

싱글플레이에서는 클라이언트의 `mods` 폴더에 설치합니다. 멀티플레이에서는 **서버와 클라이언트 모두에 설치해야 합니다.** 1.3.0부터 합성 화면이 전용 화면이라, 이 모드가 없거나 1.3.0보다 낮은 클라이언트는 서버에 접속할 수 없습니다. 필수 의존 모드도 각 실행 환경에 맞게 설치해야 합니다.

1.4.0부터 Cobblemon To Item의 공개 데이터 형식만 사용합니다. 기존 PokemonToItem 아이템 마이그레이션은 별도 jbro-policy 작업이며 이번 버전에는 포함하지 않습니다. Forge·NeoForge 지원은 제공하지 않습니다.

## 설정

현재 설정은 **`/pokefusion` 명령어의 최소 권한 레벨** 한 가지입니다. 재료 최대 수(9), IV 계산 방식, 폼 조건, 인벤토리 초과분의 바닥 드롭은 설정 항목이 아닙니다.

첫 실행 시 실행 환경의 `config/pokefusion.json`을 다음 값으로 생성합니다.

```json
{
  "commandPermissionLevel": 0
}
```

| 값 | 의미 |
| --- | --- |
| `0` | 모든 플레이어 허용 — 기본값 |
| `1`~`4` | Minecraft 명령어 권한이 해당 값 이상인 사용자만 허용 |

Mod Menu → **PokemonFusion (Fabric)** → 설정에서 값을 바꾸고 저장할 수 있습니다. 저장은 같은 게임 프로세스의 로컬/통합 서버에 즉시 적용됩니다. 취소하면 저장하지 않습니다. 멀티플레이 서버의 권한은 클라이언트 설정으로 바꿀 수 없으며, 서버의 설정 파일을 편집한 뒤 서버를 재시작해야 합니다.

권한 값이 없거나, 숫자가 아니거나, 소수이거나, `0~4` 범위를 벗어나거나, 파일을 읽을 수 없으면 원본 파일을 보존하고 권한 `4`로 실행합니다. 설정 저장에 실패하면 화면에 오류를 표시하고 실행 중인 설정도 바꾸지 않습니다.
