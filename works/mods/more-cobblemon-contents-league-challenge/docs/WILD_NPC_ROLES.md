# 야생 NPC 역할 설계

야생에서 만나는 NPC를 트레이너만 두지 않고 교환·회복·퀴즈·보상 NPC까지 넓히는 설계다. 대화창도 Cobblemon 기본 대화창에서 광장 NPC와 같은 NPC 대화창(레터박스 포함)으로 옮긴다.
이 문서는 정한 규칙과 만들 순서를 정리한다. 수치 중 "초깃값"이라고 적은 것은 실제로 돌려 보고 조정한다.

## 정한 것

| 항목 | 결정 |
|---|---|
| 트레이너 대화 | NPC 대화창으로 옮기고 레터박스를 적용한다. 선택지로 묻는다(승부 → 응/아니) |
| `cobblemon-npc` 의존 | 리그 모드의 필수 의존으로 둔다 |
| 교환: 원하는 종 | 스폰을 일으킨 플레이어의 파티·PC 포켓몬 중에서 고른다. 등급 가중치 common 80, uncommon 15, rare 5 |
| 교환: 받는 종 | 원한 종보다 희귀도가 한 단계 높은 종 중 무작위. 타입 제한 없음. ultra-rare뿐이면 ultra-rare끼리 |
| 교환: 상대 | 스폰을 일으킨 플레이어만 교환할 수 있다 |
| 교환: 제외 종 | 전설, 환상, 패러독스, 울트라비스트는 원하지도 주지도 않는다 |
| 교환: 도구 | 내준 포켓몬의 도구는 돌려준다 |
| 교환: 이로치 | 이로치도 내줄 수 있다. 받는 포켓몬은 내준 것과 무관하게 1/100로 이로치 |
| 교환: PC | 선택지에서 PC를 열 수 있다 |
| 교환: 보낼 포켓몬 | 고르는 화면 없이 파티 1번 자리의 포켓몬을 보낸다 |
| 교환: 어버이 | 받는 포켓몬의 어버이는 그 NPC다 |
| 회복 | 대기 시간 없이 언제든 회복한다 |
| 퀴즈 | 맞히면 보상 풀에서 하나를 준다 |
| 보상 | 보상 풀(BP와 아이템)에서 하나를 준다 |
| 출현 빈도 | 트레이너보다 드물게. 아래 초깃값으로 시작한다 |

## 지금 구조

코드 기준이다(`src/main/kotlin/jbro/cobblemon/mcc/league/trainer/WildTrainers.kt`).

- 트레이너 124종이 Cobblemon NPC 클래스(`data/.../npcs/wild_*.json`)다. 월드 스폰 풀(`data/.../spawn_pool_world/wild_trainers.json`)에는 자리표시 항목 두 개(트레이너·역할 NPC)만 있고, 자리표시가 스폰되면 `WildNpcSpawns`가 그 자리에서 조건(바이옴·시간)이 맞는 종류를 가중치로 골라 그 클래스로 바꾼다. 종류별 조건과 가중치는 `data/.../league-challenge/wild_spawns/{trainers,roles}.json`에 있다.
- 스폰 제한은 `WildTrainers`가 공통으로 건다. `WILD_DIMENSIONS`에 있는 차원에서만, 64블록 안에 2명까지(`NEARBY_LIMIT`), 터미널 2청크 안 제외.
- 우클릭은 `UseEntityCallback`이 가로챈다. `offer()`가 거절 사유(배틀 중, 이미 짐, 5분 대기, 싸울 포켓몬 없음)를 보고, 사유가 있으면 채팅으로 `<이름> 대사`를 보낸다. 없으면 Cobblemon `DialogueManager`로 인사 한 줄과 [승부한다! / 다음에]를 띄운다.
- 배틀이 끝나면 BP를 주고 `DEFEATED_TAG`를 붙여 300틱 뒤에 지운다.
- 정의 파일은 `data/.../league-challenge/wild_trainers/*.json`(`npc_class`, `tier`, `bp`, `pokemon`)이다.

스폰, 이름, 수 제한, 떠나기는 이미 공통 틀이다. 말을 걸었을 때 하는 일만 배틀로 고정돼 있다.

## 트레이너 대화를 NPC 대화창으로

### 지금 문제

- 인사와 선택지는 Cobblemon 기본 대화창이고, 거절 대사는 채팅으로 나온다. 광장 NPC(`cobblemon-npc`)의 대화창과 모양, 넘김 소리, 카메라, 레터박스가 다르다.

### 방법

`cobblemon-npc`에 코드로 대화를 여는 서버 API를 만든다. 지금 대화 세션(`DialogueSessions`)은 설정 파일의 대화만 열고, 선택 결과는 명령으로만 처리한다. 여기에 아래를 더한다.

```kotlin
// 예시 모양. 이름과 시그니처는 구현 때 정한다.
NpcDialogues.open(
    player, speakerEntity,               // 카메라와 이름표 얼굴은 이 엔티티를 따른다
    pages = listOf("눈이 마주쳤다! 포켓몬 승부다!"),
    choices = listOf(
        NpcChoice("응, 승부하자!") { start(player, npc, definition) },
        NpcChoice("다음에") { },
    ),
)
```

- 화면은 지금 `NpcDialogueScreen`을 그대로 쓴다. 레터박스, 배틀캠 포커스, 넘김 소리가 같이 따라온다.
- 선택 처리는 서버가 한다. 클라이언트는 고른 번호만 보낸다(지금 세션 방식과 같다).
- 의존: 리그 모드가 `cobblemon-npc`를 필수 의존으로 둔다. 개발 서버와 클라이언트 모두 이미 깔려 있다. 없을 때 Cobblemon 대화창으로 돌아가는 분기는 만들지 않는다.
- 트레이너 스킨은 `rct_fisher_alec_036a` 같은 aspect다. 대화창 이름표 얼굴은 `NpcSkinRef`의 `rct:` 형식을 쓰므로 변환이 필요하다. 구현 때 확인한다.

### 트레이너 대화 흐름

1. 인사 한 줄(지금 4종 그대로) → [응, 승부하자! / 다음에]
2. 거절 사유가 있으면 채팅 대신 대화창에 그 대사를 띄운다(선택지 없음).
3. 배틀 시작·종료 연출 대사(`LeagueTrainerScenes`)는 배틀 화면 쪽이라 건드리지 않는다.

## 역할 공통 틀

정의 파일에 `role`을 더한다. 없으면 `battle`이다.

```json
{ "schema_version": 3, "npc_class": "...:wild_trader", "role": "trade" }
```

| role | 하는 일 | 끝나면 |
|---|---|---|
| `battle` | 승부, 이기면 BP | 지금처럼 떠남 |
| `trade` | 원하는 종을 받고 더 희귀한 포켓몬을 줌 | 스폰시킨 플레이어 전용. 교환 뒤 떠남 |
| `heal` | 파티 회복 | 남아 있음. 대기 시간 없음 |
| `quiz` | 문제 한 개, 맞히면 보상 | 플레이어마다 한 번 |
| `gift` | 보상 하나 | 플레이어마다 한 번 |

- 스폰 풀, 64블록 2명 제한, 터미널 근처 제외, 이름 붙이기는 역할과 관계없이 같이 쓴다. 2명 제한도 역할을 합쳐서 센다.
- "이 플레이어는 이 NPC와 볼일을 끝냈다"는 기록은 NPC 엔티티에 저장한다(재접속·청크 언로드에도 남게). 지금 `DEFEATED_TAG`와 같은 방식이다.
- 모든 대사는 `ko_kr.json`/`en_us.json` 키로 두고, 시스템 용어(터미널, 명령)를 대사에 쓰지 않는다.

## 교환 NPC

본가 게임처럼 NPC가 특정 종 하나를 원하고, 그 종을 주면 더 희귀한 포켓몬으로 바꿔 준다. 원하는 종은 스폰을 일으킨 플레이어가 실제로 가진 포켓몬에서 고르므로, 그 플레이어는 늘 교환할 수 있다.

### 희귀도 등급

종의 등급은 Cobblemon 월드 스폰 풀(`data/cobblemon/spawn_pool_world/*.json`)의 `bucket`으로 정한다. 한 종이 여러 등급으로 나오면 가장 흔한 등급을 쓴다. Cobblemon 1.8.1 기준으로 세면 아래와 같다.

| 등급 | 종 수 |
|---|---|
| common | 567 |
| uncommon | 134 |
| rare | 35 |
| ultra-rare | 105 |

- 스폰 풀에 없는 종은 등급이 없으므로 원하는 종으로도, 주는 종으로도 쓰지 않는다.
- ultra-rare에는 화석과 스타팅 계열이 많다. rare를 주면 이것들을 받을 수 있다.

### 제외하는 종

전설, 환상, 패러독스, 울트라비스트는 원하는 종과 주는 종 모두에서 뺀다. 판정은 Cobblemon 종 라벨로 한다. Cobblemon 1.8.1 종 데이터에서 확인한 라벨과 종 수는 `legendary` 71, `mythical` 23, `paradox` 20, `ultra_beast` 11이다. 넷 중 하나라도 붙은 종을 뺀다.

### 원하는 종 정하기

교환 NPC가 스폰될 때 한 번 정하고 NPC에 저장한다.

1. 스폰을 일으킨 플레이어의 파티와 PC에서, 제외 종이 아니고 등급이 있는 포켓몬을 모은다.
2. 그 안에 있는 등급만 놓고 가중치로 등급을 뽑는다. common 80, uncommon 15, rare 5이고, 없는 등급은 빼고 다시 비율을 맞춘다(rare가 없으면 80:15).
3. 뽑은 등급의 포켓몬 중 하나를 무작위로 골라 그 종을 원하는 종으로 정한다.
4. 대상이 ultra-rare뿐이면 ultra-rare 종을 원한다.
5. 대상이 하나도 없으면 교환 NPC를 스폰하지 않는다.

스폰을 일으킨 플레이어는 Cobblemon `SpawnEvent.getCause()`의 `SpawnCause.getEntity()`(`getEntityUUID()`)로 얻는다. 플레이어마다 도는 `PlayerSpawner`라서 그 플레이어가 들어 있을 것으로 보고, 실제 값은 구현 때 확인한다. 비어 있으면 리그 쪽 스폰 처리에서 플레이어를 넘긴다.

### 교환 상대

- 스폰을 일으킨 플레이어만 교환할 수 있다. 다른 플레이어가 말을 걸면 "이건 {그 플레이어}한테 부탁하려던 거야."처럼 거절한다.
- 그 플레이어가 교환하면 NPC는 떠난다.

### 흐름

고르는 화면은 쓰지 않는다. 파티 1번 자리에 둔 포켓몬을 보낸다.

1. "혹시 피카츄 있어? 나랑 바꿔 주면 더 귀한 포켓몬을 줄게!"
   → [교환할게 / PC 좀 볼게 / 다음에]
2. [교환할게]: 파티 1번을 본다.
   - 원하는 종이 아니면(또는 알이면) "피카츄를 엔트리 맨 앞에 데려와 줘!"라고 말하고 끝낸다.
   - 원하는 종이면 그 개체를 알아볼 수 있게 묻는다. "이 피카츄(Lv.20)를 보낼 거야?" 이로치면 "★", 별명이 있으면 별명, 도구를 들고 있으면 "도구는 돌려줄게"를 덧붙인다. → [보낼게 / 다시 생각해 볼게]
3. [보낼게]를 누른 순간 파티 1번이 아직 그 개체인지 다시 확인한다(UUID 비교). 바뀌었으면 처음부터 다시 묻는다.
4. 교환한다. "고마워! 대신 이 아이를 잘 부탁해." 받은 포켓몬은 비게 된 파티 1번 자리에 들어간다.
5. [PC 좀 볼게]: 대화를 닫고 PC를 연다. `/pc` 명령처럼 `PCLinkManager.addLink(플레이어, PC, 조건)` + `OpenPCPacket`을 쓰고, 조건은 "NPC에게서 8블록 안"이다(`ProximityPCLink`는 PC 블록이 있어야 해서 쓰지 않는다). 멀어지면 PC 조작이 막힌다. 그 종을 파티 1번에 옮긴 뒤 다시 말을 건다.
6. 배틀 중이면 거절한다.

### 받는 포켓몬

- **종:** 원한 종보다 등급이 한 단계 높은 종 중 무작위(common→uncommon, uncommon→rare, rare→ultra-rare). 스폰할 때 원하는 종과 함께 정해 두고, 제안 대사("바꿔 주면 내 ○○ 줄게!")와 교환 확인 대사에서 알려 준다. 확인 대사는 레벨에 맞춰 이전 진화 단계로 내려간 실제 종을 보여 준다. 원한 종이 ultra-rare면 ultra-rare 중 무작위. 타입은 따지지 않고, 제외 종은 뺀다. 진화 단계는 레벨에 맞춰 `WildSpawnSpecies.fit()`으로 맞춘다.
- **레벨:** 내준 포켓몬의 레벨. 단 플레이어 레벨캡을 넘지 않는다.
- **이로치:** 1/100. 내준 포켓몬이 이로치였는지와 무관하다.
- **어버이:** 그 NPC로 정한다. Cobblemon `Pokemon.setOriginalTrainer(String)`이 어버이 종류를 `NPC`로, 문자열을 어버이 이름으로 저장한다. 파티에 넣을 때 `PlayerPartyStore.add`는 어버이가 비어 있을 때만 플레이어로 채우므로, 미리 정한 NPC 어버이가 그대로 남는다(JAR 바이트코드로 확인).
- **어버이 이름:** NPC 이름은 번역 키(`npc.…wild_trainer.<직업>`) 뒤에 개인 이름을 붙인 형태다. 전용 서버는 모드 언어 파일을 읽지 않아 키가 그대로 찍힐 수 있으므로, 서버에서 `ko_kr.json`의 직업 이름으로 바꿔 "낚시꾼 Alec"처럼 넣는다. 머리 위 이름표와 같은 글자가 되게 한다.
- **개체값·특성·성격:** 야생 포켓몬 규칙을 따른다(개체값 구간 추첨, 숨겨진 특성 30%). 야생 규칙은 스폰 이벤트에서 걸리므로, jbro-policy가 공개한 `WildPokemonPolicy.applyWildRolls(pokemon)`을 리플렉션으로 부른다(확률값은 jbro-policy 설정 하나에만 둔다). jbro-policy가 없으면 Cobblemon 기본값 그대로다.

### 내준 포켓몬

- 들고 있던 도구는 플레이어 인벤토리로 돌려준다. 가득 차 있으면 발밑에 떨어뜨린다.
- 내준 포켓몬은 파티에서 사라진다.

## 회복 NPC

- "많이 지쳐 보이네. 쉬었다 갈래?" → [응, 부탁해 / 괜찮아]
- 파티 전체를 회복한다(Cobblemon 파티 `heal()`).
- 배틀 중이면 거절한다. 대기 시간은 두지 않는다. 볼일이 끝나도 떠나지 않는다.
- 참고: 개발 서버 Cobblemon 설정은 회복장치 충전 제한이 켜져 있다(`config/cobblemon/main.json`의 `infiniteHealerCharge: false`, `maxHealerCharge: 6`, `secondsToChargeHealingMachine: 900`). 회복 NPC는 이 설정과 무관하다.

## 퀴즈 NPC

- 문제 은행은 데이터 파일 하나(`league-challenge/wild_quiz.json`)에 둔다. 문제마다 질문, 보기 3개, 정답 번호, 출처 위키 문서를 적는다.
- 문제는 위키(`server-wiki/pages`) 내용에서 낸다. 레벨캡 순서, 관장 타입, BP 가격, 성격 보정 같은 것들이다.
- 흐름: "문제 하나 낼게!" → 질문 → 보기 3개 → 맞히면 보상, 틀리면 정답을 알려 준다. 플레이어마다 그 NPC에게 한 번만 풀 수 있다.
- 맞히면 보상 풀에서 하나를 뽑아 준다(보상 NPC와 같은 풀).
- 구현(`WildQuiz`): 문제는 NPC마다 하나다. 처음 누가 [좋아, 내 봐!]를 고를 때 무작위로 정해 NPC 태그(`mcc_quiz_question:`)에 남기고, 그 NPC는 모든 플레이어에게 같은 문제를 낸다. 보기는 낼 때마다 순서를 섞는다(파일의 `answer`는 섞기 전 번호). 답을 고른 순간 그 플레이어는 끝난 것으로 기록되고, 문제 화면을 그냥 닫으면 기록되지 않는다. 문제 글은 한국어만 둔다(서버가 한국어 서버라서). NPC는 "퀴즈 마니아"(슈퍼너드 스킨)이고 떠나지 않는다.

## 보상 NPC와 보상 풀

- "여행하다 주운 건데, 너 가질래?" → [고마워! / 괜찮아]
- 보상 풀에서 가중치로 하나를 뽑아 준다. 플레이어마다 그 NPC에게 한 번.
- 인벤토리가 가득 차 있으면 발밑에 떨어뜨린다.
- 구현(`WildNpcRoles.gift`): NPC는 "여행자"(캠퍼·피크니커 RCT 스킨 86장, 배틀 불가)이고 떠나지 않는다. 받은 뒤 다시 말을 걸면 인사만 한다. 레벨캡에 맞는 보상이 하나도 없어 못 줬을 때는 받은 것으로 치지 않는다.

### 보상 풀 파일

`league-challenge/wild_rewards.json`에 둔다. 항목마다 BP나 아이템, 가중치, 받을 수 있는 레벨캡 범위를 적는다.

```json
{
  "entries": [
    { "bp": [2, 5], "weight": 30 },
    { "item": "cobblemon:exp_candy_s", "count": [1, 2], "weight": 20, "max_cap": 46 },
    { "item": "cobblemon:exp_candy_m", "count": [1, 1], "weight": 15, "min_cap": 39 }
  ]
}
```

### 초깃값

아이템 ID는 Cobblemon 1.8.1 등록 이름으로 확인했다(`exp_candy_s`·`m`·`l`, `rare_candy`, `great_ball`, `ultra_ball`, `oran_berry`, `sitrus_berry`, 노력치 드링크는 `hp_up`·`protein`·`iron`·`calcium`·`zinc`·`carbos`). 한 항목이 여러 아이템 중 하나를 줄 때는 `items` 배열을 쓴다. 풀은 퀴즈가 먼저 쓰므로 5단계에서 만들었다(`WildRewards`).

| 보상 | 수량 | 가중치 | 레벨캡 |
|---|---|---|---|
| BP | 2~5 | 30 | 전체 |
| 경험사탕S | 1~2 | 20 | 46 이하 |
| 경험사탕M | 1 | 15 | 39 이상 |
| 경험사탕L | 1 | 8 | 64 이상 |
| 이상한사탕 | 1 | 5 | 전체 |
| 수퍼볼 | 3~5 | 15 | 34 이하 |
| 하이퍼볼 | 2~4 | 12 | 34 이상 |
| 오랭열매 | 2~3 | 10 | 전체 |
| 자뭉열매 | 1~2 | 8 | 28 이상 |
| 노력치 드링크(6종 중 무작위) | 1 | 6 | 전체 |

## 출현 빈도

월드 스폰 풀에는 그룹마다 자리표시 항목 하나만 있다(`uncommon`). 그래서 종류가 늘어도 그룹 전체의 출현 빈도는 이 가중치 하나로만 정해진다.

| 그룹 | 월드 가중치 | 그룹 안에서 고르는 기준 |
|---|---|---|
| 트레이너 | 50 (2026-10-09 사용자 결정) | 종류별 가중치. `rare`로 적힌 종류는 0.1배(월드 rare 0.5% / uncommon 5%) |
| 역할 NPC | 15 (2026-10-09 사용자 결정, 트레이너의 약 1/3) | 회복 60, 퀴즈 40, 보상 30, 교환 20 |

교환은 이로치 1/100과 희귀도 상승이 걸려 있어 가장 드물게 둔다. 교환꾼이 뽑혔는데 원할 종이 없으면 남은 역할 중에서 다시 고른다.

## 작업 순서

1. `cobblemon-npc`에 코드로 대화를 여는 API를 만들고, 트레이너 대화와 거절 대사를 옮긴다.
2. 정의 파일에 `role`을 더하고 공통 틀(볼일 끝난 플레이어 기록)을 만든다.
3. 회복 NPC.
4. 교환 NPC(희귀도 등급표, 원하는 종 정하기, 파티 1번 확인, PC 열기, 받는 포켓몬 생성).
5. 퀴즈 NPC와 문제 은행.
6. 보상 NPC와 보상 풀(퀴즈 보상도 이 풀을 쓰므로 5단계 전에 풀을 먼저 만들어도 된다).

각 단계는 따로 커밋하고, 빌드·배치는 지시가 있을 때 한다.

## 이 문서를 읽고 할 일

1단계(대화 API와 트레이너 대화 이전)부터 구현한다. 가중치와 보상 풀 수치는 실제로 돌려 본 뒤 조정한다.
