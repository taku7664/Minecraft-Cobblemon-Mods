# 팀 프리뷰를 보고 선봉 고르기

| 항목 | 값 |
|---|---|
| Status | `shared` |
| Effective | 2026-09-27 |
| Scope | AI 트레이너의 선봉 선택(본체 API `BattleBrain.chooseLeads`와 로컬 Brain 구현) |
| 주 독자 | 빡대리님과 MCC·Better AI 구현·검증 담당자 |

## 1. 배경

AI의 팀과 순서는 전투가 만들어지기 전에 무작위 카탈로그 선택으로 정해졌고, 목록의 첫 번째가 선봉이었다. Brain에게 선봉을 묻는 경로가 없어서 선봉이 플레이어의 팀에 전혀 반응하지 않았다. 타워는 대표 포켓몬이 자주 선봉으로 나왔고, AI 테스트는 항상 미카루게가 선봉이었다. 템플릿의 `leadPriority`는 Router 프롬프트에만 쓰인다.

## 2. 본체 계약

- `BattleBrain.chooseLeads(BattleLeadChoiceContext): List<UUID>?`는 기본 구현이 `null`(순서 유지)이다. 다른 Brain에는 영향이 없다.
- 런타임은 전투를 만들기 전에 한 번 호출한다. 플레이어 팀 프리뷰가 있을 때만 호출한다(타워·AI 테스트). 팩토리는 프리뷰가 없어 지금 순서를 유지한다.
- 주 Brain, 로컬 Brain 순으로 묻고, 처음으로 답한 Brain의 답을 쓴다.
- 답은 선봉 슬롯 수(싱글 1, 더블 2)만큼의 서로 다른 팀원이어야 한다(MUST). 아니면 원래 순서를 유지하고 경고를 남긴다. 예외도 같은 처리다.
- 선봉만 앞으로 옮기고 나머지 순서는 유지한다.
- 컨텍스트: 내 팀 상태(활성 슬롯 없음), 내 기술 목록, 정확한 내 빌드, 공개 수준으로 보강한 플레이어 프리뷰, 트레이너 프로필, 전투마다 고정된 시드.

## 3. 로컬 Brain 구현

구현은 `LocalLeadChoice`다. 플레이어가 6마리 중 누구를 데려오고 누구를 선봉으로 낼지 모르므로, 내 포켓몬마다 프리뷰 전체에 대한 대면 점수의 평균을 쓴다.

| 난이도 | 계산 |
|---|---|
| 입문 | 선택하지 않는다(순서 유지) |
| 표준 | 타입만: 내 공격기 중 가장 좋은 상성(자속 1.5배) 대 상대 타입의 공격 상성 |
| 상급·보스 | 표준 + 기술 위력, 공격·방어 능력치 비율, 확실한 속도 우위 ±0.3 |

- 대면 점수는 로그 척도다. 1.0은 피해가 한 배 더 유리하다는 뜻이다.
- 선봉은 점수에 대한 소프트맥스로 뽑는다(MUST). 온도는 표준 0.6, 상급 0.4, 보스 0.3이다. 같은 프리뷰에 항상 같은 선봉이 나오지 않지만, 대면 차이가 크면 거의 항상 가장 좋은 포켓몬이 나온다.
- 결정은 `[BetterAI Lead]` 로그로 선봉과 점수를 남긴다.

## 4. 남은 과제

- 팩토리에 플레이어 프리뷰 전달.
- 에이스를 뒤에 숨기는 성향(역할 가치와 연결).
- 6→3 선출.
