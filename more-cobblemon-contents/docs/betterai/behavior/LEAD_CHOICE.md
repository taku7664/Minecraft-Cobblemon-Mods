# 팀 프리뷰를 보고 선봉 고르기

| 항목 | 값 |
|---|---|
| Status | `shared` |
| Effective | 2026-09-27 |
| Scope | AI 트레이너의 선봉 선택(본체 API `BattleBrain.chooseLeads`와 로컬 Brain 구현) |
| 주 독자 | 빡대리님과 MCC·Better AI 구현·검증 담당자 |

## 1. 배경

AI의 팀과 순서는 전투가 만들어지기 전에 무작위 카탈로그 선택으로 정해졌고, 목록의 첫 번째가 선봉이었다. Brain에게 선봉을 묻는 경로가 없어서 선봉이 플레이어의 팀에 전혀 반응하지 않았다. 타워는 대표 포켓몬이 자주 선봉으로 나왔고, AI 테스트는 항상 미카루게가 선봉이었다. 템플릿의 `leadPriority`는 Router 프롬프트에만 쓰인다.

## 2. 본체 계약

- `BattleBrain.chooseLeads(BattleLeadChoiceContext): List<UUID>?`는 기본 구현이 `null`(순서 유지)이다. 다른 Brain에는 영향이 없다.
- 런타임은 전투를 만들기 전에 한 번 호출한다. 플레이어 팀 프리뷰가 있을 때만 호출한다(타워·AI 테스트). 팩토리는 프리뷰가 없어 지금 순서를 유지한다.
- 주 Brain, 로컬 Brain 순으로 묻고, 처음으로 답한 Brain의 답을 쓴다.
- 답은 선봉 슬롯 수(싱글 1, 더블 2)만큼의 서로 다른 팀원이어야 한다(MUST). 아니면 원래 순서를 유지하고 경고를 남긴다. 예외도 같은 처리다.
- 선봉만 앞으로 옮기고 나머지 순서는 유지한다.
- 컨텍스트: 내 팀 상태(활성 슬롯 없음), 내 기술 목록, 정확한 내 빌드, 공개 수준으로 보강한 플레이어 프리뷰, 트레이너 프로필, 전투마다 고정된 시드.

## 3. 로컬 Brain 구현

구현은 `LocalLeadChoice`다. 플레이어가 6마리 중 누구를 데려오고 누구를 선봉으로 낼지 모르므로, 내 포켓몬마다 프리뷰 전체에 대한 대면 점수의 평균을 쓴다.

| 난이도 | 계산 |
|---|---|
| 입문 | 선택하지 않는다(순서 유지) |
| 표준 | 타입만: 내 공격기 중 가장 좋은 상성(자속 1.5배) 대 상대 타입의 공격 상성 |
| 상급·보스 | 표준 + 기술 위력, 공격·방어 능력치 비율, 확실한 속도 우위 ±0.3 |

- 대면 점수는 로그 척도다. 1.0은 피해가 한 배 더 유리하다는 뜻이다.
- 선봉은 점수에 대한 소프트맥스로 뽑는다(MUST). 온도는 표준 0.6, 상급 0.4, 보스 0.3이다. 같은 프리뷰에 항상 같은 선봉이 나오지 않지만, 대면 차이가 크면 거의 항상 가장 좋은 포켓몬이 나온다.
- 결정은 `[BetterAI Lead]` 로그로 선봉과 점수를 남긴다.

## 4. 남은 과제

- 팩토리에 플레이어 프리뷰 전달.
- 에이스를 뒤에 숨기는 성향(역할 가치와 연결).
- 6→3 선출.

## 5. 2026-10-03 더블 공개 조합 평가 후속 갱신

**Updates:** 3장의 더블 평가 방법. 2장의 본체 계약과 3장의 소프트맥스 선택 계약은 계속 적용한다. 위 본문은 2026-09-27 당시 방식으로 보존한다. 현재 구현 근거는 `e57478fe6c31a31eaa3c2e656d2e2fe889bbab72`이며 소스·회귀 기준의 부분 개선이다.

더블은 서로 다른 자기 팀 UUID 두 개의 순서 있는 조합을 한 번에 채점한다. 각 공개 상대 선봉 쌍에서 두 자기 포켓몬이 서로 다른 상대를 맡는 두 배치 중 더 나은 점수를 사용하고, 공개 상대 쌍 전체의 평균을 조합 점수로 삼는다. 상대 선출 인원이 1이면 공개 한 마리 후보에 대한 두 자기 포켓몬의 평균을 사용한다. 개별 점수를 따로 뽑던 방식은 두 선봉이 같은 상대만 잘 상대해도 높은 점수를 받으므로 조합 커버리지 회귀를 만족하지 못했다.

자기 확정 빌드의 특성·도구를 임시 개시 국면의 입력으로 넣고 공용 입장 특성 투영을 적용한다. 자기 입장 순서는 공개 유효 속도 범위의 순서 확률로 가중한다. 날씨와 랭크 효과를 반영한 자기 기술의 상성·위력·속도 및 상대 공개 타입의 물리/특수 압력을 평가한다. 물리 공격은 방어, 특수 공격은 특수방어와 맞추며 받는 쪽의 전체 공개 타입을 함께 읽는다. 상대 타입 압력의 기준 위력 80은 평가용 가설이며 관측한 상대 기술이 아니다. 상대의 미공개 기술·특성·도구·빌드를 새로 채우지 않는다.

선봉 답은 슬롯 수만큼 서로 다른 팀원이어야 한다(MUST). 조합 선택은 기존 소프트맥스 규칙을 유지한다(MUST). 표준 0.6·상급 0.4·보스 0.3의 온도와 전투 시드도 유지한다. 공개 프리뷰가 없는 런타임의 본체 처리는 2장 계약을 기준으로 읽는다.

**검증과 잔여:** 조합·슬롯 순서·선출 인원 1·공개 날씨/방어 압력 등 관련 11개 회귀가 통과했고 소스 커밋·푸시·원격 일치를 확인했다. 이 결과는 실게임 선택 품질이나 G-409 전체 완료를 뜻하지 않는다. 사령탑·범위기 관련 새 9개 회귀는 아직 실행 결과 대기이며 속이기+랭크업·트릭룸 협동은 아직 구현하지 않았다. 전체 선봉 백로그는 [`../engine/LOCAL_GAPS.md`](../engine/LOCAL_GAPS.md)의 G-409에서 추적한다.

## 6. 2026-10-03 알려진 자기 개시 효과 후속 갱신

**Updates:** 5장의 자기 개시 국면 평가. 근거는 `253b479a3a60f342ede7a52ad5f3e20f6f296091`이다. 2장의 공개 프리뷰·서로 다른 UUID 계약과 3·5장의 소프트맥스 계약은 계속 적용한다(MUST). 앞선 5장의 실행 대기 기록은 당시 상태로 보존하고 아래 결과로 갱신한다.

자기 확정 특성이 사령탑인 싸리용과 어써러셔 조합은 공용 입장 투영 뒤 어써러셔의 공격·특수공격·방어·특수방어·스피드를 각각 2랭크 올리고, 지휘 중인 싸리용을 공격 주체에서 제외한다. 행동 가능한 한 마리의 대면 점수와 조합의 행동 수 감소 비용을 함께 사용한다. 사령탑의 조건·랭크·행동 취소는 엔진 동작을 직접 대조했으며 행동 수 감소 비용은 선봉 평가용 휴리스틱이다.

범위기는 공개 살아 있는 대상 수를 공용 규칙에 넣어 적용되는 경우 0.75배를 반영한다. 자기 기술의 `ALL_ADJACENT`/`ALL_ACTIVE` 대상에는 알려진 자기 팀의 내성·능력치·명중률을 사용해 아군 피해도 계산한다. 남은 HP 비율을 공격 점수의 로그 척도에 반영하되 비율의 최솟값은 0.125로 둔다. 이 비용은 선봉 휴리스틱이며 실제 개시 턴 전체를 재현하거나 게임 성능 개선을 실측한 값이 아니다. 상대의 미공개 기술·특성·도구는 이 후속에서도 입력에 채우지 않는다.

**검증과 잔여:** 신규 9개 중 사령탑·아군 범위 피해의 실제 실패 4개와 대조 5개를 확인한 뒤 기존 11개와 합친 선봉 총 20개가 통과했고 건너뜀은 0이다. 메인은 사령탑의 엔진 조건·+2·행동 취소와 helper를 독립 소스로 대조했으며 소스 커밋·푸시·원격 일치를 확인했다. 속이기+랭크업·트릭룸의 후속 잠재 평가 9개는 실제 실패 2개·대조 7개 통과로 수정 진행 중이다. G-409 전체와 실게임 선택 품질은 아직 완료하지 않았다.
