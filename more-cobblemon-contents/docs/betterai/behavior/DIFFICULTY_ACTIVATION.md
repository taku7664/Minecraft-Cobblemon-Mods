## 1. 활성 계약

- 본체의 공개 트레이너 프로필은 `INTRODUCTORY`, `STANDARD`, `ADVANCED`, `BOSS` 중 하나의 명시적 난도 프로필을 포함해야 한다(MUST).
- 기본 계산량은 입문 `가설 3/탐색 0/더블 슬롯 후보 3`, 일반 `6/0/5`, 상급 `10/1/8`, 보스 `16/2/12`여야 한다(MUST).
- 배틀타워 정규전은 연승 구간으로 난도를 정한다(`TowerBattleDifficultyPolicy`): 입문(1~5전) `INTRODUCTORY`, 실전(6~10전) `STANDARD`, 상급(11~20전) `ADVANCED`, 프로(21전~) `BOSS`. 정규전 카탈로그의 `aiSkill`은 난도에 쓰이지 않는다.
- 모든 배틀타워 승급 보스와 MAX 주기 챔피언은 현재 랭크와 카탈로그의 `aiSkill` 값에 관계없이 `BOSS`와 `champion` 성격을 사용해야 한다(MUST).
- 배틀팩토리 일반전은 카탈로그의 `aiSkill`을 0~1 입문, 2 일반, 3~4 상급, 5 보스로 해석해야 한다(MUST). 싱글 21·49전의 팩토리 헤드는 `BOSS`여야 한다(MUST).
- 난도는 합법 행동과 공개 정보의 범위를 바꾸어서는 안 된다(MUST NOT). 본체가 만든 동일한 합법 후보와 공정 정보 경계를 두 Brain이 사용해야 한다(MUST).

## 2. 현재 Brain 적용 경계

- Router Brain은 난도 ID·가설 수·탐색 깊이·더블 후보 수와 단계별 판단 지시를 받아야 한다(MUST).
- 입문 Router 응답의 예측은 폐기하고 계획은 `CLEAR`로 강제해야 한다(MUST). 상급과 보스는 공개 증거가 있는 계획·예측을 사용할 수 있다(MAY).
- 로컬 Brain 입문은 팀 전략과 활성 다중 턴 계획을 사용하지 않는다. 일반·상급·보스는 둘 다 사용한다(`LocalTacticalBrain`은 입문에서만 전략과 계획을 버린다).
- `lookaheadPlies` 값은 난도 계약과 Router 탐색 지시다. 현재 로컬 휴리스틱이 완전한 전투 시뮬레이터로 1·2수 탐색을 수행했다는 뜻으로 기록해서는 안 된다(MUST NOT).
- 이 활성화는 랭크 4 이상 상대 카탈로그 데이터가 존재한다고 주장하지 않는다(MUST NOT). 현재 데이터에 없는 랭크의 실제 트레이너·세트 추가는 별도 데이터 결정과 검증을 따라야 한다(MUST).

## 3. 채택하지 않은 대안

- `aiSkill` 정수만 계속 전달하는 방식은 랭크 난도와 보스 예외를 표현하지 못해 채택하지 않았다.
- 챔피언을 `aiSkill=5`로만 표현하는 방식은 낮은 정수로 작성된 보스 카탈로그가 일반 난도로 떨어질 수 있어 채택하지 않았다.
- 낮은 난도에 불법 행동이나 미공개 정보 차이를 주는 방식은 공정 정보·서버 권위 계약을 깨므로 채택하지 않았다.
- 로컬 휴리스틱을 실제 2수 시뮬레이터라고 표시하는 방식은 구현되지 않은 성능을 주장하므로 채택하지 않았다.

## 4. 검증 계약

- 모든 타워 랭크와 보스 종류의 매핑 테스트가 있어야 한다(MUST).
- 팩토리 일반전과 헤드전의 난도 테스트가 있어야 한다(MUST).
- 두 Brain이 같은 프로필을 받고 입문과 상급 이상의 계획 사용 차이를 보이는 테스트가 있어야 한다(MUST).
- 기존 `BattleTrainerProfile(int, personality)` JVM 생성자를 유지해야 한다(MUST).
