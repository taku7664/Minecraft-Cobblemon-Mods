# 트레이너 외형

## 1. 결론

관장, 사천왕, 챔피언은 월드에 상주하는 NPC가 아니다. 전투 중에만 MBC의 가상 트레이너 투영을 사용하고, 외형은 리소스팩의 64×64 플레이어 스킨으로 정의한다.

데이터는 트레이너나 팀에 텍스처를 직접 박지 않고 안정적인 `appearance_id`를 참조한다. 따라서 팀을 바꾸지 않고 외형만 교체할 수 있다.

## 2. 1차 지원 형식

`player_skin` 외형은 최소 다음 정보를 가진다.

- 리소스 위치 형태의 64×64 PNG 텍스처
- `default` 또는 `slim` 팔 모델
- 선택적 GUI 초상화
- 선택적 표시용 크레딧

예시:

```json
{
  "schema_version": 1,
  "id": "example:roark",
  "type": "player_skin",
  "texture": "example:textures/entity/trainers/roark.png",
  "model": "default",
  "portrait": "example:textures/gui/portraits/roark.png"
}
```

이 예시는 최종 스키마가 아니다. 서버는 검증된 리소스 ID와 모델만 전송하고 PNG 데이터, 로컬 파일 경로, 원격 URL은 전송하지 않는다.

## 3. MBC 현행과 필요한 차이

현재 MBC의 가상 트레이너는 도전자 `GameProfile`을 사용해 가짜 플레이어를 만들고 도전자의 방어구까지 복사한다. 리그 트레이너에는 맞지 않는다.

MBC 공개 외형 계약은 다음 표현을 구분해야 한다.

- 기존 호환용 `GameProfile` 외형
- League Challenge가 쓰는 `ResourceSkin` 외형
- 향후 확장 가능한 NPC 렌더러 외형

`ResourceSkin`에서는 도전자 방어구를 복사하지 않는다. 렌더링에 필요한 모델과 텍스처는 전용 페이로드로 전달한다.

## 4. 수명주기

- 서버에는 충돌·AI를 가진 실제 관장 엔티티를 소환하지 않는다.
- MBC의 보이지 않는 전투 앵커와 클라이언트 투영을 사용한다.
- 배틀 시작 때 만들고 종료·이탈·차원 변경 때 확실히 제거한다.
- 리소스팩 리로드 때 텍스처 캐시를 갱신한다.
- 외형 실패가 서버 전투 판정에 영향을 주면 안 된다.

## 5. 누락 및 오류 처리

- 초상화가 없으면 3D 머리 미리보기 또는 공용 실루엣을 사용한다.
- 스킨이 없거나 잘못됐으면 공용 기본 트레이너 스킨을 사용한다.
- 같은 누락 자산은 로그를 반복 폭주시키지 않고 한 번만 식별 가능하게 보고한다.
- 외형 로딩 실패만으로 진행도나 배틀을 취소하지 않는다.

## 6. 배포와 권리

커스텀 리그는 데이터팩과 대응 리소스팩을 함께 배포한다. 기본팩에는 직접 제작했거나 재배포 권리가 확인된 스킨만 포함하고 출처와 라이선스를 기록한다. 온라인 계정 이름에서 스킨을 가져오거나 외부 URL을 기본 메커니즘으로 쓰지 않는다.

## 7. 이후 확장

Cobblemon NPC 모델을 쓰는 `cobblemon_npc` 같은 표현 형식은 공개 외형 계약을 유지한 채 후속 버전에서 추가할 수 있다. 1차 출시에 이 렌더러를 필수로 넣지는 않는다.
