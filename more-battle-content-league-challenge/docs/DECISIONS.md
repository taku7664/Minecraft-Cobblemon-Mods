# League Challenge 결정 기록

- 상태: `shared planning baseline`
- 최종 갱신: 2026-09-25 — 실제 Minecraft UI 백엔드 스파이크 관찰 추가

이 문서는 대화 중 나온 제안을 모두 확정값처럼 취급하지 않도록 결정 상태를 분리한다.

## 채택

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 애드온 이름 | `Cobblemon: More Battle Content - League Challenge` | 기존 MBC 애드온 네이밍과 일치한다. |
| 접근 방식 | 별도 리그 터미널 블록 우클릭 → 전용 GUI | 건물·스폰 NPC 없이 MBC식 접근을 유지한다. |
| 체육관 건물 | 만들지 않음 | 터미널이 도전과 전투 이동을 담당한다. |
| 상시 관장 NPC | 스폰하지 않음 | 전투 때만 클라이언트 투영으로 표시한다. |
| 콘텐츠 교체 | 관장, 사천왕, 챔피언, 순서, 팀, 규칙, 보상, 외형을 데이터·리소스팩으로 교체 가능 | 세대와 서버별 리그를 코드 변경 없이 구성한다. |
| 뱃지 모드 | PokeBadges 필수 연동 | 전용 뱃지함과 공개 지급·조회 API가 있다. |
| 진행도 권위 | League Challenge 저장 데이터 | 외부 뱃지 지급이나 아이템 복제가 진행도를 우회하지 못하게 한다. |
| 볼 계급 | 0~2 몬스터볼, 3~4 수퍼볼, 5~7 하이퍼볼, 8 마스터볼, 챔피언 격파 후 챔피언 | 사용자가 지정한 계급 계약이다. |
| 계급 저장 | 별도로 저장하지 않고 뱃지·우승 진행도에서 계산 | 중복 상태 불일치를 막는다. |
| 사천왕 구조 | 사천왕 4명과 챔피언의 연속 도전 | 포켓몬리그를 일반 관장전과 구분한다. |
| 리그 팀 | 연전 시작 시 팀, 기술, 도구를 잠근다 | 한 팀의 범용성을 시험한다. |
| 전투 사이 회복 | 기본 규칙은 완전 회복 | 소모품보다 팀 구성과 전술을 평가한다. |
| 패배 | 리그 연전만 초기화하고 뱃지·마스터볼 계급은 유지 | 재도전 비용을 주되 이전 진행은 보존한다. |
| 엔드 콘텐츠 해금 | 챔피언 격파 후 MBC 배틀타워와 배틀팩토리 해금 | 리그 우승 이후의 후반 콘텐츠로 연결한다. |
| MBC 독립성 | 애드온이 없으면 기존 MBC 동작을 유지 | 선택형 애드온 계약을 지킨다. |
| MBC 잠금 | 애드온이 설치되어 작동할 때만 타워·팩토리 잠금 정책을 등록 | MBC가 League Challenge 클래스를 직접 참조하지 않는다. |
| GUI 공개 경계 | MBC의 타입 있는 `MbcUI` 화면 모델·컴포넌트·행동 계약만 사용하고 owo·`GuiGraphics`·MBC 내부 레이아웃 타입을 직접 참조하지 않음 | 실제 렌더러를 바꿔도 League 상태·행동 계약을 유지한다. |
| 화면·행동 소유권 | 화면 구조, 행동 ID, 확인 단계와 포커스 순서는 컴파일된 코드가 소유하며 리소스팩으로 교체하지 않음 | Visual Pack이 기능 의미를 바꾸는 반례를 차단한다. |
| GUI 우선순위 | 실제 Minecraft League 홈 스파이크에서 코드 드로잉과 owo 후보를 비교한 뒤 네 화면 수직 단면으로 확장 | 웹 시안이 Minecraft 제약보다 먼저 디자인을 고정하지 않게 한다. |
| GUI 착수 기반 | League 최소 Gradle 모듈과 개발 환경 전용 진입점을 MbcUI 스파이크보다 먼저 만든다. | 첫 사용처가 없는 상태에서는 fixture와 두 백엔드를 컴파일·실행할 수 없다. |
| MbcUI 초기 호환성 | 첫 계약은 명시적 experimental로 두고 최소 두 실제 화면의 반복 요구가 확인된 뒤 안정 API 승격을 검토한다. | 첫 화면의 우연한 구조를 장기 공개 계약으로 고정하지 않는다. |
| 스파이크 수명 | 두 백엔드를 같은 fixture로 비교한 뒤 미선택 구현을 제거한다. | 제품에 이중 렌더러 유지 비용을 남기지 않는다. |
| 기본 UI 자산 | MBC 공용 테마는 MBC JAR, League 테마와 자산은 League JAR에 내장 | 별도 리소스팩이 없어도 제품 기본 화면이 완전해야 한다. |
| 외부 리소스팩 | 허용된 cosmetic 테마 토큰과 텍스처만 덮어쓰는 선택형 Visual Pack 허용 | 화면·행동·필수 의미는 불변으로 유지한다. |
| 웹 미리보기 | Minecraft 화면 안정화 뒤 fixture·컴포넌트 manifest를 쓰는 비권위 보조 도구로만 평가 | AI·디자이너의 웹 시안 장점은 쓰되 픽셀 동등성을 약속하지 않는다. |

## 방향 채택

| 항목 | 현재 방향 | 남은 확인 |
| --- | --- | --- |
| 기본 리그 | 4세대 플라티나에서 인물·뱃지·순서를 가져오고 현대 Cobblemon 규칙으로 팀을 재구성 | 기본 팀, 기술, 기믹과 실제 종족 지원 확인 |
| 관장 전술 | 타입 정체성 + 관장마다 핵심 전술 하나 | 각 관장의 실제 데이터 확정 |
| BP | 새 화폐를 만들지 않고 MBC BP를 보상·상점 해금에 재사용 | 체육관별 지급량과 재도전 보상 확정 |
| 스킨 | 리소스팩 64×64 플레이어 스킨을 기본으로 하고 `default`/`slim` 모델 지원 | 기본 스킨 제작·라이선스 확정 |
| 초상화 | 선택 자산, 없으면 같은 스킨의 3D 모델로 대체 | GUI 시안에서 필요성 확인 |
| 레벨캡 | 외부 제공자를 어댑터로 연결하고 뱃지 승리 시 동기화 | 아래 미결정 항목 참고 |
| Minecraft UI 백엔드 | owo-lib `0.12.15.4+1.21`은 세 화면 크기, 한영 화면, 긴 문자열·잠긴 행동, fixture 3D 슬롯·scissor, 키보드 행동·내레이션 전달과 닫기 경로를 통과해 MbcUI 비공개 백엔드 선두 후보로 유지 | 사용자 정의 관장 스킨, 물리 입력·음성 출력과 성능 검증 후 최종 결정. 채택 시 MBC가 내레이션 전달 어댑터도 소유 |

## 기각 또는 사용하지 않는 방향

| 방향 | 상태 | 이유 |
| --- | --- | --- |
| 체육관 건물 제작 | 기각 | 터미널 중심 구조와 범위가 충돌한다. |
| 월드에 관장 NPC 상시 스폰 | 기각 | 위치·스폰·보호·청크 수명주기가 불필요해진다. |
| 뱃지 아이템 소지만으로 진행 인정 | 기각 | 드롭, 복제, 관리자 지급으로 진행을 우회할 수 있다. |
| 계급을 별도 영구 필드로 저장 | 기각 | 뱃지 수와 어긋나는 중복 상태가 된다. |
| 외부 URL을 기본 스킨 공급 방식으로 사용 | 기각 | 네트워크 실패, 캐시, 보안과 재현성 문제가 있다. |
| MBC가 League Challenge를 필수 의존 | 기각 | 애드온이 없어도 MBC가 독립 실행되어야 한다. |
| GUI에서만 타워·팩토리 잠금 | 기각 | 패킷·명령·직접 시작 경로로 우회할 수 있다. |
| owo API를 애드온 공개 계약으로 노출 | 기각 | 백엔드와 버전 변경이 모든 애드온의 호환성 문제가 된다. |
| owo 기본 위젯 외형을 그대로 사용 | 기각 | MBC 고유 시각 언어와 리소스팩 교체 목표를 만족하지 못한다. |
| 임의 HTML·CSS 또는 내장 브라우저로 게임 GUI 구현 | 기각 | Minecraft 입력·렌더링·배포·성능 계약과 맞지 않는다. |
| 기존 MBC 화면 일괄 재작성 | 기각 | 회귀 범위와 롤백 비용이 과도하다. |
| 기본 UI를 별도 리소스팩 설치에 의존 | 기각 | 팩 누락 때 제품 기본 화면이 깨진다. |
| 화면 XML을 `assets`에서 로드 | 기각 | 같은 경로를 덮어쓰는 Visual Pack이 화면 구조와 행동까지 바꿀 수 있다. |
| 웹·Minecraft 픽셀 동등 이중 렌더러 | 기각 | 글꼴·3D·툴팁·입력·클리핑 차이와 구현 드리프트가 크다. |
| 범용 XML 파서부터 구현 | 기각 | 실제 League 화면보다 UI 언어의 범위가 먼저 커진다. |

## 미결정

다음 항목은 구현 전에 사용자 결정 또는 실제 호환성 검증이 필요하다.

1. **레벨캡 제공 모드**
   - 결정권자: 사용자
   - 현재 후보: `Cobbled Level Control`
   - 이유: Cobblemon 1.8.x 호환을 명시하고 전투·포획·육성 제한을 제공한다.
   - 남은 일: Cobblemon 1.8.1에서 실제 기동·이벤트 동작·서버 재접속 보존·명령 호출을 검증한다.
   - 대안: `Cobblemon Level Cap`, `CobbleRegions`, 또는 League Challenge 자체 구현.
2. **정확한 레벨캡 수치**
   - 결정권자: 사용자
   - 각 뱃지의 보상 데이터로 정의하되 기본값은 아직 확정하지 않는다.
3. **리그팩 동시 활성화 방식**
   - 결정권자: 사용자
   - 하나의 활성 리그만 둘지, 여러 리그를 터미널에서 선택할지 결정해야 한다.
4. **체육관 예선전**
   - 결정권자: 사용자
   - 관장전만 둘지, 최초 도전에 한해 예선전 또는 시험 전투를 둘지 결정해야 한다.
5. **연전 중 종료 정책**
   - 결정권자: 사용자
   - 정상 서버 종료·연결 끊김·전투 중 고의 이탈을 어떻게 구분하고 재개할지 확정한다.
6. **리그 중 아이템 사용**
   - 결정권자: 사용자
   - 가방 아이템 허용 범위와 전투 사이 수동 회복 허용 여부를 확정한다.
7. **챔피언 칭호 표현**
   - 결정권자: 사용자
   - 터미널·채팅·이름표·PokeBadges 리본 중 어디까지 표시할지 정한다.
8. **레벨캡 위반 처리 의미**
   - 결정권자: 사용자와 선택한 레벨캡 모드의 실제 기능
   - 경험치 획득 제한, 진화 제한, 고레벨 포켓몬의 명령 불복종, 포획·교환 포켓몬 처리 중 어떤 방식을 쓸지 확정한다.
9. **진행 중 MBC 런의 잠금 전환**
   - 결정권자: 사용자
   - 애드온 설치·업데이트 시 이미 시작된 Tower·Factory 런을 끝까지 허용할지, 다음 전투부터 막을지 확정한다.
10. **League 테마 미술 방향**
   - 결정권자: 사용자
   - 실제 Minecraft League 홈의 두 백엔드 스파이크를 본 뒤 팔레트, 프레임 밀도와 계급 엠블럼 방향을 확정한다.
11. **owo 백엔드 최종 채택**
   - 결정권자: 구현 검증 결과와 사용자
   - 시각 비교 결과는 [UI_BACKEND_SPIKE_RESULT.md](UI_BACKEND_SPIKE_RESULT.md)에 기록했다.
   - `MbcUI` 공개 계약을 유지한 채 남은 접근성·3D·렌더링·성능 증거로 결정한다.
   - 현재 League의 직접 owo 참조는 개발 비교용 예외이며, LGUI-3 전에 MBC 내부로 이동하거나 제거한다.
