# 터미널, GUI 및 전투 흐름

## 1. 진입 방식

League Challenge는 별도 터미널 블록을 제공한다. 플레이어는 건물이나 월드에 소환된 NPC가 아니라 다음 흐름으로 도전한다.

```text
리그 터미널 설치 → 우클릭 → 서버가 터미널과 플레이어 상태 검증 → GUI 열기 → 도전 선택 → 배틀
```

체육관 건물 제작과 상주 관장 NPC는 범위 밖이다. 전투 중 트레이너 표현은 클라이언트 전용 가상 투영으로 처리한다.

## 2. 메인 화면 정보 구조

- 왼쪽: 현재 계급과 8개 뱃지 진행도
- 중앙: 체육관 또는 리그 도전 카드
- 오른쪽: 현재 레벨캡, 다음 해금 조건, 선택 도전 요약
- 아래: 상대 팀 규칙, 보상, 파티 확인, 도전 버튼

도전 카드는 최소한 다음 상태를 구분한다.

- `locked`: 아직 조건을 만족하지 못함
- `available`: 지금 도전 가능
- `cleared`: 최초 승리 완료
- `active`: 현재 연속 도전의 진행 지점

잠금 이유는 클라이언트가 추측하지 않는다. 서버가 번역 키와 안전한 인자를 내려주고 GUI가 그대로 표시한다.

## 3. 세부 화면

1. **리그 홈**: 계급, 뱃지, 다음 도전, 시설 해금 상태를 보여준다.
2. **체육관 상세**: 관장, 배틀 형식, 레벨캡, 보상과 입장 조건을 보여준다.
3. **파티 확인**: 현재 파티가 인원수·레벨·중복·금지 규칙을 만족하는지 보여준다.
4. **사천왕 로비**: 연속 도전 규칙을 다시 알리고 시작을 확정한다.
5. **연속 도전 진행**: 현재 승수, 다음 상대, 잠긴 팀 상태를 보여준다.
6. **결과**: 승패, 새 뱃지·계급·레벨캡·시설 해금을 한 번에 요약한다.

## 4. 서버 권위 흐름

GUI 열기와 실제 도전 시작은 별개의 서버 검증이다.

1. 우클릭한 블록이 실제 리그 터미널인지, 거리와 월드가 유효한지 확인한다.
2. 서버가 진행도와 데이터 정의 리비전을 담은 화면 상태를 만든다.
3. 플레이어가 도전 요청을 보낸다.
4. 서버가 터미널 접근, 진행 조건, 파티, 세션 중복, 현재 데이터 리비전을 다시 검증한다.
5. 성공하면 팀 스냅샷과 규칙을 잠그고 MBC 관리형 PvE 전투를 시작한다.
6. MBC가 반환한 확정 결과를 멱등적으로 한 번만 반영한다.

요청에는 재전송을 식별할 ID를 두고, 결과·뱃지·보상이 중복 지급되지 않게 한다. 오래된 GUI의 리비전으로 요청하면 새 상태를 내려주고 시작을 거부한다.

## 5. 일반 체육관 전투

- 시작 시점 파티를 검증하고 배틀용 스냅샷을 만든다.
- 승리하면 League Challenge 저장 데이터에 최초 승리를 기록한다.
- 그 다음 PokeBadges에 대응 뱃지를 반영하고 레벨캡을 갱신한다.
- 외부 반영에 실패하면 재시도 가능한 조정 기록을 남긴다.
- 패배하면 뱃지와 최초 승리 보상을 지급하지 않는다.

## 6. 사천왕 및 챔피언 연속 도전

- 사천왕 4명과 챔피언을 한 세션으로 묶는다.
- 시작 시 파티, 기술, 지닌 도구를 잠근다.
- 각 전투 사이에는 기본적으로 완전 회복한다.
- 패배하면 연속 도전만 종료하고 체육관 뱃지와 마스터볼 계급은 유지한다.
- 챔피언 승리 결과가 확정된 뒤에만 챔피언 칭호와 Battle Tower·Battle Factory 해금을 기록한다.

접속 종료·서버 재시작 때 이어할지 실패 처리할지는 아직 정하지 않았다. 구현 전 저장 지점과 악용 방지 규칙을 확정해야 한다.

## 7. 표현과 접근성

- MBC의 시각 언어를 공유할 수 있도록 공개된 GUI 토큰과 위젯을 사용한다.
- 색만으로 잠금·완료 상태를 구분하지 않고 아이콘과 텍스트를 함께 쓴다.
- 키보드 탐색, 내레이션 문구, 작은 화면에서의 스크롤을 제공한다.
- 모든 문구는 `ko_kr`과 `en_us` 번역 키를 기본 제공한다.
- 외형이나 초상화가 누락돼도 텍스트와 기본 실루엣으로 화면을 사용할 수 있어야 한다.

## 8. 블록 및 설정

터미널 블록은 블록 상태, 블록 엔티티, 아이템, 전리품 테이블, 조합법, 모델, 텍스처와 번역을 일관되게 제공한다. 운영자가 제작법, 재도전 정책, 연출을 조절할 필요가 있으므로 `modmenu` 진입점과 설정 화면을 제공한다. 진행 규칙 자체는 데이터팩 정의가 우선이며 클라이언트 설정으로 서버 규칙을 바꿀 수 없다.
