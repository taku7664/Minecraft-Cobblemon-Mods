# 구현 계획

## 1. 계획 원칙

League Challenge는 GUI 프레임워크의 위험을 먼저 제거한 뒤 서버 진행과 전투를 연결한다. 첫 산출물은 완성 모드가 아니라 같은 선언 문서로 웹과 Minecraft에 그린 League 수직 단면이다.

- MBC가 `MbcUI`를 소유하고 League Challenge가 첫 사용처가 된다(MUST).
- 기본 UI 자산은 MBC·League 각 JAR에 내장한다(MUST).
- 외부 리소스팩은 시각 자산만 선택적으로 덮어쓴다(MAY).
- 기존 MBC 화면을 한 번에 다시 쓰지 않는다(MUST NOT).
- 웹 미리보기는 게임 내 검증을 대신하지 않는다(MUST NOT).
- 서버 권위, 진행 저장과 전투 기능은 GUI 설계와 독립적으로 테스트한다(MUST).

## 2. GUI 착수 전 결정 게이트

GUI 단계는 다음 가정으로 시작할 수 있으며, 서버 기능의 미결정 항목 때문에 막지 않는다.

1. 첫 fixture는 신오 Pt 기반 8개 체육관과 사천왕·챔피언 구조를 사용한다.
2. 레벨캡 숫자와 실제 팀은 임시 표시값이며 제품 계약으로 고정하지 않는다.
3. 뱃지 이미지는 임시 원본 아이콘 또는 자리표시자를 사용하며 제3자 원본 게임 자산을 넣지 않는다.
4. owo-lib `0.12.15.4+1.21`은 Minecraft 백엔드 후보일 뿐 최종 채택이 아니다.
5. 첫 테마 미술 방향은 웹 수직 단면을 본 뒤 빡대리님이 확정한다.

다음 항목은 서버 연동 단계 전에 실제 환경에서 확정하거나 검증해야 한다.

1. Cobblemon 1.8.1에서 사용할 개인별 레벨캡 모드와 API
2. 뱃지별 정확한 레벨캡 숫자
3. 서버당 단일 활성 리그인지 다중 리그인지
4. 사천왕 연속 도전 중 접속 종료·서버 재시작 처리
5. 연속 도전 중 가방 아이템 사용 규칙
6. 진행 중 Tower·Factory 런에 잠금 정책을 적용하는 시점
7. PokeBadges 대상 버전, 모드 ID, 실제 뱃지 식별자
8. 레벨캡 초과 포켓몬의 경험치·진화·복종·전투 참가 처리 의미

## 3. GUI 우선 단계

### 1단계: MbcUI 계약과 백엔드 스파이크

- 현행 MBC 화면·캡처와 화면별 정보 계약을 기준선으로 보존
- 최소 화면 문서, 디자인 토큰, 컴포넌트, 상태 바인딩과 행동 ID 정의
- 파서·검증기의 실패 테스트 작성
- 같은 League 홈 fixture를 웹 렌더러와 owo 후보 렌더러로 구현
- 클리핑, 스크롤, 반응형 배치, 키보드·내레이션과 3D 호스트 슬롯 확인
- owo 채택·보완·기각 후속 결정 작성

완료 조건: 공개 계약이 owo 타입을 노출하지 않고, 백엔드 선택 근거가 실제 Minecraft 1.21.1 증거로 남는다.

### 2단계: MbcUI 핵심과 내장 리소스

- MBC 클라이언트 전용 API와 내부 렌더러 분리
- 행·열·격자·겹침·스크롤·반응형 레이아웃
- 패널, 버튼, 탭, 카드, 상태 배지, 알림과 행동 디스패처
- MBC 기본 테마와 안전한 누락 자산 폴백을 JAR에 내장
- 화면·테마 후보 스냅샷의 원자적 리로드
- 개발 전용 프레임워크 갤러리 화면

완료 조건: League 없이 MBC 단독으로 갤러리가 열리고 잘못된 테마를 넣어도 직전 정상 화면이 유지된다.

### 3단계: 웹 미리보기 도구

- Minecraft와 같은 제한된 화면 문서·토큰 파싱
- `320×240`, `426×240`, `640×360` 뷰포트
- 한·영, 긴 문자열, 누락 자산과 빈 상태 fixture
- 아이템·포켓몬·트레이너 모델 대체 슬롯
- 비교 가능한 정적 스냅샷 출력

완료 조건: 동일 문서와 fixture가 웹과 Minecraft에서 같은 정보 구조, 상태 이름과 행동 ID를 가진다.

### 4단계: League GUI 수직 단면

- League 테마와 원본 또는 명확한 임시 자산을 애드온 JAR에 내장
- 리그 홈 → 체육관 상세 → 파티 확인 → 결과 네 화면
- 계급, 뱃지, 도전 카드, 관장, 레벨캡, 파티 규칙과 해금 컴포넌트
- 선택형 `League Challenge Visual Pack` 예제로 같은 ID 덮어쓰기 확인
- 세 화면 폭과 한·영 스냅샷 검토

완료 조건: 별도 팩 없이 완전한 화면이 보이고 외부 팩 제거·누락·재로드 뒤 안전한 기본 테마로 돌아간다.

### 5단계: 실제 게임 시각·입력 승인

- 세 논리 화면 크기의 웹·Minecraft 동일 fixture 캡처 비교
- 기본 owo·바닐라 표면 노출 여부 확인
- 마우스, 키보드, ESC, 포커스, 툴팁, 내레이션과 스크롤 확인
- 3D 모델 슬롯 클리핑과 리소스 재로드 확인
- 프레임 시간과 대형 목록 입력 지연 측정

완료 조건: 빡대리님의 시각 승인과 백엔드 후속 결정이 있어야 실제 서버 연동으로 진행한다.

## 4. 제품 기능 단계

### 6단계: MBC 공개 서버 계약

- 접근 정책 API와 MBC 단독 기본 허용 테스트
- 모든 Tower·Factory 시작 경로의 서버 측 검사
- 허브 가용 상태와 잠금 사유 페이로드
- 관리형 PvE 배틀 API
- `ResourceSkin` 트레이너 투영
- 원자적 BP 공개 API
- 안정적인 콘텐츠 ID

### 7단계: 애드온 골격과 데이터 로더

- Gradle 모듈, 모드 ID와 패키지 계약 적용
- Cobblemon, MBC, PokeBadges 필수 의존성
- 선택 레벨캡 제공자의 선택 의존성
- 서버·클라이언트 초기화와 등록 해제 수명주기
- `modmenu` 진입점, 설정 화면, `ko_kr`·`en_us`
- 버전 있는 JSON 스키마와 원자적 데이터 스냅샷
- 기본 신오 Pt 기반 데이터도 같은 로더로 제공

### 8단계: 진행도와 외부 동기화

- 플레이어별 체육관 승리와 챔피언 상태 저장
- 계급 파생 계산
- PokeBadges 어댑터와 조정 큐
- 선택한 레벨캡 제공자 어댑터
- 로그인·승리·리로드 시 동기화
- 백업과 명시적 관리자 이관 명령

### 9단계: 터미널과 GUI 상태 연결

- 블록, 블록 엔티티, 아이템, 조합법, 전리품, 모델, 텍스처
- 거리·월드·세션·리비전 서버 검증
- fixture 상태를 서버 권위 화면 모델로 교체
- 오래된 상태와 조작 요청 거부
- 사천왕 로비·연속 진행 화면 추가

### 10단계: 체육관 배틀

- 파티 검증과 팀 스냅샷
- MBC 관리형 PvE 시작·정리
- 데이터 정의 상대 팀과 AI 선택
- 리소스 스킨 가상 트레이너
- 승패, 뱃지, 레벨캡, 보상 거래의 멱등 처리

### 11단계: 사천왕 및 챔피언

- 팀·기술·도구 잠금
- 사천왕 4명과 챔피언의 순차 세션
- 전투 사이 기본 완전 회복
- 패배·이탈·재시작 정책 적용
- 챔피언 칭호와 최초 승리 결과

### 12단계: 후반 시설 해금

- League Challenge 접근 정책 등록
- 챔피언 전 Tower·Factory 잠금
- 챔피언 승리 직후 상태 갱신
- GUI, 패킷, 직접 API 우회 테스트
- 애드온 제거 시 MBC 기본 동작 복구

### 13단계: 기본 콘텐츠와 릴리스

- 신오 Pt 기반 8관장, 사천왕, 챔피언 정의
- 현대 Cobblemon용 팀과 보상
- 허가된 기본 스킨·초상화와 크레딧
- 뱃지별 레벨캡과 난이도 플레이테스트
- 전용 서버·실제 클라이언트, 재접속·재시작과 악의적 요청 검증
- 데이터팩·리소스팩 교체와 실패 롤백 검증

| 테마·리소스 | JAR 기본값, 외부 덮어쓰기, 누락 자산, 잘못된 재로드, 직전 정상 폴백 |

각 단위는 정확한 파일만 스테이징하고 기존의 다른 작업을 포함하지 않는다.

## 7. 완료 기준

- 같은 선언 문서가 웹과 Minecraft에서 같은 정보 구조와 행동 의미를 표현한다.
- 기본 JAR만으로 화면이 완전하고 선택형 외부 리소스팩이 시각 자산만 바꾼다.
- 관장·사천왕·챔피언과 팀·규칙·보상·외형을 데이터·리소스팩으로 교체할 수 있다.
- 터미널 우클릭만으로 전체 도전 흐름을 사용할 수 있고 월드 NPC나 체육관 건물이 필요 없다.
- 계급과 챔피언 상태가 저장 원본에서 일관되게 파생된다.
- PokeBadges와 레벨캡이 재접속·리로드·실패 복구 뒤에도 수렴한다.
- 사천왕과 챔피언이 채택된 연속 도전 규칙대로 동작한다.
- 애드온 설치 시 챔피언 전 Tower·Factory의 모든 새 진입이 잠긴다.
- 애드온이 없을 때 MBC의 기존 기능과 화면이 회귀하지 않는다.
- 빌드뿐 아니라 전용 서버·클라이언트의 실제 UI, 렌더링, 입력, 전투와 우회 방지까지 확인한다.
