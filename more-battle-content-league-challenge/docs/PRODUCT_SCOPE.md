# 제품 범위와 모듈 경계

- 상태: `shared planning baseline`
- 대상: League Challenge와 MBC 구현자

## 1. 제품 목표

League Challenge의 목표는 Cobblemon 서버에 본가식 계단형 성장을 제공하는 것이다.
플레이어는 체육관을 이겨 뱃지를 얻고, 뱃지에 따라 레벨캡과 볼 계급을 올린다. 모든 뱃지를
얻은 뒤에는 사천왕과 챔피언의 연전을 통과해 챔피언이 되고, MBC 배틀타워와 배틀팩토리를
후반 콘텐츠로 해금한다.

이 진행은 PvP 점수나 시즌 랭크가 아니다. 한번 얻은 뱃지와 계급은 일반 패배로 내려가지 않는
영구 PvE 진행이다(MUST).

## 2. 핵심 사용자 흐름

1. 플레이어가 전용 리그 터미널을 우클릭한다.
2. GUI에서 현재 뱃지, 계급, 레벨캡과 다음 도전을 확인한다.
3. 팀 적합성을 검사하고 관장에게 도전한다.
4. MBC 관리 전투에서 가상 트레이너 투영과 전투 연출을 사용한다.
5. 승리 결과를 서버가 확정한 뒤 진행도를 기록한다.
6. PokeBadges에 해당 뱃지를 반영하고 레벨캡 제공자에 새 캡을 동기화한다.
7. 8개 뱃지를 얻으면 사천왕·챔피언 연전을 시작할 수 있다.
8. 챔피언 격파 후 MBC 배틀타워·배틀팩토리가 열린다.

## 3. 모듈 책임

### 3.1 League Challenge가 소유하는 것

- 리그 터미널 블록과 블록 엔티티
- 리그 GUI와 클라이언트 표시 상태
- 리그·체육관·상대·보상 데이터 로더
- 플레이어별 체육관 클리어와 리그 우승 진행도
- 뱃지 수에서 계산한 볼 계급
- 관장전과 사천왕 연전의 세션 상태
- PokeBadges 동기화
- 외부 레벨캡 제공자 동기화
- 챔피언 여부를 MBC 콘텐츠 접근 정책으로 제공하는 어댑터

### 3.2 MBC가 소유하는 것

- 관리 전투의 공통 수명주기와 정리
- 배틀타워, 배틀팩토리, PvP, BP와 기존 허브
- 전투 상대 실행, 공개 AI 선택 경계와 전투 결과 전달
- 홀로그램 트레이너와 아레나 연출의 범용 렌더링
- 콘텐츠 접근 정책 등록 API와 서버 권위 접근 검사
- 애드온이 사용할 수 있는 BP 지급·조회 API
- 애드온이 없어도 기존 기능을 허용하는 기본 정책

### 3.3 PokeBadges가 소유하는 것

- 뱃지함 GUI와 뱃지 표시
- 뱃지 획득 시각 등 PokeBadges 고유 메타데이터
- 뱃지 보유 상태의 표현용 사본

PokeBadges의 보유 목록은 League Challenge 진행의 원본이 아니다(MUST NOT).

### 3.4 레벨캡 제공자가 소유하는 것

- 경험치 증가, 포획, 전투 출전, 교환과 PC 이동에 대한 실제 제한
- 현재 플레이어 캡의 적용과 표시

League Challenge는 승급 결과를 전달하지만 외부 제공자의 내부 저장 파일을 직접 편집하지
않는다(MUST NOT). 공개 API나 검증된 서버 명령만 사용한다(MUST).

## 4. 명시적 비목표

- 체육관 건물이나 리그 건물을 자동 생성하지 않는다.
- 월드에 관장·사천왕·챔피언 NPC를 상시 배치하지 않는다.
- 새로운 PvP 랭크나 매치메이킹을 만들지 않는다.
- MBC 배틀타워·배틀팩토리 자체를 다시 구현하지 않는다.
- 새로운 범용 뱃지함을 만들지 않는다.
- 첫 구현에서 Cobblemon NPC용 Bedrock 모델 제작 도구까지 제공하지 않는다.
- 원작 팀과 당시 세대 규칙을 완전 복각하는 것을 목표로 하지 않는다.

## 5. 기본 리그 방향

기본 제공 콘텐츠는 4세대 플라티나에서 다음 정체성을 가져오는 방향을 사용한다.

- 신오 체육관 관장 8명과 뱃지 순서
- 사천왕 4명과 챔피언 난천
- 챔피언 이후 배틀프런티어로 이어지는 분위기

실제 팀은 현대 Cobblemon과 MBC Better AI에서 흥미로운 전투가 되도록 다시 구성할 수 있다.
원작 종족·타입 정체성은 SHOULD 보존하되, 원작의 당시 기술·특성·AI 한계까지 복제할 필요는
없다.

기본 리그도 하드코딩해서는 안 되며 데이터·리소스팩으로 표현해야 한다(MUST). 동일한 구조로
관동, 호연, 하나나 완전한 오리지널 리그를 교체할 수 있어야 한다.

## 6. 서버 권위와 신뢰 경계

- 승패, 진행도, 보상과 해금은 서버가 결정해야 한다(MUST).
- 클라이언트가 보낸 상대 ID, 승리 주장, 뱃지 수나 레벨캡 값을 신뢰해서는 안 된다(MUST NOT).
- GUI 상태는 표시용이며 서버 저장 상태에서 다시 만들 수 있어야 한다(MUST).
- 중복 전투 종료 이벤트가 와도 뱃지·BP·레벨캡 보상은 한 번만 커밋되어야 한다(MUST).
- 외부 연동 하나가 실패해도 전투 종료 정리가 멈춰서는 안 된다(MUST NOT).

## 7. 용어

- **도전**: 체육관, 사천왕 또는 챔피언을 상대로 한 하나의 정의된 전투 단계
- **체육관 클리어**: 해당 체육관의 승리 결과가 영구 진행도에 커밋된 상태
- **뱃지**: 체육관 클리어를 나타내는 논리 진행 항목이자 PokeBadges 표시 항목
- **계급**: 뱃지 수와 챔피언 우승 여부에서 계산하는 몬스터볼~챔피언 표시 단계
- **리그 연전**: 사천왕 4명과 챔피언을 고정 팀으로 연속 상대하는 세션
- **활성 리그**: 서버가 현재 진행 대상으로 선택한 하나의 리그 정의
- **외형**: 트레이너의 스킨, 모델 유형, 선택적 초상화와 향후 NPC 모델 정보
- **콘텐츠 잠금**: 클라이언트 표시뿐 아니라 서버 시작 요청까지 거부하는 접근 정책
