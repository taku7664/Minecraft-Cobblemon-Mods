# 진행도와 리그 콘텐츠

- 상태: `shared planning baseline`
- 대상: 게임 기획자, 서버 진행도 구현자, 데이터팩 제작자

## 1. 진행도 원본

플레이어 진행도는 최소한 다음 의미를 보존해야 한다.

- 클리어한 체육관 도전 ID 집합
- 현재 리그 연전 상태
- 챔피언 격파 여부와 최초 격파 시각
- 각 보상 트랜잭션의 중복 방지 ID
- 데이터 버전

계급과 현재 뱃지 수는 저장 필드로 권위 있게 관리하지 않고 위 진행도에서 계산한다(MUST).
캐시가 필요하다면 원본 진행도에서 언제든 재구성할 수 있어야 한다(MUST).

## 2. 볼 계급 계약

기본 8체육관 리그의 계급은 다음과 같다.

| 조건 | 계급 | 의미 |
| --- | --- | --- |
| 뱃지 0~2개 | 몬스터볼 | 리그 초반 도전자 |
| 뱃지 3~4개 | 수퍼볼 | 중급 도전자 |
| 뱃지 5~7개 | 하이퍼볼 | 상급 도전자 |
| 뱃지 8개, 챔피언 미격파 | 마스터볼 | 포켓몬리그 도전 자격 보유 |
| 챔피언 격파 | 챔피언 | 리그 우승자 |

- 일반 패배는 뱃지나 계급을 낮추지 않는다(MUST).
- 뱃지가 관리자 명령으로 명시적으로 회수되면 계급은 다음 계산부터 자동으로 내려갈 수 있다.
- 챔피언 우승 플래그는 일반적인 뱃지 수 계산과 별도이므로, 리그 초기화·시즌 기능을 나중에
  넣을 경우 무엇을 지우는지 명시해야 한다(MUST).

## 3. 체육관 진행

- 기본 리그는 8개 체육관을 가진다.
- 체육관 순서는 리그 데이터가 정의한다(MUST).
- 기본값은 선형 순서이며 이전 체육관을 클리어해야 다음 체육관을 열어야 한다.
- 데이터 형식은 향후 분기 선행 조건을 표현할 수 있어야 하지만, 첫 구현에서 복잡한 그래프
  편집기는 필요하지 않다(MAY).
- 모든 관장은 타입 또는 캐릭터 정체성과 함께 핵심 전술 하나를 가져야 한다(SHOULD).
- 관장전은 단순히 상대 레벨만 올린 반복 전투가 되어서는 안 된다(SHOULD NOT).

관장전의 권장 전술 축 예시는 상태이상, 날씨, 교체 압박, 필드·벽, 더블배틀 연계,
스피드 제어와 세대 기믹이다. 구체적인 배치는 기본 콘텐츠 제작 단계에서 확정한다.

## 4. 레벨캡 진행

- 각 체육관 도전은 승리 보상으로 새 레벨캡을 선언할 수 있어야 한다(MUST).
- 레벨캡은 계급 이름에 하드코딩하지 않고 도전 보상 데이터에서 계산해야 한다(MUST).
- 현재 캡은 클리어한 도전 중 적용 가능한 가장 높은 캡이어야 한다(SHOULD).
- 캡 값은 엄격히 증가해야 한다(SHOULD). 같은 값이나 하락 값이 필요하면 데이터 검증에서
  명시적 허용 이유를 요구해야 한다.
- 챔피언 격파 보상은 기본적으로 최종 캡 100을 해금하는 방향이다. 정확한 값은 아직 확정하지
  않았다.

레벨캡 연동 실패는 진행도 커밋을 되돌려 중복 전투를 강요하기보다 `동기화 필요` 상태로 남기고
접속·터미널 열기·관리자 재시도 때 복구해야 한다(SHOULD). 단, 실제 캡이 이전 값에 머무는 동안
GUI는 성공한 것처럼 새 캡이 적용되었다고 표시해서는 안 된다(MUST NOT).

필수 레벨캡 동기화가 해결되지 않은 플레이어는 다음 체육관이나 리그 전투를 시작할 수 없어야
한다(MUST). 이는 진행도는 올라갔지만 실제 제한은 이전 상태인 불일치를 이용하는 것을 막는다.

## 5. 뱃지 지급

체육관 승리 트랜잭션은 다음 순서를 기준으로 한다.

1. 서버가 해당 전투 ID와 승자를 검증한다.
2. 이미 처리한 완료 ID인지 확인한다.
3. League Challenge 진행도에 체육관 클리어를 원자적으로 기록한다.
4. PokeBadges에 대응하는 뱃지를 지급한다.
5. 레벨캡 제공자에 새 캡을 반영한다.
6. BP와 아이템 보상을 지급한다.
7. 결과 GUI와 알림을 동기화한다.

3번 이후의 외부 연동이 실패하면 완료 기록과 미처리 부작용을 함께 저장해 재시도해야 한다.
전투 승리 자체를 두 번 처리해서는 안 된다(MUST NOT).

PokeBadges에 같은 뱃지가 이미 있더라도 League Challenge의 클리어가 처음이라면 해당 승리를
정상 기록할 수 있다. 반대로 PokeBadges에만 뱃지가 있고 클리어 기록이 없다면 자동으로 진행을
올리지 않는다(MUST NOT).

## 6. 마스터볼과 포켓몬리그 입장

8개 체육관 클리어 시 마스터볼 계급과 리그 도전 자격을 얻는다.

- 리그 입장 시 플레이어는 6마리 팀을 확정해야 한다(MUST).
- 팀의 종, 폼, 기술, 특성, 지닌 도구, 개체·노력치와 적용 기믹 정보는 재현 가능한 스냅샷으로
  잠가야 한다(MUST).
- 연전 중 PC, 교환, 기술 변경이나 도구 교체로 잠긴 팀을 바꿀 수 없어야 한다(MUST).
- 실제 저장 포켓몬을 파괴적으로 복사·덮어쓰지 않는다(MUST NOT).

## 7. 사천왕·챔피언 연전

기본 연전은 다음 다섯 단계다.

1. 사천왕 1
2. 사천왕 2
3. 사천왕 3
4. 사천왕 4
5. 챔피언

- 순서와 상대는 리그 데이터로 교체 가능해야 한다(MUST).
- 기본 규칙은 전투 사이 완전 회복이다.
- 회복은 체력, 상태이상과 PP를 다음 전투의 시작 상태로 되돌리는 것을 의미한다.
- 팀 구성과 도구는 회복 과정에서 바뀌어서는 안 된다(MUST NOT).
- 한 단계 승리 후에는 다음 단계 인덱스를 서버에 저장해야 한다(MUST).
- 패배하면 현재 연전 세션과 잠긴 팀을 해제하되 체육관 뱃지와 마스터볼 계급은 유지한다(MUST).
- 리그 연전 진행 중 타워·팩토리가 열려서는 안 된다(MUST NOT).

정상 서버 종료, 네트워크 단절과 고의 이탈의 세부 재개 정책은 미결정이다. 구현 전
`DECISIONS.md`의 해당 질문을 닫아야 한다.

## 8. 챔피언 우승과 해금

챔피언 승리 결과가 커밋되면 다음 동작이 한 논리 트랜잭션으로 예약되어야 한다.

- 챔피언 우승 플래그 기록
- 계급을 챔피언으로 계산
- 최종 레벨캡 동기화
- 챔피언 칭호·리본 등 확정된 표현 지급
- MBC 배틀타워 접근 허용
- MBC 배틀팩토리 접근 허용
- 최종 BP·아이템 보상 지급

타워와 팩토리의 기존 전적은 League Challenge 진행도와 별도로 유지한다(MUST). 애드온 설치 전
이미 쌓인 전적을 삭제하거나 초기화해서는 안 된다(MUST NOT).

## 9. 챔피언 이후

첫 릴리스에 반드시 포함할 후반 콘텐츠는 타워·팩토리 해금이다. 다음은 확장 가능 항목이다.

- 레벨 100 관장 재대결
- 강화 사천왕·챔피언 재도전
- 최초 보상 없는 반복 파밍 또는 제한적 BP 보상
- 챔피언 칭호 선택과 표시
- 다른 리그팩 도전

재도전 보상은 최초 클리어 보상과 분리해야 하며 무한 아이템·BP 생성 경로가 되지 않도록
상한 또는 다른 보상표를 가져야 한다(MUST).
