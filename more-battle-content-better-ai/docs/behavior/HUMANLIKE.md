## 1. 목적과 적용 경계

- Better AI는 단일 턴 최고 점수 선택을 넘어, 공개 정보 안에서 계획을 유지하고 상대의 상황별 습관을 추론해야 한다(MUST).
- 사람다움은 임의의 오답이나 높은 모델 temperature가 아니라 `예측 사전 확정 → 서버 결과 채점 → 다음 판단에 반영`되는 검증 가능한 순환으로 구현해야 한다(MUST).
- 정확한 피해·속도·합법성·진입 위험 계산은 서버 측 결정론적 분석기가 담당해야 한다(MUST). 외부 모델에 게임 산술을 맡겨서는 안 된다(MUST NOT).
- 이 결정은 배틀타워와 배틀팩토리에 별도 콘텐츠 전용 capability를 추가하지 않는다(MUST NOT). 초기 capability는 계속 `SINGLE`, `DOUBLE`다(MUST).
- 보스 레이드의 공유 HP·단계·참가자 컨텍스트는 이 결정에 포함하지 않는다(MUST NOT).

## 2. 일반 Brain 프로필

- `BattleBrainOpenContext`는 콘텐츠 중립적인 트레이너 프로필을 제공해야 한다(MUST).
- 프로필은 `skillLevel` 0~5, 구조화된 `personality`, 선택적 `strategy`를 포함해야 한다(MUST).
- `skillLevel`은 합법 정보의 양을 바꾸지 않고 추론 정밀도, 후보 비교 범위와 불확실성 처리만 바꿔야 한다(MUST).
- `personality`는 공격성, 안정성, 교체 선호, 정보 가치, 계획 지속성과 위험 감수의 가중치를 구조화된 값으로 표현해야 한다(SHOULD).
- 자연어 `aiSummary`는 외부 모델의 보조 설명으로 사용할 수 있지만 로컬 Brain이 문자열 의미를 추측해서는 안 된다(MUST NOT).

## 3. 후보 분석

- 서버가 발급한 합법 후보에는 선택적인 `TacticalCandidateAnalysis`를 붙일 수 있어야 한다(MUST).
- 분석은 다음 공개 정보 기반 결과를 표현해야 한다(SHOULD).
  - 예상 피해 범위와 KO 가능성
  - 예상 선후공
  - 상대 대표 대응별 기대·최악 효용
  - 교체 진입 위험과 다음 턴 위치 가치
  - 승리 조건·핵심 역할 보존 가치
  - 분석에 남은 불확실성
  - `TAKE_KO_THREAT`, `SAFE_PIVOT` 같은 전술 근거 코드
- 전술 근거 코드는 행동의 합법성을 결정해서는 안 된다(MUST NOT). 특히 교체 근거가 비었다는 이유로 Cobblemon이 합법으로 만든 교체 후보를 제거해서는 안 된다(MUST NOT).
- 상대의 실제 미공개 기술, 특성, 도구, 성격, IV와 EV만 바꿔도 공개 관측이 같다면 후보 분석 결과는 같아야 한다(MUST).

## 4. 전술 기억과 계획

- 본체의 판단 조정기는 외부 Brain과 로컬 Brain에 같은 읽기 전용 `BattleTacticalMemoryView`를 제공해야 한다(MUST).
- 기억은 활성 계획, 최근 실행 행동과 결과, 예측 채점, 상황별 상대 습관, 자기 습관, 교체·기믹 사용 이력을 포함할 수 있다(MAY).
- 계획은 미래의 동적 `actionId`를 저장하지 않고 의도, 대상 역할, 만료 턴과 중단 조건을 저장해야 한다(MUST).
- 외부 응답의 계획·예측 메타데이터는 응답이 제한 시간 안에 도착하고, 행동 ID 검증을 통과하고, 해당 행동이 실제 제출된 경우에만 기억에 반영해야 한다(MUST).
- 제한 시간 이후 도착한 응답은 행동과 기억 양쪽에서 완전히 폐기해야 한다(MUST).
- 로컬 폴백은 직전까지 확정된 같은 계획과 성격을 사용해야 한다(MUST). 외부 장애가 NPC의 성격 변경처럼 보여서는 안 된다(MUST NOT).

## 5. 기억 범위

- 전투 안의 상세 기억은 `BattleBrainSession` 수명으로 유지해야 한다(MUST).
- 배틀타워의 같은 도전 런에서는 플레이어의 상황별 행동 집계만 다음 배틀에 전달할 수 있다(MAY).
- 런 집계는 상세 턴 로그, 닉네임, 채팅, 실제 미공개 세트와 모델 자유 텍스트를 저장해서는 안 된다(MUST NOT).
- 런이 끝나거나 폐기되면 집계도 폐기해야 한다(MUST). 첫 구현은 월드나 플레이어 영구 데이터로 저장해서는 안 된다(MUST NOT).
- 다른 플레이어나 다른 도전 런 사이에 습관 정보를 공유해서는 안 된다(MUST NOT).

## 6. 상황별 상대 모델과 혼합 전략

- 상대 경향은 전역 교체율 하나가 아니라 `UNDER_KO_THREAT`, `AFTER_SETUP`, `LOW_HP`, `FASTER`, `MECHANIC_AVAILABLE`, `DOUBLE_FOCUS_TARGET` 같은 공개 상황별로 집계해야 한다(MUST).
- 모든 비율에는 표본 수와 최근성 가중치를 함께 제공해야 한다(MUST).
- 작은 표본은 보정해야 하며, 과거 패턴과 최근 패턴이 크게 달라지면 오래된 증거의 가중치를 낮춰야 한다(SHOULD).
- 예측 행동은 다음 조건을 함께 만족할 때만 선택해야 한다(MUST).
  - 현재 상황과 같은 조건의 표본이 충분함
  - 안전 행동 대비 기대 이득이 있음
  - 실패 손실이 현재 승리 조건을 파괴하지 않음
  - 최근 예측 실패와 읽기 빈도 제한을 통과함
- 읽을 근거가 충분해도 같은 읽기를 항상 실행해서는 안 된다(MUST NOT). 상대가 AI의 읽기 빈도를 역이용하지 못하도록 성격과 근거 강도에 따른 제한된 혼합 전략을 사용해야 한다(SHOULD).
- 연속 교체는 절대 금지하지 않는다(MUST NOT). 최근 교체, 진입 위험과 반복 경로에 감점을 주되 강제 교체·안전 피벗·합법적인 순환은 허용해야 한다(MUST).

## 7. 외부 모델 호출 정책

- 기본 외부 Brain은 로컬 분석 결과를 전략적으로 재평가하는 하이브리드 방식이어야 한다(MUST).
- 외부 모델은 첫 턴, 강제 교체, 새 공개 정보, 계획 중단, 기믹으로 매치업을 바꿀 수 있는 국면과 상위 후보 점수차가 작은 결정 지점에서만 호출해야 한다(SHOULD).
- 일반 턴은 로컬 Brain이 확정된 계획을 집행할 수 있어야 한다(MUST).
- 하드 제한은 기존 계약대로 요청 대기열 진입부터 최대 10초다(MUST).
- 소프트 제한은 모델별 실제 지연 관측 전에는 강제하지 않으며, 도입할 경우 서버 설정값으로 둬야 한다(MUST).
- 외부 호출 여부, 비용 소진과 장애는 전투 합법성, 보상과 저장 경계를 바꿔서는 안 된다(MUST NOT).

## 8. 외부 요청과 응답

- 외부 요청은 전체 `BattleDecisionContext`와 원시 이벤트를 그대로 직렬화해서는 안 된다(MUST NOT).
- 요청은 익명 슬롯 별칭, 공개 사실 원장, 최근 1~3턴 요약, 상황별 경향, 확정된 계획과 후보별 전술 분석만 포함해야 한다(MUST).
- 플레이어 닉네임, 포켓몬 별명, 채팅, 책·표지판·NPC 대사와 API 키는 프롬프트에 포함해서는 안 된다(MUST NOT).
- 시스템 명령은 모델이 합법성·피해·속도를 다시 계산하지 않고 제공된 후보 중 하나만 선택하도록 고정해야 한다(MUST).
- 응답은 엄격한 JSON 스키마로 `actionId`, 선택적 `prediction`, 선택적 `planUpdate`, `reasonCodes`, `mindGameIntent`만 허용해야 한다(SHOULD).
- 실행에는 검증된 `actionId`만 사용해야 한다(MUST). 나머지 필드는 별도 검증 후 전술 기억과 관측에만 사용할 수 있다(MAY).
- 모델 자유 텍스트와 숨은 사고 과정은 실행, 로그와 플레이어 출력에 사용해서는 안 된다(MUST NOT).

## 9. 연출

- 첫 구현의 읽기·계획 해설은 전투 종료 후 공개된 사실과 서버 이유 코드로만 구성해야 한다(MUST).
- 실시간 읽기 연출은 기본 비활성 상태로 유지해야 한다(MUST). 향후 도입 시 다음 턴의 내부 확률·계획·미공개 추론을 노출해서는 안 된다(MUST NOT).
- 연출은 설정으로 완전히 비활성화할 수 있어야 한다(MUST).

## 10. 설정 쓰기 게이트

- OpenRouter 설정은 서버 전용 `config/cobblemon-more-battle-content-better-ai/openrouter.json`에 둬야 한다(MUST).
- 실제 키는 저장소, 테스트 리소스, 로그, 크래시 메시지와 클라이언트 패킷에 포함해서는 안 된다(MUST NOT).
- 안전 기본 파일은 `enabled: false`, 빈 `apiKey`, 빈 `model`이어야 한다(MUST).
- 2026-08-18 승인된 스키마 1은 `enabled: false`, 빈 키·모델, 하드 제한 10초, 소프트 제한 비활성(`0`), 동시 요청 2개, 대기열 32개, 전투당 최대 8회 호출을 안전 기본값으로 사용한다(MUST).

## 11. 검증 게이트

- 정보 누출 불변성: 미공개 실제 세트만 바꾼 동일 관측에서 상태·분석·판단이 같아야 한다(MUST).
- 계획 지속성: 외부 성공 후 다음 일반 턴과 외부 실패 턴에서 로컬이 같은 계획을 사용해야 한다(MUST).
- 지연 응답: 마감 뒤 도착한 행동·예측·계획이 모두 폐기되어야 한다(MUST).
- 교체 진동: 생성 시뮬레이션에서 불필요한 `A→B→A`와 연속 교체가 설정 상한을 넘지 않아야 한다(MUST).
- 예측 보정: 상황별 예측 정확도와 Brier score를 항상 공격 예측 기준선과 비교해야 한다(SHOULD).
- 실패 손실: 직진형·상습 교체형·혼합형·조건화 후 배신형·후반 적응형에서 무제한 읽기보다 최대 후회값이 낮아야 한다(MUST).
- 운영 경계: 잘못된 키, 인증·할당량·네트워크 오류와 비용 소진 중에도 로컬→기준선 폴백으로 배틀이 완료되어야 한다(MUST).

## 12. 채택하지 않은 방식

- 매 턴 원시 컨텍스트를 외부 모델에 보내는 방식은 비용, 지연과 계획 변덕을 키우므로 채택하지 않았다.
- 교체 근거가 없는 합법 후보를 제거하는 방식은 합법성과 전략 책임을 섞으므로 채택하지 않았다.
- 연속 교체를 절대 금지하는 방식은 정상 피벗과 강제 교체를 깨뜨리므로 채택하지 않았다.
- 단일 정수 `riskBudget`만으로 심리전을 제어하는 방식은 표본 신뢰도·현재 판세·실패 손실을 표현하지 못하므로 채택하지 않았다.
- 늦은 외부 응답을 기억에만 반영하는 방식은 실행되지 않은 가상 계획으로 실제 기억을 오염시키므로 채택하지 않았다.
- 높은 temperature로 사람다움을 만드는 방식은 개성이 아닌 무작위 실수를 늘리므로 채택하지 않았다.
- 실시간으로 구체적인 읽기 결과를 알려 주는 방식은 플레이어에게 다음 턴 전략 정보를 노출하므로 첫 구현에서 채택하지 않았다.

## 13. 구현 순서

1. 일반 Brain 프로필, 후보 분석과 공유 전술 기억의 공개 계약
2. 정확한 실패 테스트와 공개 정보 불변성 테스트
3. 로컬 Brain의 교체·회복·계획·혼합 전략 평가
4. 결정 지점 분류와 다이제스트 직렬화
5. 승인된 OpenRouter 설정 로더·클라이언트·제공자
6. 상황별 습관 집계와 배틀타워 런 범위 전달
7. 전투 후 이유 코드 해설과 운영 통계

각 단계의 빌드·JAR 생성과 실제 게임 플레이 검증은 별도 상태로 기록해야 한다(MUST).
