# Cobblemon: More Battle Content - Better AI 설계서

- Status: shared
- Effective: 2026-08-18
- Updates: `private-docs` 브랜치의 `BATTLE_AI_DESIGN.md`
- Scope: AI의 판단 품질, 공정 정보, 안전 경계, 로컬·외부 Brain과 운영 정책

기존 AI 설계의 내용과 품질 목표는 그대로 승계한다. 아래 후반부의 2026-08-13 구현 확정 기록은 기존 Battle Facilities 구현에서 검증된 근거로 보존한 것이며, `refactor` 브랜치의 새 패키지에 이미 이식됐다는 뜻은 아니다. 소드·실드 배틀타워 전용 매핑은 새 배틀타워 데이터의 참고자료일 뿐 Better AI의 현재 활성 정책이 아니다.

## 0. 2026-08-18 적용 결정

이 절은 아래의 과거 설계 중 폴백 소유권, capability와 콘텐츠 컨텍스트 범위를 갱신한다.

- **MUST:** Better AI가 설치되지 않았을 때 본체는 Cobblemon 기본 AI를 호출하는 내부 기준선 어댑터로 NPC 턴을 진행한다.
- **MUST:** Better AI가 설치된 경우 정상 폴백 순서는 `외부 Brain → Better AI 로컬 Brain → 본체 기준선 어댑터 → 비상 안전 행동`이다. 구성에서 외부 Brain을 사용하지 않으면 첫 단계를 건너뛴다.
- **MUST:** 비상 안전 행동은 서버가 검증한 첫 합법 후보 또는 Cobblemon의 안전한 패스다. 이는 마지막 장애 격리 수단이며 기준선 AI나 Better AI 품질로 간주하지 않는다.
- **MUST:** 초기 Brain capability는 `SINGLE`과 `DOUBLE`만 지원한다. `MEGA`, `DYNAMAX`, `TERA`를 별도 capability로 등록하지 않는다.
- **MUST:** 본체가 규칙, 설치된 호환 기능과 기믹 사용 상태를 검사해 합법 행동 후보를 만든다. Better AI는 기믹 후보의 전략적 가치만 평가하며 합법 여부를 결정하지 않는다.
- **MUST:** Better AI가 없어도 본체 기준선은 각 허용 기믹 프리셋에서 NPC의 합법적인 턴 제출과 전투 완료를 보장해야 한다. 기믹 사용 시점의 전술 품질은 Better AI의 평가 대상이다.
- **MUST:** 배틀타워와 배틀팩토리는 난도·성격·전략 프로필 외 콘텐츠 전용 AI 컨텍스트를 추가하지 않는다.
- **MUST NOT:** 보스 레이드용 공유 HP·단계·참가자 capability나 DTO를 미리 확정하지 않는다. 보스 레이드 구현 단계에서 일반 싱글·더블 계약으로 부족한 정보를 증명한 뒤 확장한다.

## 1. 문서 목적

- 대상 환경: Minecraft 1.21.1 / Fabric / Cobblemon 1.7.3
- 대상 모드:
  - `cobblemon_more_battle_content`
  - `cobblemon_more_battle_content_better_ai`(선택형 서버 애드온)
- 목적: NPC가 싱글·더블 배틀에서 합법적이고 설명 가능하며 난도 조절이 가능한 행동을 선택하도록 한다.
- 현재 단계: 기존 설계 승계 완료, 새 모듈 이식 전

## 2. 설계 원칙

1. **서버 권위:** 클라이언트와 외부 AI는 전투 결과를 결정하지 않는다.
2. **판단과 실행 분리:** Brain은 후보를 고르고 Cobblemon 엔진이 행동과 결과를 실행한다.
3. **동일한 정보 경계:** 로컬 Brain과 외부 AI Brain은 같은 `BattleStateView`를 받는다.
4. **미공개 정보 직접 열람 금지:** 플레이어가 공개하지 않은 기술, 도구, 특성, 대기 포켓몬의 실제 값을 직접 읽지 않는다. 종족과 관측 결과를 이용한 인간 수준의 추론은 허용한다.
5. **항상 가능한 폴백:** 외부 서비스가 없어도 Better AI 로컬 Brain으로 진행하고, Better AI 자체가 없거나 실패해도 본체 기준선 어댑터로 전투가 진행된다.
6. **데이터 주도:** 난도, 평가 가중치, 전략 프로필은 코드 수정 없이 조절할 수 있게 한다.
7. **설명 가능성:** 선택한 행동과 주요 점수 근거를 디버그 로그로 확인할 수 있게 한다.
8. **제한 시간 보장:** AI가 느리거나 실패해도 턴이 무기한 멈추지 않는다.

## 3. 전체 처리 흐름

```text
Cobblemon Battle
       ↓
BattleSnapshotAdapter
       ↓
KnowledgePolicy로 비공개 정보 제거
       ↓
BattleStateView
       ↓
BattleActionFactory가 합법 행동 후보 생성
       ↓
빠른 전처리 및 명백히 나쁜 후보 제거
       ↓
BattleBrain.decide(DecisionContext)
       ↓
BattleDecision(actionId, metadata)
       ↓
BattleActionValidator 재검증
       ↓
BattleActionExecutor
       ↓
Cobblemon Battle
```

Brain이 응답하지 않거나 잘못된 후보를 반환하면 같은 `DecisionContext`를 다음 Better AI Brain에 전달한다. Better AI 경로가 모두 실패하거나 애드온이 없으면 본체가 Cobblemon 기본 AI 기준선으로 위임한다.

### 3.1 기존 1차 공개 API 구현 상태와 승계 범위

- `BattleBrain`, `BattleBrainSession`, `BattleBrainOpenContext`, `BattleDecisionContext`, `BattleDecision` 계약은 기존 API 모듈에서 구현됐다. 새 구조에서는 Better AI가 사용할 최소 계약만 본체에 선별 재작성한다.
- 전투 상태는 Cobblemon 객체가 아닌 직렬화 가능한 읽기 전용 DTO로 전달한다. 상대의 미공개 레벨·기술·특성·도구는 `null` 또는 빈 집합으로 표현할 수 있다.
- 행동 후보는 서버가 고유 `actionId`를 발급하며 기술, 교체, 항복, 대기, 더블 조합 종류와 필요한 슬롯·대상만 포함한다.
- 기본 판단 제한은 10초다. 반환된 `requestId`, `actionId`, 마감 시각을 `BattleDecisionValidator`가 실행 직전에 다시 검사한다.
- 외부 모드는 네임스페이스 ID로 Brain을 등록할 수 있다. 같은 ID의 중복 등록은 거부한다.
- 초기 등록 capability는 `SINGLE`과 `DOUBLE`뿐이다. 주요 기믹은 서버가 생성한 행동 후보의 종류와 메타데이터로 전달하며 별도 provider capability로 분리하지 않는다.
- 난도는 입문·일반·상급·보스 단계와 가설 수·탐색 깊이·더블 후보 수로, 성격은 공격성·위험 감수·교체·전개·정보 선호의 독립 가중치로 표현한다.
- 이 단계에는 로컬 판단 알고리즘, 상태 스냅샷 변환기, Cobblemon 행동 실행 변환기와 폴백 조정기가 아직 포함되지 않는다.

## 4. 핵심 타입

아래 이름은 개념 설계이며 실제 언어와 Cobblemon API에 맞춰 조정할 수 있다.

### 4.1 BattleBrain

```kotlin
interface BattleBrain {
    val id: Identifier

    fun openSession(context: BrainOpenContext): BattleBrainSession

    fun decide(
        session: BattleBrainSession,
        context: DecisionContext
    ): CompletionStage<BattleDecision>

    fun closeSession(
        session: BattleBrainSession,
        result: BattleResult
    )
}
```

- `decide`는 로컬·외부 AI를 동일하게 지원하도록 비동기 반환형을 사용한다.
- 실제 서버 스레드를 블로킹하지 않는다.
- Brain 인스턴스는 공유할 수 있지만 전투별 가변 상태는 `BattleBrainSession`에 둔다.

### 4.2 DecisionContext

```kotlin
data class DecisionContext(
    val requestId: UUID,
    val turn: Int,
    val state: BattleStateView,
    val candidates: List<BattleActionCandidate>,
    val difficulty: DifficultyProfile,
    val strategy: StrategyProfile,
    val deadline: Instant
)
```

`requestId`는 한 번의 판단 요청을 식별한다. 같은 요청이 재시도되더라도 행동을 두 번 제출하지 않도록 사용한다.

### 4.3 BattleDecision

```kotlin
data class BattleDecision(
    val actionId: String,
    val confidence: Double?,
    val tags: Set<String>,
    val trace: DecisionTrace?
)
```

- `actionId`: 서버가 제공한 후보 중 하나
- `confidence`: 선택적 신뢰도이며 실행 여부를 단독 결정하지 않음
- `tags`: `ko`, `speed_control`, `safe_switch` 같은 분석용 분류
- `trace`: 서버 디버그 모드에서만 기록하는 선택 근거

### 4.4 BattleBrainSession

전투별 기억을 저장한다.

- 상대가 공개한 기술, 특성, 도구
- 관측된 속도 관계
- 이전 행동과 실제 결과
- 현재 전략 목표
- 보호 기술 연속 사용 횟수 등 확률 판단에 필요한 상태
- 외부 AI 호출 횟수와 남은 예산
- 시간 초과와 폴백 이력

월드 저장이 필요한 최소 정보와 일시적인 계산 캐시는 분리한다.

## 5. 전투 상태와 지식 정책

### 5.1 BattleStateView

Brain에 제공하는 읽기 전용 상태다.

- 배틀 형식과 현재 턴
- 날씨, 필드, 룸, 남은 지속 턴
- 양쪽 활성 슬롯
- 공개된 대기 포켓몬
- HP 비율, 상태이상, 능력치 랭크
- 공개된 기술·특성·도구
- 진입 위험과 필드 효과
- 양쪽 남은 포켓몬 수
- 이전 턴 행동과 결과
- AI 자신의 파티 전체 정보

Cobblemon 내부 객체를 그대로 넘기지 않고 직렬화 가능한 불변 DTO로 변환한다.

### 5.2 KnowledgePolicy

| 정책 | 설명 | 사용처 |
|---|---|---|
| `FAIR_INFERENCE` | 공개 정보와 종족·메타 지식을 바탕으로 확률적으로 추론 | 모든 정식 난도 |
| `OPEN_TEAM_SHEET` | 시작 시 공개하기로 한 정보 사용 | 특정 PvP형 규칙 |
| `OMNISCIENT` | 상대 전체 정보 사용 | 디버그·테스트 전용 |

정식 PvE 난도에서는 `OMNISCIENT`를 사용하지 않는다. 여기서 **정보 치팅**은 상대가 아직 보여 주지 않은 실제 기술, 특성, 도구, EV, 대기 포켓몬을 서버 내부 객체에서 직접 읽고 정답을 아는 상태로 판단하는 것을 뜻한다. 플레이어가 화면과 전투 결과로 알 수 없는 사실을 NPC만 읽는 것이므로 모든 정식 난도에서 금지한다.

반대로 종족, 일반적으로 쓰이는 세트, 공개된 기술, 실제 피해량, 행동 순서 등을 이용해 가능성을 좁히는 것은 허용한다. 이는 플레이어가 수행하는 추론과 같은 규칙을 따른다.

### 5.3 가설 기반 추론

AI는 상대 포켓몬을 처음 확인했을 때 가능한 세트 가설들을 생성한다. 마피아 게임에서 역할 후보를 세운 뒤 단서가 나올 때마다 가능성을 갱신하는 것과 같은 방식이다.

초기 가설의 근거:

- 종족이 가질 수 있는 기술, 특성 및 도구
- 싱글·더블 형식
- 현재 규칙에서 허용되는 세트
- 서버 렌탈·트레이너 세트 풀 또는 별도의 메타 지식 데이터
- 상대 파티에서 예상되는 역할
- 관측 전에는 실제 엔트리 데이터와 대조하지 않음

관측 시 갱신하는 정보:

- 사용하거나 실패한 기술
- 발동하거나 억제된 특성
- 공개·소모·발동된 도구
- 선후공 관계와 우선도
- 주고받은 피해량
- 상태이상과 필드 효과에 대한 반응
- 교체 패턴과 선택 경향
- 형태 변화와 전투 기믹

AI가 추론한 정보는 사실처럼 확정하지 않고 후보 가설과 확률 분포로 저장한다.

```text
Choice Scarf 가능성: 0.65
Protect 보유 가능성: 0.40
물리 공격형 가능성: 0.80
```

한 가설과 모순되는 정보가 확인되면 해당 가설의 가중치를 0 또는 매우 낮게 만들고 나머지를 다시 정규화한다. 확정적으로 공개된 정보는 확률이 아닌 사실로 승격한다.

```text
최초 조우
  → 가능한 세트 가설 생성
  → 사전 확률 부여
  → 매 행동 결과 관측
  → 가설별 일치도 계산
  → 확률 재분배
  → 행동 평가에 기대값으로 반영
```

초기 구현은 완전한 베이즈 모델보다 규칙 기반 가중치 갱신으로 시작한다. 구조는 가설 목록을 유지하도록 만들어 나중에 통계 기반 확률 모델로 교체할 수 있게 한다.

난도에 따른 차이는 볼 수 있는 정보가 아니라 **추론의 품질**이다.

- 입문 트레이너: 대표 가설 수가 적고 새 단서를 느리게 반영
- 일반 트레이너: 흔한 세트를 중심으로 기본적인 모순 제거
- 상급 트레이너: 피해량과 속도 관계까지 이용해 세트 범위를 좁힘
- 보스: 더 많은 가설을 유지하고 작은 단서를 결합하며 불확실성을 정밀하게 반영

보스도 실제 미공개 정보를 읽지는 않는다. 같은 단서를 보고 더 정확하게 추론할 뿐이다.

### 5.4 프로급 제약조건 추론

상급·보스 AI는 단순히 `스카프일 가능성이 높다`고 가중치를 올리는 수준을 넘어, 관측 결과와 양립할 수 없는 세트를 수학적으로 제거한다. 이를 `BattleInferenceEngine`으로 분리한다.

```text
사전 지식              관측 증거
- 종족 기본 스탯       - 실제 행동 순서
- 가능한 성격·EV       - 우선도와 속도 랭크
- 기술·특성·도구       - 실제 피해 범위
- 현재 필드 효과       - 발동 메시지와 상태 변화
        \               /
         Constraint Solver
                ↓
       가능한 세트 범위 갱신
                ↓
   확정 / 사실상 확정 / 유력 / 불명
```

#### 속도 추론

각 포켓몬의 가능한 실수치 범위를 계산한다.

```text
possibleSpeed = speciesBaseSpeed
              + level
              + nature candidates
              + EV/IV candidates
              + item modifier
              + ability modifier
              + stat stage
              + field modifier
```

행동 순서를 관측하면 다음 조건을 추가한다.

```text
같은 우선도이고 트릭룸이 아님:
observedFirst.speed >= observedSecond.speed
```

예를 들어 AI의 최속 한카리아스보다 상대 한카리아스가 먼저 행동했다면 다음을 순서대로 검사한다.

1. 두 기술의 우선도가 같은가?
2. 트릭룸 또는 행동 순서 반전 효과가 없는가?
3. AI 측에 마비, 속도 랭크 하락 등 보정이 없는가?
4. 상대에게 순풍, 날씨 연계 특성 등 다른 속도 보정이 없는가?
5. 동속 가능성이 있는가?
6. 남은 합법 세트 중 구애스카프 없이 관측을 만족하는 경우가 존재하는가?

스카프 없는 모든 가설이 불가능하면 `Choice Scarf 확정`으로 승격한다. 동속 승리나 다른 특성 가능성이 남아 있으면 확정하지 않고 확률만 높인다.

속도 추론은 정확한 수치 하나보다 가능한 구간을 관리한다.

```text
상대 속도 추론 범위: 270..333
관측 후 하한 갱신:   310..333
스카프 미착용 최대:  299
결론: 스카프 또는 다른 속도 배율 효과 필요
```

#### 피해량 역추론

주고받은 피해로 공격·방어 실수치, 성격, EV, 도구와 특성 가설을 좁힌다.

- 실제 피해를 최대 HP 대비 범위로 기록
- 기술 위력, 타입, 날씨, 필드, 랭크와 공개 효과 반영
- 가능한 세트별 피해 난수 범위 계산
- 관측 피해가 범위 밖인 가설 제거
- 생명의구슬, 구애머리띠, 돌격조끼 등 후보 확률 갱신
- 급소, 난수, 복수 타깃 기술 보정 등 특수 상황을 별도 표시

피해량은 난수가 있으므로 한 번의 관측으로 성급히 확정하지 않는다. 여러 번의 피해 관측이 같은 가설을 지지하면 신뢰도를 높인다.

#### 기술과 도구의 논리 추론

확정 가능한 예:

- 기술을 직접 사용함 → 해당 기술 보유 확정
- 도구가 발동·소모됨 → 해당 도구 확정
- 구애 상태에서 다른 기술을 정상 사용함 → 구애 계열 가설 제거
- 특정 특성만 설명 가능한 메시지가 발생함 → 특성 확정
- 기술 네 개가 모두 공개됨 → 다른 기술 가설 제거

강한 추정에 머물러야 하는 예:

- 큰 피해를 줌 → 공격 EV나 강화 도구 가능성이 높지만 급소·난수 고려
- 매번 교체함 → 구애 도구일 수 있지만 플레이어 판단일 수도 있음
- `Protect`를 쓰지 않음 → 미보유 증거가 되지 않음
- 먼저 행동함 → 동속, 우선도, 필드 보정을 모두 배제하기 전에는 스카프 확정 불가

#### 확신 단계

| 단계 | 의미 | 행동 반영 |
|---|---|---|
| `CONFIRMED` | 공개 사실이거나 다른 합법 가설이 없음 | 사실로 사용 |
| `NEAR_CERTAIN` | 극히 드문 예외만 남음 | 강하게 반영하되 안전책 유지 |
| `LIKELY` | 가장 유력하지만 현실적인 대안 존재 | 기대값으로 반영 |
| `POSSIBLE` | 가능한 후보 중 하나 | 낮은 가중치 유지 |
| `RULED_OUT` | 관측과 양립 불가 | 후보 제거 |

`CONFIRMED`는 단순 확률 임계값이 아니라 논리적 증명 사유를 함께 저장한다.

```text
fact: held_item = choice_scarf
confidence: CONFIRMED
proof:
  - same_priority
  - no_trick_room
  - no_external_speed_modifier
  - observed_speed_greater_than_333
  - non_scarf_legal_max_speed_333
```

#### 구현 난도 관리

전체 포켓몬 조합을 매 턴 처음부터 계산하면 비싸므로 다음 방식으로 제한한다.

- 종족별 대표 세트와 합법 실수치 구간을 미리 캐시
- 관측 이벤트가 발생할 때만 관련 제약 갱신
- 불가능해진 가설은 즉시 제거
- 같은 피해 계산 결과 캐시
- Brain 판단 시에는 이미 정리된 가설 요약만 사용
- 알 수 없는 커스텀 효과는 억지로 확정하지 않고 `UNKNOWN_MODIFIER`로 남김

프로 추론은 외부 AI 모델이 직접 계산하는 기능이 아니다. 로컬 `BattleInferenceEngine`이 정확한 게임 규칙으로 가설과 증명을 계산하고, 로컬 또는 외부 Brain은 그 결과를 받아 전략 판단에 사용한다. 이렇게 해야 산술 오류와 환각을 막고 모든 Brain에 동일한 추론 능력을 제공할 수 있다.

## 6. 행동 후보 생성

### 6.1 기본 행동

- `UseMoveAction(userSlot, moveSlot, targetSlot)`
- `SwitchAction(userSlot, partySlot)`
- `ForfeitAction(reason)`
- `WaitAction(reason)`
- `CompositeAction(actions)`

### 6.2 싱글 후보

- 사용 가능한 각 기술과 합법적인 대상
- 교체 가능한 각 대기 포켓몬
- 전투 시스템이 요구하는 특수 선택

### 6.3 더블 후보

각 활성 포켓몬의 단일 행동 후보를 먼저 만든 뒤 합법적인 조합을 생성한다.

제외해야 하는 조합 예시:

- 두 슬롯이 같은 대기 포켓몬으로 교체
- 이미 교체로 비워질 아군을 대상으로 하는 행동
- 선택 불가능한 대상 지정
- 기절하거나 행동 불가능한 슬롯의 일반 행동
- 규칙상 동시에 사용할 수 없는 특수 기믹 중복

더블 후보 수가 지나치게 커지므로 두 단계로 줄인다.

1. 슬롯별 단일 행동을 빠르게 평가해 상위 `K`개를 남긴다.
2. 남은 행동의 조합만 만들고 조합 시너지를 평가한다.

`K`는 난도와 서버 성능 설정에 따라 조정한다. 낮은 난도에서 후보를 무작위로 버리지는 않고 계산량과 판단 정밀도만 낮춘다.

## 7. 로컬 AI 평가 로직

### 7.1 평가 파이프라인

```text
후보 행동
  → 즉시 효과 평가
  → 턴 종료 예상 상태 평가
  → 위험과 불확실성 반영
  → 전략 프로필 가중치 적용
  → 반복·실수 모델 적용
  → 최종 점수
```

기본 점수 범위는 `-1000 ~ +1000`으로 정규화한다. 강제 승리와 즉시 패배에 가까운 판단만 범위 끝값을 사용한다.

### 7.2 공통 평가 항목

| 항목 | 내용 |
|---|---|
| 피해 | 예상 피해 비율과 피해 안정성 |
| KO | 상대를 쓰러뜨릴 확률과 가치 |
| 생존 | 행동 후 살아남을 가능성 |
| 속도 | 선공 여부와 속도 제어 변화 |
| 상태 | 수면, 마비, 화상 등 기대 가치 |
| 랭크 | 능력치 상승·하락의 예상 지속 가치 |
| 필드 | 날씨, 필드, 룸, 진입 위험 |
| 위치 | 교체 후 상성과 다음 턴 선택지 |
| 정보 | 상대 세트 확인으로 얻는 가치 |
| 자원 | 일회성 도구, 기믹, 핵심 포켓몬 보존 |
| 위험 | 빗나감, 무효화, 예측 실패 가능성 |

초기 예시 점수이며 실제 값은 테스트로 조정한다.

```text
확정 KO                  +250
핵심 상대 KO             +80 추가
아군 포켓몬 손실         -220
유리한 속도 제어 확보    +70
상대 주요 기술 무효화    +60
명백히 무효인 기술       -500
불필요한 반복 행동       -40 ~ -150
```

### 7.3 예상 피해

- 가능한 경우 Cobblemon 또는 Showdown 계층의 실제 계산 로직을 재사용한다.
- AI가 별도 피해 공식을 복제해 엔진과 결과가 달라지는 상황을 피한다.
- 난수 피해는 최소·평균·최대와 KO 확률로 표현한다.
- 미공개 상대 세트는 추론 범위에 따라 여러 가정을 가중 평균한다.

### 7.4 교체 평가

교체 점수는 단순 타입 상성만으로 결정하지 않는다.

- 교체 진입 시 받는 예상 피해
- 스텔스록 등 진입 위험
- 교체 후 상대 기술에 대한 내성·면역
- 다음 턴 압박과 KO 가능성
- 현재 포켓몬을 보존할 가치
- 상대의 교체 예상
- 교체되는 포켓몬의 핵심 역할
- 더블에서는 남은 아군과의 조합

교체 반복을 막기 위해 짧은 기간 내 같은 교체 패턴에 감점한다. 단, 실제로 교체 반복이 최적 전략인 상황까지 완전히 금지하지는 않는다.

## 8. 싱글 Brain

### 8.1 기본 판단 순서

1. 즉시 패배를 막는 강제 행동 확인
2. 확정 또는 높은 확률의 KO 확인
3. 상대의 확정 KO 위협에 대한 교체·방어 판단
4. 필드와 상태이상 가치 평가
5. 랭크업 또는 승리 조건 준비
6. 중립 상황에서 피해·위치·정보 가치 비교

이 순서는 하드코딩된 절대 우선순위가 아니라 후보 평가의 특징으로 사용한다. 예외 상황에서 낮은 항목이 더 높은 총점을 얻을 수 있어야 한다.

### 8.2 승리 조건 추적

AI는 남은 파티 중 누가 후반 승리 조건인지 태그로 관리한다.

- `SWEEPER`
- `WALL_BREAKER`
- `DEFENSIVE_CORE`
- `SPEED_CONTROL`
- `UTILITY`
- `SACRIFICE_CANDIDATE`

승리 조건 포켓몬을 초반에 불필요하게 희생하면 큰 감점을 적용한다. 반대로 역할을 마친 포켓몬을 희생해 안전하게 교체하는 판단은 허용한다.

### 8.3 위협 대응과 생존 판단

AI는 활성 포켓몬이 다음 상대 행동에 쓰러질 가능성을 먼저 평가한다.

```text
incomingThreat = 상대의 가능한 행동별 KO 확률
               × 해당 행동을 선택할 추정 확률
```

확정 1타 또는 매우 높은 확률의 KO 위협이 있으면 다음 선택지를 비교한다.

1. 현재 자리에서 더 빠르게 상대를 쓰러뜨릴 수 있는가?
2. 선공기, 방어 기술, 무효화 기술로 위협을 피할 수 있는가?
3. 기합의띠, 옹골참, 반감열매 등 공개되거나 추론된 생존 수단이 있는가?
4. 안전하게 받아낼 교체 포켓몬이 있는가?
5. 교체 포켓몬이 진입 피해와 상대의 다음 기술까지 견디는가?
6. 상대가 교체를 읽고 다른 기술을 쓸 가능성이 있는가?
7. 현재 포켓몬을 희생해 핵심 포켓몬을 안전하게 진입시키는 편이 나은가?
8. 현재 포켓몬이 승리 조건 또는 반드시 보존할 역할인가?

교체 가능한 포켓몬이 있고 현재 자리를 지킬 실익이 없다면 교체 점수에 강한 보너스를 준다. 그러나 아래 상황에서는 확정 1타 위협에도 잔류할 수 있다.

- AI가 먼저 확정 KO를 낼 수 있음
- 교체 후보도 같은 기술에 쓰러지거나 진입 위험 때문에 안전하지 않음
- 상대의 예측 기술까지 고려하면 유효한 교체가 없음
- 현재 포켓몬의 역할이 끝났고 희생 후 안전 진입 가치가 큼
- 마지막 포켓몬이라 교체할 수 없음
- 방어·회복·무효화 행동으로 더 큰 이득을 얻음

즉, `확정 1타 → 무조건 교체`가 아니라 `현재 자리 유지의 기대값보다 안전 교체의 기대값이 높음`을 판단한다.

### 8.4 안전 교체 평가

교체 후보마다 다음 턴까지의 위험을 계산한다.

```text
safeSwitchScore = 진입 후 생존 가치
                + 상대 기술 무효·반감 가치
                + 다음 턴 압박
                + 핵심 포켓몬 보존 가치
                - 진입 위험 피해
                - 상대의 교체 예측 대응
                - 회복 불가능한 자원 손실
```

안전 교체의 등급:

- `HARD_CHECK`: 상대의 주요 가설 대부분을 안정적으로 상대
- `SOFT_CHECK`: 특정 기술에는 안전하지만 다른 기술에 위험
- `PIVOT`: 한 번 받고 유리한 포켓몬을 다시 투입 가능
- `SACRIFICE`: 생존은 어렵지만 안전 진입권을 만듦
- `UNSAFE`: 현재 합리적 가설에 대해 교체 가치가 없음

AI는 `HARD_CHECK`가 있다는 이유만으로 반복 투입하지 않는다. HP, 도구 소모, 진입 위험 누적과 해당 포켓몬이 맡아야 할 다른 상대까지 고려한다.

### 8.5 필수 전술 판단 목록

#### 공격 판단

- 확정 KO와 난수 KO 구분
- 명중률을 포함한 실질 KO 확률
- 반동 피해로 인한 동시 기절
- 선공기와 우선도 역전
- 상대의 면역, 흡수 특성 및 반감열매 가능성
- 상대 교체 시 가장 손해가 적은 일관성 있는 기술
- 기술 PP와 구애 상태
- 급소에 의존하는 행동의 위험도

#### 방어와 회복

- 회복량과 다음 피해량 비교
- 회복해도 같은 턴 또는 다음 턴에 쓰러지는지 검사
- `Protect` 성공 확률과 연속 사용 감점
- 날씨·독·화상·씨뿌리기 등 턴 종료 피해
- 방어 행동으로 날씨·필드·룸 턴을 소모하는 가치
- 상대의 랭크업 기회를 무료로 주는 위험

#### 랭크업과 설치

- 랭크업 후 실제로 추월·KO 가능한 상대 수
- 랭크업 중 받는 피해와 상태이상 위험
- 상대의 도발, 앙코르, 날려버리기, 클리어스모그 등 대응 가능성
- 스텔스록 등 설치기의 기대 교체 횟수
- 이미 충분히 설치된 효과의 중복 사용 방지
- 필드 제거가 아군과 상대 중 누구에게 더 유리한지 평가

#### 상태이상

- 이미 상태이상인 대상에게 중복 시도 금지
- 타입·특성·필드에 의한 상태이상 면역
- 수면 규칙과 남은 수면 턴
- 물리형에게 화상, 고속형에게 마비 등 역할별 가치
- 독 누적을 위해 시간을 벌 수 있는지
- 상태 기술 반사·도발 가능성

#### 교체와 희생

- 핵심 역할 포켓몬 보존
- 죽어내밀기로 얻는 속도·상성 우위
- 교체 반복과 진입 위험 누적
- 상대의 추격성 기술 또는 교체 방해 효과
- 희생할 포켓몬의 남은 역할과 PP
- 한 마리를 희생하면 확정적으로 승리 구도가 만들어지는지

#### 자원 관리

- 일회성 도구와 열매
- 포켓몬별 남은 HP와 PP
- 전투당 한 번인 특수 기믹
- 날씨·필드·룸을 설치할 수 있는 남은 수단
- 후반 스위퍼를 막을 유일한 포켓몬
- 상대의 마지막 미공개 포켓몬에 대비한 보험

### 8.6 종반 승리 계산

남은 포켓몬과 가능한 행동 수가 충분히 작아지면 일반 점수 평가보다 종반 계산을 우선한다.

- 확정 승리 경로가 있으면 성격보다 우선
- 상대의 모든 합리적 대응에 이기는 행동 탐색
- PP 고갈, 발버둥, 턴 종료 피해 포함
- 동시 기절 시 현재 규칙의 승패 판정 반영
- 불필요한 예측 대신 승리를 보장하는 안전 행동 선택
- 확정 승리가 없으면 승률이 가장 높은 경로 선택

보스와 엘리트는 종반 계산을 더 일찍 시작하고, 낮은 단계는 명백한 1~2턴 승리만 인식한다.

## 9. 더블 Brain

### 9.1 조합 단위 평가

더블에서는 행동 두 개의 개별 점수를 더하는 것만으로 부족하다.

```text
조합 점수 = 행동 A 점수
          + 행동 B 점수
          + 두 행동의 시너지
          - 충돌과 과잉 투자
          - 상대 최선 대응 위험
```

### 9.2 주요 시너지

- 집중 공격으로 확정 KO 달성
- `Protect` + 파트너의 전체 공격
- 날씨 설정 + 날씨 활용 기술
- 트릭룸 설정 + 저속 공격
- 속도 제어 + 선공권 확보
- 날따름 계열 + 랭크업 또는 설치
- 아군 대상 기술 + 면역·흡수 특성
- 위협적인 슬롯을 묶고 다른 슬롯으로 공격

### 9.3 주요 충돌

- 이미 쓰러질 대상을 두 번 공격하는 과잉 투자
- 아군에게 치명적인 전체기 사용
- 같은 효과를 불필요하게 중복 설치
- 한 행동 때문에 다른 행동의 대상이 사라짐
- 트릭룸을 설치하면서 동시에 해제
- 날씨·필드를 서로 덮어쓰기

### 9.4 상대 대응 모델

초기 버전은 상대의 대표 대응 몇 개만 평가한다.

- 그대로 공격
- 위협받는 포켓몬 교체
- `Protect`
- 집중 공격
- 속도 제어

상급 Brain은 후보 행동을 상대의 상위 대응들과 대조해 최악의 경우와 평균 결과를 혼합한다.

```text
robustScore = expectedScore × 0.7 + worstPlausibleScore × 0.3
```

계수는 난도 프로필에서 조절한다.

### 9.5 더블 위협 대응

더블에서는 각 활성 슬롯에 대해 상대 두 포켓몬의 단독·집중 공격 KO 가능성을 계산하고, 행동 조합 이후의 전체 보드를 비교한다.

- 집중 공격을 받을 가능성이 높은 슬롯의 `Protect`
- 한 슬롯이 방어하는 동안 파트너가 위협 제거
- 위험한 슬롯만 교체하고 파트너는 공격
- 날따름 계열로 핵심 포켓몬 보호
- 위협적인 상대를 속이다, 재우기, 도발 등으로 행동 차단
- 속도 제어로 두 아군이 먼저 행동하도록 만들기
- 광역기 피해와 대미지 감소 보정
- 한 상대를 이미 쓰러뜨릴 수 있을 때 과잉 집중 방지
- 아군 전체기와 면역·방어·교체의 조합
- 교체로 날씨·특성·위협 효과를 재발동하는 가치

더블의 교체 판단은 교체되는 슬롯만 평가하지 않는다. 교체 후 파트너가 상대 두 마리에게 노출되는지, 새 포켓몬의 특성으로 행동 순서와 타깃 선택이 바뀌는지까지 다시 계산한다.

### 9.6 더블 특수 상황

- `Fake Out` 가능한 첫 턴과 재등장 여부
- `Wide Guard`, `Quick Guard`, `Ally Switch` 등 방어 선택 가능성
- 날따름·분노가루와 해당 효과를 무시하는 기술·특성
- 전체기 사용 시 아군 피해·면역·흡수·약점보험 발동
- 한쪽 슬롯이 기절할 것이 확정될 때 행동 낭비 방지
- 두 포켓몬이 동시에 같은 제한 자원을 쓰는 조합 금지
- 트릭룸 설정 턴의 생존과 설정 직후 속도 순서
- 날씨·필드 변경으로 이번 턴 기술 위력이나 우선도가 바뀌는 상황
- 상대의 `Protect` 가능성이 높을 때 다른 슬롯 압박
- 마지막 2대1 또는 1대2 구도에서 광역기와 집중 공격 비교

## 10. 난도 프로필

난도는 AI에게 불법 정보를 주거나 스탯을 조작하지 않고 판단 품질과 실수율로 조절한다.

| 설정 | 입문 | 일반 | 상급 | 엘리트 |
|---|---:|---:|---:|---:|
| 슬롯별 후보 K | 3 | 5 | 8 | 제한 내 전체 |
| 상대 대응 고려 | 없음 | 1개 | 3개 | 3개 이상 |
| 교체 평가 | 낮음 | 기본 | 정밀 | 정밀 |
| 미래 탐색 | 없음 | 없음 | 선택적 1턴 | 1턴 |
| 점수 오차 | 큼 | 보통 | 작음 | 매우 작음 |
| 상위 후보 무작위 선택 | 높음 | 보통 | 낮음 | 거의 없음 |
| 종족 기반 추론 | 기본 | 보통 | 정밀 | 정밀 |

종족 기반 추론은 모든 단계에서 수행하도록 수정한다. 위 표의 차이는 추론 유무가 아니라 유지하는 가설 수와 갱신 정밀도를 뜻한다.

| 추론 설정 | 입문 | 일반 | 상급 | 보스 |
|---|---:|---:|---:|---:|
| 종족당 유지 가설 수 | 2~3 | 4~6 | 6~10 | 설정 한도 내 전체 |
| 기술 공개 반영 | 즉시 | 즉시 | 즉시 | 즉시 |
| 피해량 역추론 | 사용 안 함 | 거친 범위 | 정밀 범위 | 정밀 범위+복수 가설 |
| 속도 관계 추론 | 명백한 경우 | 기본 | 우선도·보정 고려 | 가능한 원인별 확률 유지 |
| 상대 대응 모델 | 없음 | 대표 1개 | 상위 3개 | 상위 대응과 위험 분포 |

추론 계산기 자체는 같은 정확한 게임 규칙을 사용하되, 단계별로 활성화되는 모듈과 사용할 수 있는 증거가 다르다.

- 입문: 공개 사실과 기본 종족 세트 가설
- 일반: 기술·도구 모순 제거와 단순 속도 비교
- 상급: 실수치 범위, 피해량 역산, 복수 가설 갱신
- 보스: 모든 프로 추론 모듈, 증명 기반 확정, 상대 대응별 위험 계산

서버 설정으로 일반 트레이너에게도 보스급 프로 추론을 부여할 수 있다. 트레이너 단계는 기본 프리셋일 뿐 API의 강제 제한은 아니다.

### 10.1 실수 모델

낮은 난도라고 명백히 무효인 기술을 계속 쓰게 만들지는 않는다. 먼저 치명적으로 잘못된 행동을 제외하고, 남은 합리적인 상위 후보 중 가중 무작위로 선택한다.

```text
확률(action) = softmax(score / temperature)
```

- 높은 `temperature`: 선택이 다양하고 실수가 늘어남
- 낮은 `temperature`: 최고점 행동을 주로 선택

보스 성격에 따라 공격적·방어적 실수를 다르게 만들 수 있다.

## 11. 전략 프로필

`StrategyProfile`은 같은 Brain을 사용하는 NPC 사이에 성격과 운영 차이를 만든다.

예시 프로필:

- `balanced`: 피해, 생존, 위치를 균형 있게 평가
- `aggressive`: KO와 피해를 중시하고 교체를 덜 함
- `defensive`: 생존, 상태이상, 교체와 자원 보존 중시
- `tempo`: 속도 제어와 유리한 위치 유지 중시
- `setup`: 승리 조건을 위한 랭크업과 지원 중시
- `weather`: 날씨 유지와 날씨 에이스 보존 중시
- `trick_room`: 트릭룸 설치·유지와 저속 포켓몬 보존 중시

프로필은 평가기의 가중치만 변경하며 새로운 실행 권한을 주지 않는다.

### 11.1 성격과 숙련도 분리

NPC의 판단은 `TrainerPersonality`와 `TrainerRank`를 조합해 만든다.

```text
최종 판단 성향
= 공통 평가 점수
+ 트레이너 성격 가중치
+ 트레이너 단계의 추론·탐색 보정
+ 현재 전투에서 형성된 단기 전략
```

`TrainerPersonality`는 무엇을 선호하는지 결정한다.

- 공격적: KO, 집중 공격, 고위력 저명중 기술 선호
- 신중함: 생존, 안정 명중, 안전한 교체 선호
- 전술적: 상태이상, 필드, 속도 제어와 정보 수집 선호
- 도박형: 고위험·고보상 행동과 예측 교체 선호
- 집착형: 에이스나 특정 전략을 오래 유지하려는 경향
- 적응형: 관측된 상대 습관에 가중치를 빠르게 조정

`TrainerRank`는 얼마나 잘 판단하는지 결정한다.

- 신입 트레이너: 적은 가설, 얕은 대응 탐색, 성격 편향이 강함
- 일반 트레이너: 기본 추론과 합리적인 행동 선택
- 베테랑: 피해·속도 단서를 결합하고 교체를 정밀 평가
- 엘리트: 복수 대응을 비교하고 장기 자원을 보존
- 보스: 가장 많은 가설과 높은 탐색 정밀도, 성격에 맞는 장기 계획 유지

따라서 낮은 단계의 공격적 트레이너와 보스급 공격적 트레이너는 모두 공격을 선호하지만, 전자는 눈앞의 피해에 치우치고 후자는 에이스 보존과 상대의 방어 대응까지 고려한다.

난도를 위해 성격을 없애지 않는다. 보스도 항상 수학적으로 같은 최적 행동만 고르기보다 자신의 성격 범위 안에서 강한 판단을 한다. 단, 명백한 자살 행동이나 불법 행동은 성격과 무관하게 제외한다.

## 12. 외부 AI Brain

### 12.1 역할

외부 AI는 피해 계산기나 전투 엔진이 아니다. 서버가 생성하고 요약한 상태, 평가 정보, 합법 행동 후보 중 전략적으로 가장 적절한 후보를 선택한다.

권장 방식은 다음 두 가지다.

1. `ExternalAiBrain`: 모든 후보를 받아 직접 선택
2. `HybridBattleBrain`: 로컬 AI 상위 후보 3~8개만 외부 AI가 재평가

기본은 `HybridBattleBrain`으로 한다. 비용과 지연을 줄이고 외부 AI의 계산 오류 범위를 제한할 수 있다. AI 연동 모드가 활성화된 서버에서는 일반 트레이너부터 보스까지 모든 NPC가 외부 AI Brain을 사용할 수 있다. 보스 전용으로 제한하지 않는다.

NPC 단계의 차이는 외부 AI 사용 여부가 아니라 전달하는 추론 결과, 유지하는 가설 수, 로컬 후보 평가의 정밀도, 외부 AI에게 요구하는 대응 탐색 수준으로 만든다. 동일한 외부 모델을 사용해도 신입 트레이너는 제한된 분석 자료와 강한 성격 편향을 받고, 보스는 풍부한 가설과 정밀한 분석 자료를 받는다.

### 12.2 요청 데이터

- 규칙과 승리 조건
- 공개 정보만 포함한 현재 전장
- 이전 1~3턴의 요약
- 현재 전략 목표
- 합법 행동 후보 ID
- 각 후보의 간략한 전술적 결과
- 반드시 지켜야 하는 응답 스키마

전체 전투 로그나 내부 객체를 그대로 전송하지 않는다.

### 12.3 응답 형식

```json
{
  "action_id": "double:m1-target1+m2-self",
  "confidence": 0.78,
  "strategy_tag": "speed_control"
}
```

자유 텍스트 설명은 실행에 사용하지 않는다.

### 12.4 실패 처리

다음 조건이면 현재 요청을 실패로 처리한다.

- 제한 시간 초과
- 네트워크 오류
- 인증 또는 할당량 오류
- JSON 스키마 불일치
- 존재하지 않는 행동 ID
- 이미 상태가 바뀐 오래된 응답
- 경기 호출·비용 예산 초과

실패 시 같은 턴의 최신 상태로 로컬 Brain을 실행한다. 외부 AI 요청의 늦은 응답은 폐기한다.

### 12.5 호출 정책

- 일반 NPC부터 보스까지 외부 AI Brain 지정 허용
- AI 연동 모드가 활성화된 기본 프리셋은 모든 NPC에 외부 AI 사용
- 비용 절약 프리셋에서는 쉬운 NPC가 전략 전환점에만 호출 가능
- 보스는 더 정밀한 추론 자료와 높은 후보·대응 예산 사용
- 운영자 실험 모드에서는 모든 NPC의 매 턴 직접 평가 허용
- 서버 전체 동시 호출 제한
- 전투별 호출 횟수와 비용 제한
- 반복 상태는 안전한 범위에서 캐시 가능

## 13. 동시성과 제한 시간

### 13.1 스레드 원칙

- Cobblemon 상태 읽기와 행동 실행은 서버 스레드에서 한다.
- 로컬의 무거운 탐색과 외부 HTTP 요청은 작업 스레드에서 한다.
- 작업 스레드에는 불변 `BattleStateView`만 전달한다.
- 응답 실행 전 서버 스레드에서 턴, 요청 ID, 후보 유효성을 다시 확인한다.

### 13.2 권장 시간 예산 초안

| Brain | 목표 | 최대 제한 |
|---|---:|---:|
| 기본 로컬 | 10ms 이하 | 50ms |
| 고급 로컬 | 50ms 이하 | 250ms |
| 외부 AI | 3초 이하 | 10초 |

외부 AI 판단의 절대 제한 시간은 **10초**로 한다. 10초가 지나면 요청을 취소하거나 늦은 응답을 폐기하고 즉시 로컬 폴백 Brain으로 결정한다. 플레이어 화면에는 NPC가 생각 중이라는 상태와 남은 제한 시간을 표시할 수 있다.

서버 TPS가 낮으면 탐색 깊이를 자동으로 낮출 수 있다. 시간 초과가 발생해도 무작위 불법 행동이 아니라 더 빠른 폴백 Brain을 실행한다.

## 14. Brain 등록과 선택

API 레지스트리 예시:

```kotlin
BattleBrainRegistry.register(
    id = id("local_search"),
    factory = ::LocalSearchBrain,
    capabilities = setOf(SINGLE, DOUBLE)
)
```

트레이너 프로필 예시:

```json
{
  "brain": "cobblemon_more_battle_content_better_ai:hybrid",
  "fallback_brain": "cobblemon_more_battle_content_better_ai:local",
  "difficulty": "cobblemon_more_battle_content:elite",
  "strategy": "cobblemon_more_battle_content:rain_offense"
}
```

선택 순서:

1. 지정 Brain 등록 여부 확인
2. 현재 형식 지원 여부 확인
3. 설정과 API 키 등 준비 상태 확인
4. 지정 Brain 사용
5. 실패하면 프로필의 폴백 Brain
6. Better AI 경로가 모두 실패하면 본체의 Cobblemon 기본 AI 기준선 어댑터
7. 기준선 위임도 불가능할 때만 첫 합법 후보 또는 안전한 패스

## 15. 안전 경계

Brain이 직접 할 수 없는 작업:

- 서버 명령 실행
- 파일 읽기·쓰기
- BP 지급과 차감
- 아이템 지급
- 엔티티 생성과 제거
- 플레이어 순간이동
- 월드 블록 변경
- 임의 네트워크 요청

Brain은 등록된 `BattleAction`만 선택한다. 외부 AI 네트워크 요청은 `cobblemon_more_battle_content_better_ai` 내부의 제한된 클라이언트만 수행한다.

대사, 바라보기, 지정 위치 이동, 애니메이션 같은 연출은 전투 행동과 분리된 `NpcPresentationAction` 허용 목록으로 처리한다.

## 16. 로그와 관측

일반 로그:

- Brain ID와 전략·난도 프로필
- 판단 소요 시간
- 후보 수와 선택한 행동
- 폴백 여부와 사유
- 잘못된 응답과 시간 초과

디버그 로그:

- 상위 후보와 총점
- 점수 구성 항목
- 지식 정책으로 가려진 정보 종류
- 더블 조합 시너지와 충돌
- 외부 AI 요청의 해시, 모델 식별자, 프롬프트 버전

API 키와 전체 인증 헤더는 어떤 로그에도 기록하지 않는다. 외부 AI 요청 원문 로그는 기본 비활성화한다.

추가 결정 필요:

1. 싱글과 더블에서 배틀 시작 시 상대 엔트리 종족을 어디까지 공개할 것인가?

3. 같은 NPC가 플레이어의 이전 경기 성향을 다음 경기까지 기억할 수 있는가?
4. 외부 AI 호출 비용 제한에 도달했을 때 관리자에게만 알릴지 플레이어에게도 표시할지 결정해야 한다.
5. AI 디버그 로그를 관리자만 볼지, 전투 후 플레이어에게 간단한 해설로 제공할지 결정해야 한다.

## 20. 외부 AI 설정과 API 키

### 20.1 서버 전용 설정 파일

OpenRouter API 키와 모델은 서버의 `config/cobblemon-more-battle-content-better-ai/openrouter.json`에서 읽는다. 서버 운영자가 직접 편집하며 이 실제 파일은 배포물이나 Git에 포함하지 않는다.

```json
{
  "schemaVersion": 1,
  "enabled": true,
  "apiKey": "SERVER_OPERATOR_SECRET",
  "model": "google/gemini-3.1-flash-lite",
  "modelsByDifficulty": {},
  "endpoint": "https://openrouter.ai/api/v1/chat/completions",
  "timeoutMillis": 10000,
  "requireStructuredOutput": true,
  "appUrl": "",
  "appName": "Cobblemon Battle Intelligence"
}
```

- 키를 `server.properties`, 월드 저장 데이터, 데이터팩, 클라이언트 설정, 명령 블록에 저장하지 않는다.
- 키를 Git에 커밋하지 않는다.
- 설정 화면이나 명령어에서 전체 키를 다시 표시하지 않는다.
- 키 유효성 검사 결과만 `사용 가능`, `인증 실패`, `할당량 없음`으로 표시한다.
- 최초 기동은 비활성·빈 키·빈 모델의 안전한 기본 파일을 원자적으로 만든다.
- `modelsByDifficulty`는 필요할 때 `introductory`, `standard`, `advanced`, `boss`만 재정의하며 비어 있으면 공통 `model`을 사용한다.
- 게임 채팅에서 `/ai key <값>`처럼 키를 입력받는 명령은 제공하지 않는다. 채팅·콘솔 기록에 비밀이 남을 수 있기 때문이다.

### 20.2 운영 명령

키 값을 노출하지 않는 관리자 명령만 제공한다.

```text
/battleai status
/battleai test
/battleai enable
/battleai disable
/battleai reload
/battleai budget
/battleai circuit reset
```

- `status`: 제공자, 모델, 활성화, 대기 요청, 폴백률과 키 존재 여부만 표시
- `test`: 실제 전투 데이터 없이 최소 요청으로 연결 검사
- `reload`: 서버 전용 JSON 설정을 다시 읽음
- `budget`: 금일 호출량과 추정 비용 표시
- `circuit reset`: 장애로 열린 차단기를 운영자가 재설정

명령 권한은 운영자 레벨 또는 별도 권한 노드로 제한한다.

### 20.3 설정 검증과 적용 시점

- 서버 시작 시 스키마, 제한값, 제공자 어댑터와 키 존재 여부를 검사한다.
- 설정 오류가 있어도 서버 시작을 막지 않고 외부 AI만 비활성화한다.
- 리로드 시 진행 중인 판단 요청은 시작 당시 설정으로 완료하거나 폐기한다.
- 진행 중인 배틀은 Brain과 프롬프트 버전을 고정하고 다음 배틀부터 새 설정을 적용한다.
- 모델명은 코드에 특정 최신 모델로 고정하지 않고 운영자가 설정한다.

## 21. 외부 AI 운영 안정성

### 21.1 요청 스케줄러

모든 NPC가 외부 AI를 사용할 수 있으므로 각 배틀이 직접 HTTP 요청을 생성하지 않고 중앙 `AiRequestScheduler`를 거친다.

- 서버 전체 동시 요청 제한
- 배틀별 한 번에 하나의 활성 판단 요청
- 요청 우선순위: 턴 제한 임박 → 보스 → 일반 NPC
- 대기열 최대 길이와 최대 대기 시간
- 대기열에서 제한 시간을 넘길 것으로 예상되면 요청하지 않고 로컬 폴백
- 플레이어별 공정한 순환 배정으로 한 전투의 요청 독점 방지

10초 제한은 대기열 진입부터 계산한다. HTTP 요청을 시작한 뒤 추가로 10초를 주지 않는다.

### 21.2 회로 차단기

연속 인증 실패, 속도 제한, 서버 오류 또는 시간 초과가 일정 횟수를 넘으면 `CircuitBreaker`를 연다.

```text
CLOSED      정상 외부 호출
OPEN        외부 호출 중단, 즉시 로컬 폴백
HALF_OPEN   소수 시험 호출 후 복구 여부 판단
```

- 인증 실패는 자동 재시도를 반복하지 않는다.
- 속도 제한 응답은 제공자의 재시도 가능 시간을 존중한다.
- 일일 비용 또는 호출 예산을 넘으면 다음 초기화까지 `OPEN`으로 처리한다.
- 외부 장애 때문에 플레이어가 연승이나 보상을 잃지 않도록 Brain만 교체한다.

### 21.3 비용 정책

모든 NPC가 매 턴 외부 AI를 호출하면 비용과 대기 시간이 급격히 증가한다. 따라서 `모든 NPC가 외부 Brain을 사용한다`와 `모든 턴마다 API를 호출한다`를 구분한다.

- 모든 NPC의 Brain은 `HybridBattleBrain` 사용 가능
- 로컬 평가에서 최선 행동이 명백하면 외부 호출 생략
- 상위 후보 점수가 비슷하거나 전략 전환점이면 외부 호출
- 신입은 짧은 상태와 적은 후보, 보스는 더 풍부한 분석 자료 사용
- 동일한 공개 상태·후보·프로필·프롬프트 버전은 짧은 수명의 캐시 사용 가능
- 비용 예산 소진 후에도 같은 성격과 난도의 로컬 Brain으로 계속 진행

플레이어에게는 외부 호출 여부를 난도 차이로 노출하지 않는다. 장애나 예산 소진이 게임 규칙을 바꾸지 않고 판단 엔진만 교체해야 한다.

## 22. 프롬프트와 데이터 안전

플레이어가 지정할 수 있는 닉네임, 포켓몬 별명, 채팅, 책 내용, 표지판, NPC 대사는 외부 AI의 명령문에 삽입하지 않는다. 이런 문자열에 모델을 속이는 지시가 포함될 수 있다.

- 포켓몬은 번역된 표시명이 아니라 종족 ID로 전달
- 기술·도구·특성도 레지스트리 ID로 전달
- 플레이어는 임시 익명 ID로 표시
- 자유 채팅과 닉네임은 전송하지 않음
- 시스템 지시와 전투 상태를 구조적으로 분리
- 응답은 엄격한 JSON 스키마의 `action_id`만 실행에 사용
- 출력 길이 제한
- 서버가 제공하지 않은 행동 ID는 즉시 거부
- 제공자에 전송한 필드 목록과 보존 정책을 운영 문서에 명시

외부 AI가 반환한 설명 텍스트를 플레이어 채팅에 그대로 출력하지 않는다. 해설 기능은 서버가 허용한 태그와 전투 사실로 다시 구성한다.

## 23. 추가하면 재미있는 기능

### 23.1 전투 후 AI 해설

전투 종료 후 2~3개의 핵심 장면을 보여 준다.

- `상대가 먼저 행동해 구애스카프 가능성을 확정했습니다.`
- `교체하면 에이스가 안전하게 진입할 수 있어 희생을 선택했습니다.`
- `두 행동의 점수가 비슷해 트레이너의 공격적 성격을 반영했습니다.`

실시간 내부 정보는 공개하지 않고 전투가 끝난 뒤 이미 드러난 사실과 추론만 보여 준다. 플레이어가 AI에게 배울 수 있는 콘텐츠가 된다.

### 23.2 트레이너 스타일 학습

같은 도전 세션 안에서는 NPC가 플레이어의 반복 습관을 관측할 수 있다.

- 첫 턴마다 교체하는 경향
- 체력이 낮으면 항상 `Protect`하는 경향
- 특정 포켓몬을 지나치게 보존하는 경향
- 더블에서 한 슬롯에 집중 공격하는 경향

관측된 경기 안에서만 추론하며, 다음 플레이어의 정보를 공유하지 않는다. 장기 기억을 도입할 경우 별도 동의와 초기화 기능을 둔다.

### 23.3 보스의 시그니처 사고방식

보스마다 불법 보정이 아닌 고유한 판단 철학을 준다.

- 확률보다 안정적인 승리 경로를 고르는 보스
- 위험을 감수하고 빠른 KO를 노리는 보스
- 플레이어의 교체 습관을 적극적으로 읽는 보스
- 날씨나 트릭룸의 남은 턴을 완벽하게 관리하는 보스

보스전 재도전 시 파티만 바뀌는 것이 아니라 상대의 사고방식 자체가 다르게 느껴지게 한다.

### 23.4 추론 연출

AI의 원시 사고 과정은 공개하지 않고 확정된 전투 태그만 짧게 연출할 수 있다.

```text
트레이너가 상대의 속도 범위를 파악했다.
트레이너가 구애 도구를 의심하고 있다.
트레이너가 승리 경로를 발견했다.
```

이 연출은 설정으로 끌 수 있고, 실제 확률이나 미공개 정보는 보여 주지 않는다.

## 24. 최종 설계 결론

- 정확한 피해·속도·가설 추론은 로컬 `BattleInferenceEngine`이 담당한다.
- `BattleBrain`은 합법 행동 후보 중 전략적 선택을 담당한다.
- 외부 AI는 선택적 Brain 구현이며 서버의 필수 구성요소가 아니다.
- 모든 NPC가 외부 Brain을 사용할 수 있지만 호출 여부는 중앙 스케줄러와 하이브리드 정책이 제어한다.
- API 키는 서버 전용 `config/cobblemon-more-battle-content-better-ai/openrouter.json`에서 읽고 게임 채팅·월드·클라이언트 패킷에는 저장하지 않는다.
- 외부 장애, 예산 소진, 잘못된 응답은 항상 동일 규칙의 로컬 Brain으로 폴백한다.
- 트레이너의 개성은 정보 치팅이나 스탯 보정이 아니라 성격, 추론 정밀도, 탐색 깊이로 표현한다.

## 25. 호환성과 구현 검수 기준

### 25.1 관측 이벤트 경계

`BattleInferenceEngine`은 Cobblemon의 전체 전투 객체를 직접 받지 않는다. 별도 `BattleObservationCollector`가 플레이어에게도 관측 가능한 사건만 표준 이벤트로 변환한다.

```text
MoveRevealed
ItemRevealed
AbilityActivated
DamageObserved
OrderObserved
PokemonRevealed
FormChanged
FieldChanged
StatusChanged
```

추론기는 이 이벤트 스트림과 공개 규칙 데이터만 소비한다. 테스트에서는 의도적으로 미공개 기술·도구를 바꿔도 동일한 관측 이벤트라면 AI 판단이 같아야 한다. 이를 정보 누출 회귀 테스트로 둔다.

### 25.2 Cobblemon 호환 계층

Cobblemon 1.7.3 연동 코드는 공개 AI 타입과 분리된 `CobblemonBattleAdapter`에 모은다.

- 전투 상태 스냅샷 변환
- 합법 행동 후보 생성
- 피해 계산기 접근
- 행동 제출
- 전투 이벤트 수집
- 싱글·더블 능력 감지

지원하지 않는 커스텀 기술, 특성, 도구 또는 전투 기믹을 만나면 다음 원칙을 적용한다.

- 효과를 지어내지 않음
- 확정 추론을 하지 않고 `UNKNOWN_MECHANIC` 표시
- 규칙 프리셋과 Cobblemon 엔진이 합법으로 판정한 행동만 후보로 노출
- 기믹 후보에는 안정된 기믹 ID, 대상, 사용 가능 여부와 공개된 비용을 포함하되 Cobblemon 내부 객체는 노출하지 않음
- 예상 결과의 불확실성 페널티 적용
- 디버그 로그에 미지원 레지스트리 ID 기록
- 반복적으로 등장하는 미지원 효과는 데이터 어댑터로 추가 가능

메가진화·다이맥스·테라스탈을 이해한다는 것은 Brain이 기믹 허용 여부를 결정한다는 뜻이 아니다. 본체가 현재 규칙에 없는 기믹, 이미 사용한 기믹과 불가능한 중복을 후보에서 제외한다. Better AI는 남은 기믹 후보를 일반 기술·교체 후보와 함께 비교한다. 배틀타워·배틀팩토리에는 이를 위해 별도 콘텐츠 capability를 추가하지 않는다.

### 25.3 출시 전 필수 통과 조건

- AI 키 없이 서버와 모든 콘텐츠가 정상 실행됨
- 잘못된 키, 할당량 소진, 네트워크 단절 중에도 배틀 완료
- 외부 AI가 잘못된 행동 ID를 반환해도 불법 행동 실행 불가
- 같은 관측 정보에서 실제 미공개 세트만 바꿔도 AI 판단이 변하지 않음
- 싱글·더블 모두 10초 제한 후 로컬 폴백
- Better AI를 제거한 상태에서 `NONE`, `MEGA`, `DYNAMAX`, `TERA` 배틀이 합법성 오류나 턴 정지 없이 완료됨
- 서버 재시작 후 진행 세션과 Brain 버전이 안전하게 복구 또는 종료
- 콘텐츠의 보상·저장 처리는 AI 응답과 분리되어 중복 처리되지 않음
- 플레이어 입력 문자열이 외부 프롬프트 명령으로 해석되지 않음
- API 키가 로그, 크래시 리포트, 설정 출력과 네트워크 패킷에 노출되지 않음
- 자동 배틀에서 무한 교체·무한 방어·행동 없음 상태가 탐지되고 종료됨
- Better AI 제거 후 본체의 월드 데이터와 진행 중인 배틀이 안전하게 복구 또는 종료됨
## 공정 정보 스냅샷과 행동 후보 경계 (2026-08-13 기존 구현 확정, 이식 대상)

- Brain은 Cobblemon의 실제 전투 객체를 직접 받지 않는다. API가 제공하는 `BattleStateView`와 서버가 발급한 `BattleActionCandidate`만 받는다.
- 자기 포켓몬은 기술·특성·지닌 도구를 포함한 전체 정보를 제공한다.
- 상대의 기술·특성·지닌 도구는 전투 중 실제로 공개되어 누적 기록에 들어온 값만 제공한다. 후보 생성기가 상대 파티 원본을 읽어 채우지 않는다.
- 현재 필드, 최근 공개 사건과 추론 결과 역시 별도 누적 기록에서 전달한다. 아직 관측기가 수집하지 못한 값은 비어 있어야 하며 임의의 기본 효과를 가정하지 않는다.
- 현재 나온 상대 포켓몬의 종족·폼·레벨·HP·상태·랭크 변화는 화면에 공개되는 현재 상태로 갱신한다. 교체되어 들어간 포켓몬만 `activeSlot`을 가지며 이전 기록의 활성 자리는 해제한다.
- 코블몬 1.7.3 호환 계층은 싱글과 더블만 허용한다. 그 밖의 전투 형식이나 망가진 요청은 추측해 진행하지 않고 구분된 실패 상태를 반환한다.
- 가능한 기술 대상과 교체는 Cobblemon이 보낸 현재 요청에서 만들고, 각 응답의 `isValid`를 다시 통과한 것만 Brain 후보로 노출한다.
- 더블은 두 활성 자리의 후보를 완전 조합하되 같은 대기 포켓몬으로 동시에 교체하는 불가능한 조합을 제거한다. Brain이 고른 조합 ID는 원래 Cobblemon 응답 묶음으로만 되돌린다.
- 가방 도구, 현재 규칙에 없는 배틀 기믹, 이미 소모한 전투당 1회 기믹과 규칙상 중복되는 기믹은 행동 후보로 만들지 않는다. **합법성 제한은 본체 후보 생성기가 담당하고**, 합법 후보 사이의 전술적 가지치기와 순위 평가는 난도별 Brain이 담당한다.

## 10초 판단 조정과 안전 폴백 (2026-08-13 기존 구현 확정, 이식 대상)

- 각 판단은 컨텍스트의 마감 시각과 공용 최대 10초 중 더 짧은 시간만 기다린다.
- Brain이 예외를 내거나, 끝나지 않거나, 오래된 요청 ID·존재하지 않는 행동 ID·기한이 지난 응답을 반환하면 그 응답을 제출하지 않는다.
- Better AI 경로 실패 시 먼저 본체의 Cobblemon 기본 AI 기준선 어댑터로 위임한다. 기준선 위임도 실패한 경우에만 서버가 이미 검증해 발급한 후보 중 첫 후보를 즉시 선택한다. 첫 후보 선택은 전술 AI가 아니라 배틀 정지를 막는 비상 안전장치이며 원인을 별도 상태로 남긴다.
- 먼저 완료된 정상 응답 또는 시간 초과 중 하나만 최종 결과가 된다. 시간 초과 뒤 늦게 도착한 외부 응답은 결과를 바꾸지 못한다.
- Brain의 `decide` 호출 자체가 비동기 결과를 반환하기 전에 멈추는 잘못된 구현도 서버 호출 스레드와 시간 제한 스케줄러에서 분리한다.
- Better AI는 외부 API가 없어도 동작하는 `cobblemon_more_battle_content_better_ai:local` Brain을 항상 등록해야 한다. 본체는 애드온 유무와 관계없이 Cobblemon 기본 AI 기준선 어댑터를 보유한다. 첫 합법 후보 선택기는 두 경로가 모두 실패했을 때의 전투 정지 방지용 안전장치일 뿐이며 Better AI 구현 완료 기준이 아니다.
- 외부 API Brain은 선택 기능이며, 등록·호출 실패가 로컬 Brain 등록이나 배틀 안전장치를 막아서는 안 된다.

## OpenRouter 외부 모델 연결 (2026-08-13 기존 구현 확정, 이식 대상)

- 최초 외부 모델 연결은 개별 OpenAI·Anthropic·Google 어댑터가 아니라 OpenRouter 단일 API를 사용한다.
- 서버 전용 `config/cobblemon-more-battle-content-better-ai/openrouter.json`에서 `enabled`, `apiKey`, 기본 `model`을 읽는다.
- 기본 모델은 입문·일반·상급·보스 전 단계에 적용한다. `modelsByDifficulty`에 `introductory`, `standard`, `advanced`, `boss` 중 필요한 키만 적으면 해당 단계 모델만 재정의한다.
- 엔드포인트와 1~10,000ms 범위의 HTTP 제한시간도 JSON에서 관리한다. 기본 엔드포인트는 OpenRouter의 `/api/v1/chat/completions`다.
- API 키는 서버 전용 JSON에 평문으로 존재하므로 파일 접근 권한 자체가 보안 경계다. 키를 HTTP 본문, 프롬프트, 일반 로그, 진단 메시지와 클라이언트 패킷에 포함하지 않는다.
- 모델에는 공정 정보 상태, 난도·성격과 서버가 발급한 행동 후보만 전달한다. 응답은 JSON Schema의 `actionId` 한 필드로 제한하고 최종적으로 공용 행동 검증기를 다시 통과시킨다.
- Structured Output을 지원하지 않는 모델은 기본 설정에서 선택하지 않는다. `requireStructuredOutput`을 끌 수는 있지만 파싱·행동 ID 검증은 그대로 유지한다.
- 키나 모델이 비어 있거나 JSON이 깨졌거나 스키마·난도 키·제한시간이 잘못되면 서버 자체를 중단하지 않고 OpenRouter Brain만 사용할 수 없는 상태로 둔다. 잘못된 기존 파일은 자동으로 덮어쓰지 않는다.
- 외부 모델 장애, 인증·잔액·속도 제한, 제공자 장애, 잘못된 응답과 10초 초과는 공용 판단 조정기의 안전 폴백 대상이다.

## Cobblemon NPC 턴 실행 구조 (2026-08-13 기존 구현 확정, 이식 대상)

- Cobblemon 1.7.3 기본 `BattleAI.choose`는 더블 행동도 활성 슬롯마다 동기 호출하므로 공용 Brain을 직접 끼우지 않는다.
- 전용 `TrainerBattleActor`가 한 번의 선택 요청 전체를 받아 상태·후보를 한 번 만들고, 더블은 조합 후보 하나를 선택해 원래 Cobblemon 응답 두 개로 되돌린다.
- OpenRouter Brain과 Better AI 로컬 Brain의 판단은 같은 컨텍스트로 동시에 시작한다. 외부 판단이 정상이면 그것을 사용하고, 실패·잘못된 ID·시간 초과라면 이미 준비된 로컬 판단을 추가 대기 없이 사용한다.
- 두 Better AI Brain이 모두 실패했거나 Better AI가 설치되지 않았으면 본체가 Cobblemon 기본 AI 기준선 어댑터로 위임한다. 기준선 위임까지 실패했을 때만 서버가 발급한 첫 합법 후보를 비상 선택으로 사용한다. 준비 단계 자체가 깨진 경우에는 Cobblemon의 패스 처리로 안전하게 빠지고 운영 로그에 오류 종류를 남긴다.
- Brain 응답은 작업 스레드에서 기다리되 실제 `setActionResponses`는 Minecraft 서버 스레드에서만 호출한다.
- 같은 Cobblemon 요청이 중복 통지되어도 하나의 판단만 실행한다. 판단 중 새 요청으로 교체되거나 전투가 끝나면 오래된 결과를 제출하지 않는다.
- 전투 종료 시 실제 NPC 관점의 승패와 턴 수를 두 Brain 세션에 전달하고, 같은 세션을 두 번 닫지 않는다.

## 공용 PvE 실행 서비스와 공개 정보 관측기 (2026-08-13 기존 구현 확정, 이식 대상)

- 본체의 배틀 콘텐츠는 Cobblemon 내부 전투 객체를 직접 참조하지 않고 공용 `PveBattleService`에 프로젝트 소유 요청 DTO를 전달한다.
- 요청에는 고유 `requestId`, 양측 확정 엔트리, 룰 세트, 주·폴백 Brain ID, 난도, 성격과 정보 정책이 들어간다. 같은 ID·같은 내용의 재요청은 기존 시작 결과를 반환하고, 같은 ID에 다른 내용을 넣으면 충돌로 거부한다.
- 멱등성 비교용 엔트리 NBT는 요청 시점에 복사해 이후 호출자가 원본 태그를 바꿔도 기존 요청의 정체성이 변하지 않게 한다.
- 전투 시작은 Minecraft 서버 스레드에서만 허용한다. 오프라인, 이미 전투 중, Brain 미등록, 잘못된 팀, Cobblemon 거부와 내부 오류를 서로 다른 공개 상태로 반환한다.
- 종료 콜백은 프로젝트 소유 승패 DTO만 전달하고, 콘텐츠 콜백의 예외가 Cobblemon 전투 종료나 Brain 세션 정리를 깨뜨리지 않게 격리한다.
- 전투별 관측기는 Cobblemon의 공개 Showdown 메시지를 새로 추가된 부분만 읽는다. 상대 파티 원본의 미공개 기술·특성·도구는 읽지 않는다.
- 관측 대상은 양측 행동 순서, 교체·기절, 공개 HP 비율 변화, 상태, 날씨, 지형, 필드 효과, 사이드 조건과 공개된 기술·특성·도구다. 이번 단계에서는 사건 수를 임의로 잘라내지 않는다.
- 필드 효과의 남은 턴을 공개 정보만으로 확정할 수 없으면 임의 수치를 넣지 않고 `activeEffects`에 활성 여부만 기록한다.

## 소드·실드 배틀타워 AI 확장 프리셋 (기존 구현 참고자료, 현재 비활성)

- 소드·실드 원작 배틀타워 트레이너 테이블에는 트레이너별 성격·숙련도 값이 없다. 따라서 아래 값은 원작 데이터 복원이 아니라, 원작 공통 AI 경향을 전문 추론 Brain으로 강화하는 모드 고유 확장값이다.
- 기존 구현에서는 모든 값을 `data/cobblemon_battle_tower/battle_tower/sword_shield_ai/policy.json` 스키마 1에서 읽었다. 이 경로는 새 모드에 이식하지 않으며, 향후 콘텐츠가 같은 프리셋을 채택할 때 새 네임스페이스와 독립 스키마를 정한다.
- 정규전 난도는 랭크 1~3 `INTRODUCTORY`, 4~6 `STANDARD`, 7~11 `ADVANCED`다. 모든 승급전 리언과 마스터 10승 주기 리언은 랭크와 무관하게 `BOSS`를 사용한다.
- 기본 계산량은 입문 `가설 3/탐색 0/더블 슬롯 후보 3`, 일반 `6/0/5`, 상급 `10/1/8`, 보스 `16/2/12`다. 이 값은 볼 수 있는 정보가 아니라 유지하는 가설 수와 탐색 정밀도만 바꾼다.
- 성격은 `balanced`, `aggressive`, `defensive`, `tactical`, `risk_taker`, `setup`, `weather`, `trick_room`, `champion` 9개다. 각 프로필은 공격성·위험 감수·교체·전개·정보 선호의 0~1 가중치만 바꾼다.
- 비 테마는 클래스보다 `weather`, 저속·트릭룸 테마는 `trick_room`을 우선한다. 리언은 클래스와 테마보다 `champion`을 우선한다. 나머지는 트레이너 클래스별 명시적 대응표를 사용하며 알 수 없는 외부 클래스는 `balanced`로 안전하게 처리한다.
- 기존 주 Brain은 `cobblemon_battle_intelligence:openrouter`, 폴백은 `cobblemon_battle_tower:local`이었다. 새 Better AI에서는 각각 `cobblemon_more_battle_content_better_ai:openrouter`, `cobblemon_more_battle_content_better_ai:local`로 바꾼다. Better AI가 없거나 두 Brain이 모두 실패하면 본체의 Cobblemon 기본 AI 기준선 어댑터를 사용한다.
- 두 Brain은 동일한 난도·성격과 `FAIR_INFERENCE` 정보만 받는다. 외부 AI 사용 여부가 난도나 정보 공개 범위를 바꾸지 않는다.
- 알 수 없거나 새로 추가된 Showdown 메시지 하나의 파싱 실패가 전체 턴 판단을 막지 않도록 해당 메시지만 건너뛴다.
- Cobblemon 연동, 메시지 해석과 실제 행동 제출은 본체 내부 1.7.3 호환 계층에 남고 공개 서비스에는 노출하지 않는다.
