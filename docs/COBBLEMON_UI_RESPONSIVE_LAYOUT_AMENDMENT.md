| 적용 대상 | `cobblemon-ui-kit`, `more-cobblemon-contents`와 콘텐츠 모드 네 개(배틀타워·배틀팩토리·PvP·리그 챌린지) |

## 1. 배경

ui-kit은 처음부터 owo를 쓰지 않았다. 화면 모양은 ui-kit이 그리고, 입력·포커스·낭독은 바닐라 위젯이 맡는다. owo를 쓰면 얻을 수 있는 것은 배치 엔진 하나뿐이었고, 그 대가로 어댑터 안에서 낭독이 끊기고 비율 크기에 1px 반올림 오차가 생긴다.

ui-kit에도 배치 도구는 있었지만 단층 계산기(`UiStackLayout`, `UiFlowLayout`, `UiGridLayout`, `UiAnchorLayout`)뿐이었다. Hub와 탭들은 이것도 쓰지 않고 탭마다 `calculate(bounds)`에서 좌표를 손으로 계산했다. 그래서 반응형 배치를 ui-kit에 구조화하면 owo를 쓸 이유가 남지 않는다.

## 2. owo 비의존

- ui-kit과 MCC 모드 다섯 개는 owo를 코드·`fabric.mod.json`·빌드 파일 어디에서도 쓰거나 선언하면 안 된다(MUST NOT).
- owo는 Mega Showdown → Accessories → owo-lib로 이어지는 요구 때문에 개발 실행 환경에만 들어간다. 이 묶음(Mega Showdown, Architectury, Accessories, owo-lib)은 루트 `build.gradle.kts` 한곳에서 MCC 모드 다섯 개의 `modRuntimeOnly`로 넣는다(MUST). 배포 JAR에는 들어가지 않는다.
- `OwoIndependenceTest`(MCC 본체)가 여섯 모듈의 소스·메타데이터·빌드 파일을 검사한다.

## 3. 배치 트리

`UiLayoutContract.kt`의 배치 트리는 Minecraft 클래스 없이 정수 연산만 쓴다. 트리를 사각형 하나에 `solve`하면, 키가 있는 잎마다 사각형이 하나씩 나온다(`UiLayoutResult`). 같은 키가 두 번 나오면 실패한다.

### 3.1 노드

| 노드 | 하는 일 |
| --- | --- |
| `Leaf` | 이름 붙은 사각형. 키가 없으면 자리만 차지한다. 내용 크기로 쓸 선호 크기를 가진다 |
| `Linear`(`row`, `column`) | 자식을 한 방향으로 늘어놓는다. 간격·안쪽 여백·정렬(`UiJustify`)·나머지 처리(`UiRemainder`)를 가진다 |
| `Inset` | 네 변을 안으로 줄인다. 음수면 바깥으로 넓힌다. 최소 크기를 둘 수 있다 |
| `Align` | 크기를 정한 자식을 가운데·끝에 놓는다. `fit`은 공간에 맞게 줄이고, `pinStart`는 넘칠 때 시작 변을 넘지 않게 한다 |
| `Grid` | 열·행 트랙에 칸을 채운다. 행 우선과 열 우선을 고를 수 있다 |
| `Flow` | 자식을 선호 크기대로 왼쪽부터 놓고, 넘치면 다음 줄로 넘긴다 |
| `Layers` | 같은 사각형에 여러 자식을 겹친다(틀과 그 안의 내용) |
| `Responsive` | 받은 크기를 보고 트리를 새로 만든다. 크기 구간마다 구조가 바뀌는 배치에 쓴다 |

### 3.2 크기 규칙(`UiLength`)

| 규칙 | 뜻 |
| --- | --- |
| `Fixed(n)` | 정확히 n픽셀 |
| `Content` | 자식이 잰 크기. 격자 트랙이면 그 트랙에서 가장 큰 칸. 라벨 열을 가장 긴 라벨에 맞추면 모든 줄의 컨트롤이 같은 x에서 시작한다 |
| `Percent(p, min, max)` | 컨테이너 전체 크기(여백 포함)의 p%를 min..max로 자른 값 |
| `Weight(w, min, reserve)` | 크기가 정해진 형제가 남긴 공간의 w 비율. 공간이 모자라도 min 크기로는 그리지만, 뒤 형제를 밀지 않는다. reserve는 형제가 양보해서 남겨 줘야 하는 공간이다 |

가로지르는 방향은 `UiCross`로 정한다. 크기를 주지 않으면 앞뒤 여백 사이를 채우고, 크기를 주면 그 안에서 시작·가운데·끝에 놓는다.

### 3.3 정수 분배 규칙

- 가중치 몫은 내림한다. `UiRemainder.LAST`는 마지막 가중치 자식이 나머지 픽셀을 가져가 가장자리에 딱 맞게 끝난다. `NONE`은 모두 같은 몫을 받고 남는 픽셀은 끝에 비워 둔다(같은 폭 버튼 줄).
- 자리는 원래 크기로 넘기고, 그리는 크기만 최소값으로 늘린다. 그래서 공간이 모자라도 뒤쪽 자식의 자리가 바뀌지 않는다. 기존 손 계산과 같은 규칙이다.

### 3.4 보조 함수

`UiLayout.fittingCount`는 한 줄에 들어가는 항목 수를 센다(레일 탭, 목록 페이지). `UiLayout.spread`는 위치를 고르게 벌린다(리그 경로). `UiLayout.keys`와 `UiLayoutResult.list`는 `이름.0`, `이름.1`처럼 반복 키를 만들고 다시 읽는다. `CobblemonUiLayout.flow`와 `apply`는 이미 만든 바닐라 위젯을 배치 결과로 옮긴다.

### 3.5 사용 규칙

- 화면·카드·줄을 사각형으로 나누는 계산은 배치 트리로 한다(MUST). 탭의 `*Layout.calculate`는 결과를 담는 데이터 클래스를 그대로 두고, 안에서 트리를 푼다.
- 위젯 하나 안에서 글자·아이콘을 몇 픽셀 옮기는 그리기 좌표와, 스크롤로 움직이는 목록 줄의 좌표는 위젯이 직접 계산해도 된다(MAY).
- 글꼴로 재야 하는 크기(버튼 폭, 라벨 폭)는 호출부가 재서 `Fixed`나 잎의 선호 크기로 넘긴다. 순수 배치 함수(`footerLayout`, `choiceLayout`, `pagedListLayout`)는 잰 값만 받아 Minecraft 없이 테스트할 수 있어야 한다(MUST).

## 4. 옮긴 배치

| 모듈 | 옮긴 것 |
| --- | --- |
| ui-kit | 목록 줄 끝 동작 버튼, 갤러리의 줄바꿈 배치 |
| MCC 본체 | Hub 틀(창·헤더·잔액·닫기·레일·내용), 레일 탭, 헤더 배지, 대시보드, 상점과 장바구니, 카드 본문, 탭 틀(요약 띠·본문·푸터), 푸터, 선택 줄(한 줄·제목 위·압축), 같은 폭 버튼 줄, 목록 페이지와 넘기기, 초상 카드 격자 |
| 배틀타워 | 탭 배치, 설정 카드(설정·요약·규칙) |
| 배틀팩토리 | 탭 배치, 규칙 카드 세로 가운데 정렬, 안내 줄 |
| PvP | 탭 배치, 좌석, 설정 카드(압축·일반), 초대 목록, 선출 화면, 방 HUD, 관전자 격자, 라운지 나가기 버튼 |
| 리그 챌린지 | 탭 배치, 경로 노드 위치 |

MCC 전용 사각형 타입 `MccRect`는 없애고 ui-kit의 `UiRect`로 합쳤다. 옛 단층 계산기(`UiStackLayout`, `UiFlowLayout`, `UiGridLayout`, `UiAnchorLayout`, `UiLayoutItem`, `UiLayoutPlacement`, `UiAnchoredItem`)는 삭제했다. 저장소 안에서는 갤러리만 쓰고 있었다.

## 5. 검증

- 옛 손 계산을 각 모듈 테스트에 기준본으로 그대로 옮겨 두고, 새 배치와 사각형이 모두 같은지 넓은 크기 범위에서 비교한다. 옛 계산이 사각형을 만들지 못하는 크기(음수 폭)는 건너뛴다.
  - Hub 틀: 화면 1..1000 × 1..600, 탭 0·6·7·9개. 30만 가지 이상의 조합을 비교했다.
  - 탭 배치, 카드 본문, 열 나누기, 같은 폭 나누기, 선택 줄, 목록 페이지, 초상 격자: 사각형 1..760 × 1..480.
  - 푸터: 폭 1..760과 시작·끝 버튼 조합 16가지.
  - PvP HUD, 관전자 격자, 나가기 버튼, 목록 줄 동작 버튼.
- 1px 폭의 대시보드 기록 카드와 배틀타워 안내 카드처럼, 옛 계산이 잘린 크기를 기준으로 삼던 곳도 같은 결과가 나오게 맞췄다.
- 개발 클라이언트에서 DS 창·`tower_lobby`·427×240(GUI 배율 2)로 대시보드·상점(담기 3단계)·배틀타워(같은 파티 여섯 마리)·배틀팩토리·PvP(방 만들기)·리그 챌린지를 캡처했고, 전날 같은 조건의 캡처와 픽셀 단위로 비교했다. 창·레일·카드·버튼·글자 위치는 모두 같았다. 다른 픽셀은 실행마다 바뀌는 것뿐이었다.
  - 창 뒤로 보이는 월드
  - 무작위 오프라인 플레이어의 스킨과 이름
  - 전적 숫자
  - 초상 모델의 대기 동작 프레임
  - 전날 캡처 뒤에 짙게 바꾼 DS 스타일의 흐린 글자 색
