# Better AI 공개 팀 프리뷰·선출 가설 후속 결정

| 항목 | 값 |

| 주 독자 | 빡대리님과 Better AI·시설전·Cobblemon 호환 계층 구현 및 검증 담당자 |

## 1. 결정

- AI가 상대 선출을 직접 알 수 없는 규칙에서는 사람에게 공개된 팀 프리뷰만 사용해야 한다(MUST).
- 프리뷰의 포켓몬 식별자는 `0..5` 범위의 불투명 정수 슬롯 ID여야 한다(MUST). 호출자가 임의 문자열을 넣게 해서는 안 되며, 라이브 `BattlePokemon` UUID나 원본 객체를 노출해서는 안 된다(MUST NOT).
- 상대가 실제로 선출한 벤치, 기술, 특성, 도구, 성격, IV·EV 또는 정확한 실능을 프리뷰에서 읽어서는 안 된다(MUST NOT).
- 시설 런타임이 실제 선출을 알고 있더라도 같은 정보가 플레이어에게 공개되지 않았다면 AI에 전달해서는 안 된다(MUST NOT).
- 공개 프리뷰가 없는 전투는 숨은 실제 선출을 대신 읽어 네이티브 기준 상태를 만들지 않는다(MUST NOT). 네이티브 경로를 명시적으로 사용할 수 없다고 처리하고 비재귀 기본 선택으로 내려가야 한다(MUST).

## 2. 선출 세계 생성

- 첫 판단에서 싱글 6→3은 공개된 활성 포켓몬을 포함하는 가능한 3마리 조합을 전부 생성해야 한다(MUST). 한 마리가 공개됐다면 조합 수는 10이고, 아무도 공개되지 않았다면 20이다.
- 첫 판단에서 더블 6→4는 공개된 두 활성 포켓몬을 포함하는 가능한 4마리 조합을 전부 생성해야 한다(MUST). 두 마리가 서로 다른 프리뷰 슬롯으로 확정됐다면 조합 수는 6이다.
- 공개된 전투 포켓몬과 프리뷰 슬롯의 대응은 일대일이어야 한다(MUST). 두 전투 포켓몬을 같은 프리뷰 슬롯에 배정해서는 안 된다(MUST NOT).
- 입력 순서와 무관하게 같은 공개 상태는 같은 가설 ID, 순서와 확률을 만들어야 한다(MUST).
- 별도의 사용률 근거가 없는 초기 선출 조합은 균등 확률을 사용해야 한다(SHOULD). 근거가 추가되면 버전된 공개 정책으로만 확률을 바꿀 수 있다(MAY).
- 일관된 대응이나 선출 조합이 하나도 없으면 원인을 포함해 명시적으로 실패해야 한다(MUST). 실제 숨은 선출로 빈칸을 채워서는 안 된다(MUST NOT).
- 최초 리드 제시에서 생긴 턴 0 `SWITCHED`, `ABILITY_REVEALED`, `HELD_ITEM_REVEALED`, `FIELD_EFFECT_CHANGED` 사건은 초기 가설 생성에 사용할 수 있다(MAY). 포켓몬 사건의 주체는 현재 활성 포켓몬이어야 하고 `FIELD_EFFECT_CHANGED`에는 포켓몬 주체가 없어야 한다(MUST). 다른 종류의 사건이나 턴 1 이후 공개 사건이 하나라도 생긴 상태를 다시 초기 가설 생성기로 처리해서는 안 된다(MUST NOT).

## 3. 공개 모습과 실제 정체

- 일반적인 경우 공개 종·폼이 같은 프리뷰 슬롯을 대응 후보로 사용한다(MUST).
- `Illusion`처럼 공개 모습만으로 실제 정체를 확정할 수 없는 경우, 공개 정보와 룰로 가능한 모든 프리뷰 슬롯 대응을 별도 가설로 유지해야 한다(MUST).
- 공개된 모습과 라이브 UUID의 내부 연결을 읽어 정답 슬롯을 고르면 안 된다(MUST NOT).
- 정체가 공개된 뒤에는 모순되는 대응 가설을 제거하고 남은 확률을 다시 정규화해야 한다(MUST).

## 4. 이후 네이티브 조립 계약

- 각 선출 가설은 선택된 프리뷰 슬롯과 공개 포켓몬→프리뷰 슬롯 대응만 소유해야 한다(MUST).
- 미등장 벤치는 프리뷰 슬롯에서 만든 합성 전투 식별자를 사용해야 한다(MUST). 실제 비공개 `BattlePokemon` 식별자를 사용해서는 안 된다(MUST NOT).
- 기술·특성·도구·능력치 가설은 이 선출 가설과 별도 단계에서 생성한 뒤 전체 판단의 빔 예산 안에서 결합해야 한다(MUST). 모든 축의 데카르트곱을 무제한 생성해서는 안 된다(MUST NOT).
- 이후 공개 사건은 전투 내내 같은 대응 가설에 반영되어야 한다(MUST). 매 턴 공개 프리뷰부터 독립적으로 다시 뽑아 과거 공개 정보를 잃어서는 안 된다(MUST NOT).

## 5. 합격 조건

- 공개 프리뷰 DTO에 라이브 전투 포켓몬 식별자나 숨은 정확 수치가 존재하지 않아야 한다(MUST). `PUBLIC_SPECIES_RANGE` 라벨을 붙였더라도 최솟값과 최댓값이 같은 능력치 성분은 거부해야 한다(MUST).
- 6→3의 20/10 조합과 6→4의 6조합을 자동 테스트로 고정해야 한다(MUST).
- 중복 슬롯 대응, 불가능한 공개 정체와 초기 상태가 아닌 입력은 빈 가설이 아니라 명시적 오류로 끝나야 한다(MUST).
- 프리뷰 배열 순서를 뒤집어도 가설 목록이 동일해야 한다(MUST).
- `Illusion` 정체가 공개되기 전에는 가능한 복수 대응이 유지되고, 공개 후에는 모순 가설이 제거되는 제품 경로 테스트가 있어야 한다(MUST).

## 6. 거절한 대안

- **시설 내부의 실제 선출을 그대로 전달**: 사람보다 많은 정보를 사용하고 `Illusion`을 UUID로 관통하므로 거절한다.
- **보이는 종과 첫 번째 일치 슬롯만 연결**: 같은 종 중복과 `Illusion`에서 공개적으로 구분할 수 없는 세계를 임의로 제거하므로 거절한다.
- **매 턴 선출 조합을 새로 균등 생성**: 이미 공개된 교체·기절·정체 정보를 잃고 확률이 역행하므로 거절한다.
