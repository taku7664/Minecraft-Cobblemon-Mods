## 1. 결론

- Better AI의 전투 규칙 권위는 Cobblemon 서버에 실제 탑재된 Pokemon Showdown 엔진이어야 한다(MUST).
- 기술·교체·턴 종료·강제 교체·합법 행동·특성·도구·필드·날씨·주요 기믹의 상태 전이를 Kotlin에서 다시 구현해서는 안 된다(MUST NOT).
- Better AI는 공개 정보와 §3의 난이도 제한 추론 근거로 상대 가설을 만들고, 탐색할 가설·행동·깊이·표본을 제한하고, 네이티브 결과를 평가하는 책임을 가진다(MUST).
- 제품 런타임은 실제 배틀과 분리된 소수의 Graal 컨텍스트를 사용해야 한다(MUST). AI 탐색을 라이브 배틀 컨텍스트에서 실행해서는 안 된다(MUST NOT).
- 각 분기는 Showdown `Battle.toJSON()` 상태를 `Battle.fromJSON()`으로 복제한 뒤 합동 행동을 실행해야 한다(MUST).
- 싱글과 더블은 같은 네이티브 실행 계약을 사용해야 한다(MUST). 더블에서는 두 활성 슬롯의 합동 행동, 대상, 리다이렉션과 강제 교체를 한 라운드 단위로 실행해야 한다(MUST).
- 싱글은 공개 프리뷰의 크기 안에서 1명부터 전원까지 어떤 선출 크기도 허용해야 한다(MUST). 3선출이나 6대6은 이 일반 규칙의 사례이지 별도 하드코딩 대상이 아니다(MUST NOT).

### 1.1 기존 수제 투영기의 종료 규칙

- `PublicSingleTurnProjector`와 `LocalSwitchStateProjector`는 2026-09-24부터 새 전투 규칙을 추가하지 않는 동결된 이행 코드다(MUST NOT).
- 네이티브 경로가 아래 합격표를 전부 통과하기 전에는 교체 완료를 선언해서는 안 된다(MUST NOT).
- 네이티브 경로가 활성화된 뒤 규칙 세대 불일치나 실행 실패가 발생하면 해당 네이티브 판단을 명시적으로 실패 처리해야 한다(MUST). 같은 판단을 구형 수제 투영기로 조용히 재실행해서는 안 된다(MUST NOT).
- 아래 합격표가 전부 통과한 릴리스에서 수제 상태 전이 실행 경로를 제거해야 한다(MUST). 제거 뒤 같은 역할의 두 번째 자체 전투 엔진을 만들지 않는다(MUST NOT).

## 2. 소유권과 데이터 흐름

```text
BattleDecisionContext + 난이도 제한 추론 슬롯
        ↓
NativeHypothesisCompiler
        ↓ 난이도별 제한된 상대 가설
공개 DTO + 정규화된 가설로 만든 Native Showdown 기준 상태
        ↓ Battle.toJSON()/fromJSON()
Native Showdown branch snapshot
        ↓ 합동 행동 + 공통 난수 표본
Native turn outcomes
        ↓
상태 평가 → 재귀 탐색 → 후보 점수 → 가중 선택
```

### 2.1 공개 정보 경계

- 자기 팀은 자기 요청에 공개된 실제 기술·특성·도구·수치를 사용할 수 있다(MAY).
- 상대 팀 가설은 종·폼·레벨, 공개된 기술·특성·도구·타입·랭크·상태, 공개 행동 순서와 공개 피해량을 기본 근거로 사용해야 한다(MUST).
- 난이도 정책이 허용한 경우에만 추론 정규화 경계가 상대의 실제 기술 ID와 공격기·변화기 개수를 제한적으로 읽을 수 있다(MAY). 이 예외는 §3에 명시한 상급·보스의 숨은 자속기와 슬롯 모양, 보스의 순수 랭크업기에만 적용한다(MUST).
- 제한된 숨은 기술 근거는 `DIFFICULTY_SET_READ` 출처로 표시하고 네 개의 추론 슬롯으로 정규화해야 한다(MUST). 실제 전체 세트나 원본 배틀 객체를 네이티브 실행기로 넘겨서는 안 된다(MUST NOT).
- Cobblemon 호환 계층은 상급·보스 정규화에 필요한 실제 기술 ID만 추출할 수 있다(MAY). 원본 `BattlePokemon`이나 그 밖의 필드는 추론 정규화 경계 뒤로 넘겨서는 안 된다(MUST NOT).
- 실제 IV·EV·성격·도구·특성, 비공개 요청 또는 라이브 Showdown 스냅샷을 읽어 상대 가설을 채워서는 안 된다(MUST NOT).
- 최초 네이티브 기준 상태는 `BattleDecisionContext`의 공개 DTO와 정규화가 끝난 상대 가설만으로 새 샌드박스에 구성해야 한다(MUST). 라이브 배틀 스냅샷을 복제한 뒤 숨은 값을 지우는 방식은 금지한다(MUST NOT).
- `Battle.toJSON()/fromJSON()` 분기 복제는 위 공개 기준 상태가 완성된 뒤에만 사용해야 한다(MUST).
- Illusion 등 공개된 모습이 실제 종과 다르면 AI 가설도 공개된 모습을 기준으로 해야 한다(MUST).
- 숨은 기술을 읽지 않는 난이도에서는 숨은 상대 세트만 바꾼 쌍둥이 전투의 입력, 가설, 네이티브 요청과 선택 분포가 같아야 한다(MUST).
- 상급·보스에서는 §3이 허용한 기술 정보만 가설을 바꿀 수 있다(MAY). 실제 IV·EV·성격·도구·특성이나 선택되지 않은 기술의 내부 순서는 여전히 결과를 바꾸지 않아야 한다(MUST).

### 2.2 규칙 세대

- 샌드박스는 서버가 실제 사용하는 패치 완료 Showdown 파일과 같은 런타임 등록 원문을 실행해야 한다(MUST).
- 함수가 포함된 기술·특성·도구·스크립트를 JSON 완성 객체로 복사해서는 안 된다(MUST NOT). 콜백을 보존하는 원문 또는 동등한 공급자 계약을 사용해야 한다(MUST).
- 엔진 파일과 런타임 등록의 지문을 하나의 규칙 세대로 관리해야 한다(MUST).
- 데이터팩 재적용 때 새 규칙 세대를 완전히 준비한 뒤 원자적으로 교체해야 한다(MUST). 진행 중인 이전 세대 작업은 끝까지 같은 세대를 사용해야 한다(MUST).
- 지문이나 지원 공급자가 맞지 않으면 네이티브 투영을 비활성화하고 원인을 기록해야 한다(MUST).

## 3. 난이도와 상대 가설

| 난이도 | 최대 완결 깊이 | 포켓몬당 가설 상한 | 상대 기술 가정 |
|---|---:|---:|---|
| 입문 | 1 | 3 | 공개 확정 기술과 최소 공격 가설만 사용한다. |
| 표준 | 2 | 6 | 공개 기술, 예상 자속기 1개와 제한된 서브웨폰 가설을 사용한다. |
| 상급 | 2 | 10 | 실제 채용 자속기 중 추론 공격 점수가 가장 높은 것 최대 1개와 실제 공격기·변화기 개수의 슬롯 모양을 읽고, 남은 공격 슬롯은 서브웨폰 우선·자속기 보충 가설로 채운다. |
| 보스 | 3 | 16 | 실제 채용 자속기 중 추론 공격 점수가 높은 것 0~2개, 실제 채용한 순수 랭크업기 최대 1개, 변화기 수만큼의 그룹 가설을 사용하고, 남은 공격 슬롯은 서브웨폰 우선·자속기 보충 가설로 채운다. |

- 표의 값은 최대치다. 마감 시간, 공개 근거와 합법 조합이 더 작은 집합을 요구하면 줄일 수 있다(MAY).
- 표의 `가설` 하나는 상대 포켓몬 한 마리의 **완결 세트 세계**다. 네 기술 슬롯 조합, 공개 근거로 가능한 특성·도구, 성격·EV의 이산 범위, 룰상 가능한 메가·테라·다이맥스 형태를 포함하며 네 개 기술 슬롯과 같은 단위가 아니다(MUST).
- 각 완결 세트 가설은 정규화된 사후확률을 가져야 한다(MUST). 공개 행동 순서·피해·도구·폼 사건이 생기면 모순 가설을 제거하고 남은 확률의 합을 다시 1로 정규화해야 한다(MUST).
- 초기 사전확률, 공개 사건별 우도와 상한 초과 시 보존 순서는 버전된 단일 정책에서 관리해야 한다(MUST). 같은 규칙 세대·공개 DTO·정규화 슬롯에는 같은 가설 집합과 확률을 만들어야 한다(MUST). 상한으로 가설을 버린 뒤 남은 확률을 다시 1로 정규화하고, 남은 가설이 없으면 판단을 명시적으로 실패해야 한다(MUST).
- 표의 상한은 포켓몬별 완결 세트 가설 수다. 여러 상대 포켓몬의 가설을 조합할 때는 전수 데카르트곱을 만들지 않고, 결합 사후확률이 높은 순서와 결정적 동점 규칙으로 빔을 구성해 판단 전체의 별도 노드 예산 안에서 잘라야 한다(MUST).
- 같은 공개 결과를 만들고 이후 합법 행동·상태 전이도 같은 가설은 하나로 병합할 수 있다(MAY). 서로 다른 기믹 가능성이나 수치 범위를 단지 현재 점수가 비슷하다는 이유로 병합해서는 안 된다(MUST NOT).
- 기술 슬롯은 `이름 - 그룹 - 추측/예상/확정`을 보존해야 한다(MUST).
- 공개된 기술은 같은 논리 슬롯을 `확정`으로 갱신해야 한다(MUST). 종·폼·공개 타입이 바뀌어 슬롯 의미가 달라지면 남은 가설을 다시 정규화해야 한다(MUST).
- `추측` 변화기는 임의의 실제 기술 하나로 꾸며 네이티브 깊이를 타게 해서는 안 된다(MUST NOT). 구체적인 기술명이 없는 `추측` 슬롯은 도발을 포함한 어떤 행동에도 직접 점수를 주지 않고, 공개 기술을 같은 그룹 슬롯에 확정하기 위한 자리와 진단 정보로만 사용해야 한다(MUST). 이미 도발 상태인 경우도 이 슬롯에서 생기는 도발 점수는 0이다(MUST).
- `예상` 또는 `확정` 기술만 네이티브 가설 세트의 실제 기술이 될 수 있다(MUST).
- 한 아군 행동에 대한 구체 상대 응답을 상대에게 유리한 순서로 정렬했을 때 1위가 `예상` 기술이면 신뢰 보정을 하지 않는다(MUST). 2위 이하 `예상` 응답은 같은 아군 행동의 무응답 기준점에서 달라진 효과량에만 `0.8`을 곱해야 한다(MUST). 최종 점수 자체에 `0.8`을 곱해서는 안 된다(MUST NOT).
- 더블의 합성 응답에서는 `예상` 기술 자리만 `unknown`으로 바꾼 합성 응답을 무응답 기준점으로 사용하고, 함께 있는 `확정` 기술의 효과는 보정하지 않아야 한다(MUST). 일부 슬롯이 `unknown`인 합성 응답은 구체 상대 응답의 1위 판정에서 제외해야 한다(MUST).
- 자속기는 타입별 의무 슬롯이 아니다(MUST NOT). 무자속·단일 자속·복수 자속 가설은 공개 기술과 합법 풀에 따라 함께 존재할 수 있어야 한다(MUST).
- 테라스탈 이후의 공개 포켓몬 상태는 `현재 방어 타입`, `테라 전부터 유지되는 기본 자속 타입`, `활성 테라 타입`을 서로 다른 값으로 보존해야 한다(MUST). 상대 기술 그룹과 공격 기대값은 기본 자속과 활성 테라 타입을 사용하고, 피격 상성은 현재 방어 타입을 사용해야 한다(MUST).
- 스텔라 테라는 현재 방어 타입을 스텔라로 교체하지 않는다(MUST NOT). 공개 테라 정체성은 `stellar`로 보존하되 방어 타입과 기본 자속 타입은 테라 전 타입을 유지해야 한다(MUST). 타입별 최초 공격 부스트 소모와 테라파고스-스텔라의 반복 부스트는 활성 테라 타입만으로 추측하지 않고 네이티브 상태에서 별도로 보존해야 한다(MUST).
- 추론 공격 점수는 원시 위력만 비교해서는 안 된다(MUST NOT). 명중률, 자속, 공격·특공 적합도, 우선도, 확률 부가효과, 더블 광역 가치와 공개 비용을 함께 반영해야 한다(MUST).

중간 턴 조정 primitive는 공개 `MOVE_USED`·직접 `SWITCHED`·`TERA_TYPE_REVEALED`를 네이티브 요청 행동에 대응시키며, 더블은 이벤트 나열 순서가 아니라 행동 슬롯별 합성 행동으로 대응시킨다. 피벗 기술 뒤 같은 슬롯의 교체는 직접 교체로 오인하지 않고 원래 기술 행동을 유지한다. 행동 전에 쓰러진 경우처럼 그 슬롯의 행동이 공개되지 않았다면 임의 행동을 만들거나 한 후보로 축소하지 않고 가능한 요청 행동을 모두 남긴다. 이동 요청에서 이미 다른 포켓몬의 기술이 공개된 뒤 나온 교체 사건은 직전의 자발적 교체 명령 근거로 삼지 않고 피벗·밀쳐내기·기절 후 교체 등 다음 요청의 근거로 남겨 둔다. 세션 조정기는 공개 사건 연속성과 규칙 지문을 먼저 검증하고, 직전에 실제 선택한 아군 행동과 공개 근거에 맞는 상대 행동을 각 보존 루트에 실행한다. 실행 결과가 현재 공개 보드와 모순되는 가설·난수 입자는 제거하고 확률을 재정규화한다. 상대 행동이 공개되지 않아 서로 다른 후속 스냅샷이 모두 가능하면 어느 하나를 고르지 않고 별도 계보로 보존한다. 조정된 루트는 `LocalTacticalBrain`의 다음 판단 검색과 권위 점수 선택에 연결됐으며, 합법 행동이 하나뿐인 요청도 조정을 건너뛰지 않는다. 조정·검색 실패는 수제 투영기로 돌아가지 않고 상위 fallback으로 전달한다. 공개 기술 장부는 관측된 기술을 같은 논리 슬롯에 확정하고, 타입 변화 뒤 미공개 슬롯만 새 타입 기준으로 재구성한 뒤 진행 중인 네이티브 세트에 재결합한다.

공개 도구 사건도 같은 제품 세션 조정 경로에 들어간다. 실제 번들 Showdown에서 독타입 포켓몬의 먹다남은음식과 검은진흙이 같은 턴 종료 HP를 만들도록 한 두 세계를 동시에 보존한 뒤, 공개 `HELD_ITEM_REVEALED` 값과 모순되는 세계만 제거하고 남은 확률을 1로 재정규화한다. 공개 전에는 두 도구 세계를 모두 유지하고 관찰 상태의 도구를 `null`로 남기며, 공개 뒤에는 먹다남은음식과 검은진흙 각각의 실제 Showdown 턴 종료 로그·네이티브 세트·공개 상태가 같은 도구를 가리키는 양방향 제품 테스트를 통과했다. 가설별 내부 네이티브 세트가 도구를 갖는 것은 그 세계의 전이를 실행하기 위한 값이지 공개 확정 사실이 아니다.

진행 중인 네이티브 Showdown 세션도 같은 논리 슬롯 장부를 따른다. 관측 턴에 처음 공개된 기술은 그 행동을 재생하기 전에 기존 예상·추측 슬롯과 네이티브 세트에 동시에 결합하고, 테라 등으로 공개 타입이 바뀐 뒤 새로 선택된 미공개 예상 슬롯은 관측 턴이 완료된 뒤에만 재결합한다. HP·랭크·필드·권위 난수·PP와 기존 휘발 상태는 원본 스냅샷에서 보존한다. 기술 변경 뒤 `DisableMove` 콜백과 요청 합법성은 별도 복제 전투에서 다시 계산해 원본 난수를 소비하지 않으며, 구애 고정 요청과 이 상태 불변성을 실제 번들 Showdown으로 검증했다. 이미 사용해 과거 상태에서 참조 중인 기술을 삭제하거나, Transform·Mimic처럼 원본과 현재 기술 배열이 다른 스냅샷을 덮어쓰는 재결합은 실행하지 않는다. 수정 전 `OBSERVED_ACTION_MISMATCH`로 실패하던 실제 번들 Showdown 제품 세션에서 예상 `growl`을 공개 `protect`로 바꾸어 해당 턴을 재생했고, 공개 테라 불꽃 타입 뒤에 확정 `psychic`과 소모 PP는 유지하면서 나머지 예상 기술만 `flamethrower`로 재구성하는 후속 루트를 검증했다.

다단계 요청 중 단일 강제 교체, 아군 피벗 뒤 지연 상대 행동, 상대 피벗 뒤 중간 AI 판단 없이 상대 교체와 지연 아군 행동을 재생하는 흐름을 실제 번들 Showdown 경로에서 검증했다. 교체 요청 때문에 아직 실행되지 않은 제출 행동은 세계별로 보존하고, 나중에 나타난 공개 증거와 먼저 대조한 뒤 현재 `WAIT` 요청을 처리한다. 같은 스냅샷이라도 지연 행동이 다르면 세계를 합치지 않으며, 소비한 지연 행동은 후속 `WAIT`가 계속되어도 다시 보존하지 않는다. 자동 재생은 아군 전체 요청이 `WAIT`일 때만 허용하며 아군 강제 교체 선택을 건너뛴 입력에서는 교체를 추측하지 않는다. 더블에서는 한 슬롯 강제 교체의 `switch + pass`, 양쪽 동시 부분 교체, 한쪽 두 슬롯 동시 교체를 제품 세션 경로에서 검증했다. 싱글에서는 스텔스록을 실제로 설치한 뒤 저체력 4배 약점 교체 포켓몬이 진입 즉시 기절하고 다음 강제 교체까지 중간 AI 판단 없이 연쇄 재생되는 경로를 검증했다.

더블 공개 행동 대응은 `MOVE_USED.targetPokemonIds`를 네이티브 선택 대상에 맞춰 같은 기술의 잘못된 대상 분기를 제거한다. 또한 Showdown에서 테라 행동이 일반 기술보다 먼저 실행되는 순서를 근거로, 공개 테라 사건이 없는 슬롯의 테라 명령 가설은 그 슬롯이 기술을 사용하기 전에 쓰러졌더라도 제거한다.

## 4. 탐색·확률·캐시 계약

- 한 깊이는 양쪽 트레이너가 제출하는 한 라운드의 합동 행동과 턴 종료를 소비해야 한다(MUST).
- 같은 노드의 후보들은 같은 난수 표본 집합을 사용해야 한다(MUST). 후보마다 유리한 난수를 따로 뽑아서는 안 된다(MUST NOT).
- 난수 표본은 전투 ID, 실제 턴, 가설 ID, 노드 지문과 표본 번호로부터 결정적으로 만들 수 있다(MAY).
- 풀죽음·혼란·화상·부가 랭크 변화처럼 확률적인 결과는 네이티브 분기의 확률과 효용으로 집계해야 한다(MUST). 단순히 부가효과 점수를 명목 확률로 곱한 값이 실제 상태 전이를 대신해서는 안 된다(MUST NOT).
- 전이 캐시 키에는 규칙 세대, 네이티브 스냅샷 지문, 가설, 양쪽 합동 행동과 난수 표본이 들어가야 하며 값 캐시에는 남은 깊이도 들어가야 한다(MUST).
- 공개 정보 갱신, 규칙 세대 변경 또는 가설 변경 뒤 이전 캐시를 재사용해서는 안 된다(MUST NOT).
- 가지치기는 `현재까지 확정된 값 + 남은 깊이에서 가능한 최대 효용 변화`로 계산한 안전한 상한이 이미 확보한 하한보다 낮을 때만 결과를 버릴 수 있다(MUST). 단순 점수 차이나 “말이 안 되는 수”라는 휴리스틱만으로 완결 가능한 역전 분기를 버려서는 안 된다(MUST NOT).
- 시간 초과 시 마지막으로 **모든 루트 후보가 완결된 깊이**의 결과만 반환해야 한다(MUST). 일부 후보만 더 깊게 계산한 결과를 섞어서는 안 된다(MUST NOT).
- 최종 선택은 기존의 상위 후보 가중 무작위 계약을 유지한다(SHOULD). 네이티브 기대 점수 순위를 만들기 전의 후보를 임의 선택해서는 안 된다(MUST NOT).

구현 증거(2026-09-25): 네이티브 반복 심화가 깊이별 전체 루트 완료 결과를 보존하고, 상대 완결 세계 집계기는 모든 보존 세계가 완료한 공통 깊이의 동일한 제품 행동 집합만 `세계 사후확률 × 행동 효용`으로 합산한다. 어느 한 세계라도 실행 실패·완결 깊이 0·행동 누락이면 그 세계를 버리고 남은 확률을 재정규화하지 않고 판단 전체를 명시적으로 실패시킨다. 하나의 결정적 노드 예산도 전체 세계에 나눠 사용한다. 제품 판단 평가기는 초기 세계 계획 또는 공개 결과로 조정한 보존 세계와 이 집계를 연결하고, 각 세계의 루트 효용도 같은 사후확률로 합산해 행동 후 효용에서 먼저 뺀 뒤 그 변화량을 기존 선택 점수 단위에 맞춰 `100`배로 변환한다. 따라서 남은 포켓몬 수처럼 모든 행동에 공통인 절대 보드값이 regret 폭을 왜곡하지 않으며, 수제 상태 전이 점수나 `LocalRootDecisionPolicy`도 재적용하지 않는다. 계획·조정·검색 실패와 마감 전 완결 깊이 없음은 빈 순위로 숨기지 않고 서로 구분된 실패 상태로 반환하며, 시간 초과 전에 모든 루트가 완결된 마지막 공통 깊이는 부분 결과로 보존한다. 제품 `LocalTacticalBrain`은 초기와 후속 판단 모두 이 순위를 최종 가중 선택기에 직접 전달하고, 수제 switch/setup 결과 메타데이터가 네이티브 후보를 다시 배제하지 않도록 권위 점수 모드를 사용한다. 다만 안전 상한 가지치기와 최종 분포 검증은 남았으므로 INF-13~14를 완료하지 않는다.

전이 캐시는 깊이와 무관한 `규칙 세대 + 가설 + 난수 표본 + 부모 스냅샷 + 양쪽 합동 행동`으로 키를 만들고, 반복 심화가 같은 분기를 다시 요구하면 Showdown을 재실행하거나 노드 예산을 다시 소비하지 않는다. 상태 값 캐시는 여기에 남은 깊이를 더해 서로 다른 합동 행동이 같은 네이티브 스냅샷에 합류한 경우 같은 깊이의 하위 값을 한 번만 계산한다. 두 캐시는 한 `NativeRecursiveSearch` 인스턴스에만 존재하므로 공개 상태가 갱신되는 다음 판단, 다른 규칙 세대, 다른 가설 또는 다른 난수 표본으로 넘어가면 구조적으로 공유되지 않는다. 제품이 사용하는 네이티브 검색 코어에서 반복 심화 전이 재사용, 합류 상태 값 재사용, 깊이별 값 분리와 캐시 적중의 노드 예산 비소비를 회귀 테스트로 검증했다.

Showdown이 로그에 넣는 벽시계 `|t:|` 값은 분기 스냅샷에서 `|t:|0`으로 정규화한다. 같은 루트·양쪽 선택·PRNG를 재실행했을 때 상태뿐 아니라 전체 스냅샷 JSON도 같음을 검증했다. 이 결정적 입력과 위의 의사결정 내부 전이·값 재사용을 함께 INF-12의 캐시 계약으로 사용한다.

### 4.1 Brain 소유권

- 네이티브 상대 가설, 재귀 탐색, 상태 효용, 후보 순위와 가중 선택은 Better AI **로컬 Brain 내부**에서만 수행해야 한다(MUST).
- 공통 계산기는 공개 사실만 공급해야 하며 네이티브 효용·순위·추천 행동을 만들거나 Router 요청에 전달해서는 안 된다(MUST NOT).
- OpenRouter Brain은 전체 합법 후보와 공개 사실을 받아 독립적으로 최종 행동을 선택해야 한다(MUST). 로컬 네이티브 결과가 Router의 행동을 교체·제한·재정렬해서는 안 된다(MUST NOT).

## 8. 완료 증거

- 각 표 행에는 실패하는 회귀 테스트를 먼저 추가해야 한다(MUST).
- 각 코어 규칙은 Better AI 제품 어댑터 결과와 같은 Cobblemon/Mega Showdown 엔진의 독립 oracle 결과를 비교해야 한다(MUST).
- 확률 규칙은 강제 난수 또는 완전한 결과 열거로 확률 질량 합이 1인지 확인해야 한다(MUST). 소수의 우연한 실전 승패만으로 통과 처리해서는 안 된다(MUST NOT).
- 싱글은 프리뷰 안의 1명부터 전원까지 모든 선출 크기를 회귀 검증하고, 더블 4선출은 양쪽에 동일한 완성 선출 팀을 넣고 사이드를 바꾼 시나리오를 실행해야 한다(MUST). 싱글 팀과 더블 팀이 서로 같은 엔트리일 필요는 없다.
- 빌드와 테스트 통과는 정적 증거다. 서버 배포, 실제 전투 실행, 타임아웃·메모리·동시 배틀 안전성은 별도 런타임 증거로 보고해야 한다(MUST).
- 모든 `OPEN`이 제품 경로에서 `PASS`가 되고 수제 상태 전이 실행 경로가 제거되기 전에는 이 리팩터링을 완료로 표시해서는 안 된다(MUST NOT).

- 라이브 Graal 컨텍스트 안에서 AI 분기를 실행하는 방식은 실제 배틀 처리 지연과 동시 진입 위험 때문에 채택하지 않았다.
- Node 사이드카를 제품 필수 런타임으로 만드는 방식은 별도 설치·프로세스 수명·IPC 운영 부담 때문에 채택하지 않았다. Node는 독립 테스트 oracle로만 사용할 수 있다(MAY).
- 라이브 상대 배틀을 통째로 복제한 뒤 숨은 필드를 지우는 방식은 제거 누락을 증명하기 어려워 채택하지 않았다.
- 기술·특성별 예외를 Kotlin 투영기에 계속 추가하는 방식은 실제 엔진과 두 번째 규칙 구현을 영구히 동기화해야 하므로 채택하지 않았다.
- 런타임 등록 객체를 JSON으로 복사하는 방식은 JavaScript 함수가 소실되므로 채택하지 않았다.
- 공개 피해 뒤 HP 숫자만 네이티브 스냅샷에 덮어쓰는 방식은 `lastDamage`·`attackedBy`·반동·드레인·피해 임계 발동처럼 같은 피해에 의존하는 내부 상태를 표본의 옛 값으로 남기므로 채택하지 않았다. 관측 난수로 해당 턴 전체를 Showdown에서 다시 실행해야 한다(MUST).
- 피해 난수 장부를 보존 스냅샷에 넣는 방식은 같은 루트·행동의 JSON 동일성과 전이 캐시 지문을 오염시키므로 채택하지 않았다. 이 장부는 공개 관측을 조정하는 반환 프레임에서만 소비해야 한다(MUST).
