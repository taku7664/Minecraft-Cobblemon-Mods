# Cobblemon Battle UI 선택·연출·기록 분리 결정

| 항목 | 값 |
| --- | --- |
| Status | `shared` |
| Effective | 2026-09-25 |
| Depends on | `COBBLEMON_UI_TOOLKIT_AND_RUNTIME_EVIDENCE_AMENDMENT.md` |
| Updates | `cobblemon-battle-ui`의 상시 `BattleLogWidget` 표시 방식 |
| 적용 대상 | `cobblemon-battle-ui` 클라이언트 |
| 주 독자 | Better Battle UI 구현자와 시각 검수자 |

## 1. 목표

전투 화면은 사용자가 명령을 고르는 시간과 결과 연출을 보는 시간을 분리한다(MUST). 지금처럼 실시간 로그를 항상 한쪽에 띄우지 않는다(MUST NOT).

- **선택 단계:** 포켓몬 챔피언스식 행동 메뉴를 표시한다.
- **연출 단계:** 행동 메뉴를 숨기고 화면 하단의 반투명 내레이션 바에 현재 연출과 맞는 메시지만 표시한다.
- **기록 열람:** 전체 전투 기록은 별도 아이콘·키·화면으로 연다.

이 변경은 클라이언트 UI 전용이어야 하며 수정되지 않은 Cobblemon 서버와 호환돼야 한다(MUST).

## 2. 현재 근거와 문제

- `BattleInfoRenderer`는 기능이 켜진 동안 `BattleLogWidget`을 HUD 프레임마다 렌더한다.
- `BattleLog.LogEntry`는 턴, 종류, 메시지, 키와 시각을 저장하지만 아군·상대·시스템 출처를 구조적으로 저장하지 않는다.
- `BattleGuiNavigationMixin`은 현재 `BattleActionSelection`과 실제 `BattleOptionTile` 목록을 읽을 수 있다.
- 현재 오른쪽 아래 세로 명령 배치와 마우스·키보드 통합 포커스는 이미 구현돼 있다.

따라서 새 명령 UI는 Cobblemon이 만든 실제 선택지를 재사용할 수 있으며, 로그 문자열을 화면 위치로 추측할 필요가 없다.

## 3. 상태 모델

클라이언트 표시는 최소한 다음 상태를 구분해야 한다(MUST).

```text
COMMAND_GENERAL
COMMAND_MOVE
COMMAND_TARGET
COMMAND_SWITCH
RESOLVING
BATTLE_END
```

- `COMMAND_*`에서는 해당 선택 위젯을 표시하고 하단 내레이션 바를 숨긴다(MUST).
- `RESOLVING`에서는 행동 위젯을 숨기고 현재 이벤트 내레이션을 표시한다(MUST).
- `BATTLE_END`에서는 마지막 결과를 표시한 뒤 Cobblemon 종료 수명주기를 따른다(MUST).
- 더블배틀처럼 여러 활성 포켓몬의 입력이 필요할 때는 필요한 모든 행동이 제출되기 전까지 `RESOLVING`으로 전환하면 안 된다(MUST NOT).
- 강제 교체는 일반 명령 화면으로 돌아가지 않고 `COMMAND_SWITCH`로 진입해야 한다(MUST).

## 4. 선택 단계

`BattleActionMenu`는 공격, 포켓몬, 포획, 도망 등 현재 가능한 행동을 보여준다. 표시 항목은 하드코딩하지 않고 Cobblemon의 현재 `BattleActionSelection`과 `BattleOptionTile`에서 파생해야 한다(MUST).

- 야생 전투에만 포획 행동을 표시하는 등 Cobblemon의 실제 가용성을 보존한다(MUST).
- 오른쪽 아래 세로 명령 방향과 마우스·키보드의 하나인 포커스 상태는 첫 구현에서 유지한다(SHOULD).
- 버튼 종류, 내용 폭, 아이콘, 제목과 보조 문구는 공용 툴킷의 의미 속성으로 표현한다(MUST).
- 현재 포커스·호버·선택·비활성 상태는 색만으로 구분하면 안 된다(MUST NOT).

## 5. 연출 단계 내레이션

`BattleNarrationBar`는 화면 하단에 반투명 사각형 표면으로 표시하며, 현재 Cobblemon 연출과 관련된 메시지 한두 줄만 보여준다(MUST).

- 단순 벽시계 타이머만으로 다음 메시지나 선택 단계 전환을 결정하면 안 된다(MUST NOT).
- Cobblemon의 전투 메시지 큐, 애니메이션 또는 행동 선택 수명주기 중 확인 가능한 신호와 동기화해야 한다(MUST).
- 다음 `COMMAND_*` 상태가 시작되면 내레이션 바를 숨긴다(MUST).
- 긴 한·영 문장은 줄바꿈하되 전투 필드의 핵심 정보와 현재 선택지를 가리지 않아야 한다(MUST).

## 6. 전체 기록 화면

`BattleTranscript`는 평상시 HUD에 상주하지 않는다(MUST NOT). 사용자가 별도 아이콘 또는 키로 열었을 때만 표시한다(MUST).

- 플레이어 사건은 왼쪽, 상대 사건은 오른쪽에 정렬한다(MUST).
- 턴, 날씨, 필드, 오류와 출처 불명 사건은 가운데 시스템 행으로 표시한다(MUST).
- 턴별 묶음, 스크롤과 출처/종류 필터를 지원할 수 있다(MAY).
- 기존 Tab 전투 정보 모달과 입력이 충돌하면 안 된다(MUST NOT). 기록 열기 키와 아이콘의 정확한 선택은 구현 전 사용성 검토에서 정한다.
- 첨부된 대화창 이미지는 좌우 화자 구분과 선택적 기록 표시의 참고이며 자산을 복제하지 않는다(MUST NOT).

## 7. 구조화 이벤트

로그는 번역이 끝난 최종 문자열만 저장하지 않고 다음과 같은 의미 이벤트를 보존해야 한다(MUST).

```text
BattleEvent(
  turn,
  sourceSide = PLAYER | OPPONENT | SYSTEM,
  kind,
  message,
  sourcePokemonId?
)
```

- 출처는 번역 키·인자와 현재 battle registry의 actor/Pokémon 관계에서 판정한다(MUST).
- 한국어·영어 완성 문자열을 다시 파싱해 출처를 추측하면 안 된다(MUST NOT).
- 둘 이상의 후보가 있거나 확인할 수 없으면 `SYSTEM`으로 처리한다(MUST). 첫 이름 일치 대상을 임의 선택하면 안 된다(MUST NOT).
- 표시용 번역문과 필터·정렬용 의미 필드는 분리한다(MUST).

## 8. 기존 로그의 종료

새 세 컴포넌트가 실제 전투에서 동작하면 기존 상시 `BattleLogWidget` 렌더 경로를 제거한다(MUST). 두 로그 UI를 장기 설정 옵션으로 병존시키지 않는다(MUST NOT).

종료 조건은 다음과 같다.

1. 선택, 기술, 대상, 강제 교체와 다중 활성 포켓몬 상태가 전환된다.
2. 연출 메시지가 실제 전투 흐름과 동기화된다.
3. 전체 기록에서 아군·상대·시스템 정렬을 확인한다.
4. 종료·연결 끊김·관전·최소화 뒤 상태와 기록이 정리된다.

위 조건이 충족된 커밋에서 기존 위젯을 제거하고 문서에 종료 커밋을 기록한다(MUST).

## 9. 예외와 접근성

- 관전자는 명령 UI를 보지 않지만 내레이션과 허용된 기록을 볼 수 있어야 한다(SHOULD).
- 화면 최소화·일시 중지·리소스 재로드 뒤 중복 이벤트를 추가하면 안 된다(MUST NOT).
- 연결 종료와 전투 종료 때 임시 선택, 포커스와 큐를 정리한다(MUST).
- 마우스와 키보드는 같은 선택 상태를 갱신해야 한다(MUST).
- 내레이션은 현재 포커스 행동과 연출 문장을 구분해 전달해야 한다(MUST).

## 10. 검증 행렬

| 증거 | 필수 사례 |
| --- | --- |
| 단위 | 상태 전환, 다중 행동 제출, 출처 판정, 불명 출처의 SYSTEM 폴백 |
| 통합 | 실제 `BattleOptionTile` 목록과 포커스·활성화 동기화 |
| 실제 전투 | 야생 포획, 트레이너전, 강제 교체, 더블배틀, 승리·패배·도망 |
| 시각 | 한·영 긴 문장, GUI 배율, 하단 바와 전투 정보 겹침, 좌우 기록 정렬 |
| 수명주기 | 관전, 최소화, 연결 종료, 전투 종료, 리소스 재로드 |

실제 월드의 Cobblemon 전투에 들어가지 않은 fixture, 빌드와 단위 테스트만으로 이 결정을 완료했다고 보고하면 안 된다(MUST NOT).

## 11. 기각한 대안

| 대안 | 상태 | 이유 |
| --- | --- | --- |
| 상시 스크롤 로그 유지 | 기각 | 선택 정보와 연출 정보가 동시에 경쟁해 화면 밀도와 집중 흐름을 해친다. |
| 행동 목록 하드코딩 | 기각 | 야생·트레이너·강제 교체·후속 Cobblemon 변경에서 실제 가능 행동과 어긋난다. |
| 완성 번역 문자열로 좌우 출처 판정 | 기각 | 언어와 이름 중복에 따라 잘못 정렬된다. |
| 메시지마다 고정 시간만 기다림 | 기각 | 실제 애니메이션·메시지 큐와 쉽게 어긋난다. |
| 새 로그와 기존 로그를 영구 병존 | 기각 | 상태·입력·설정과 유지보수 경로가 둘로 갈라진다. |
