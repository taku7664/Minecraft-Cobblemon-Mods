# Better AI 행동 순서 사후분포 결정

| 항목 | 값 |
|---|---|
| Status | `shared` |
| Effective | 2026-09-25 |
| Updates | `BETTER_AI_PUBLIC_ACTION_EVIDENCE_DECISION.md` §5, `BETTER_AI_NATIVE_SHOWDOWN_SIMULATION_DECISION.md` §§3·7의 `INF-03`·`AUD-06` |
| Scope | 공개 행동 순서로 상대 속도·도구 완결 세계를 좁히고 구애 고정을 네이티브 요청에 유지하는 Better AI 제품 경로 |
| 주 독자 | 빡대리님과 Better AI·Cobblemon 호환 계층 구현 및 검증 담당자 |

## 1. 결론

- 코어 공개 관측기는 계속 행동자·기술·기본 우선도·공개 순서만 기록해야 한다(MUST). 관측기에서 실제 스피드, EV·성격 또는 구애스카프를 확정해서는 안 된다(MUST NOT).
- Better AI는 보유한 각 완결 세계를 실제 번들 Showdown에서 실행하고, 그 세계가 낸 기술 실행 순서를 공개 순서와 대조해 사후분포를 좁혀야 한다(MUST).
- 속도·트릭룸·우선도 변경 특성·도구 발동·동률 난수를 Kotlin 식으로 다시 계산해서는 안 된다(MUST NOT). 세계의 일치 여부는 Showdown이 실제로 낸 순서로만 판정해야 한다(MUST).
- 남은 세계가 모두 구애스카프를 포함할 때 AI는 그 도구를 사실상 추론한 것이지만, 다른 공개적으로 가능한 원인이 남았다면 스카프라고 단정해서는 안 된다(MUST NOT).

## 2. 네이티브 순서 장부

- 격리된 Showdown 분기는 실제 `move` 프로토콜 메시지가 추가되는 순간의 턴, 행동 포켓몬 UUID와 기술 ID를 구조화해 기록해야 한다(MUST).
- 이 장부는 `Battle.toJSON()`·`Battle.fromJSON()` 분기 복제 뒤에도 보존되어야 한다(MUST).
- 공개 `ACTION_ORDER` 중 양쪽 기술의 기본 우선도가 같은 쌍만 비교해야 한다(MUST).
- 공개 또는 네이티브 장부에서 같은 행동자가 한 턴에 두 번 이상 기술을 사용하면 Dancer·Instruct 같은 추가 행동과 구분할 수 없으므로 그 턴을 속도 근거로 쓰지 않아야 한다(MUST NOT).
- 공개 쌍의 UUID·기술 ID가 네이티브 장부에 모두 없으면 그 턴은 미해결로 남겨야 한다(MUST). 누락을 일치 또는 모순으로 꾸며서는 안 된다(MUST NOT).
- 충분한 공개 근거와 모순되는 세계는 제거하고 남은 확률을 1로 재정규화해야 한다(MUST). 모든 세계가 제거되면 네이티브 판단을 명시적으로 실패해야 한다(MUST).

## 3. 난이도 정책

| 난이도 | 행동 순서로 세계를 좁히는 시점 |
|---|---|
| 입문 | 사용하지 않는다. 공개 관계는 보존하지만 속도·도구 세계를 제거하지 않는다. |
| 표준 | 서로 다른 비교 가능 턴 2개가 쌓인 뒤 모순 세계를 제거한다. |
| 상급 | 비교 가능 턴 1개부터 모순 세계를 제거한다. |
| 보스 | 비교 가능 턴 1개부터 모순 세계를 제거한다. 상급보다 큰 완결 세계 상한과 더 깊은 탐색을 유지한다. |

- 표준의 2턴 조건은 단일 동률 난수나 일회성 순서 효과에 과도하게 확신하지 않기 위한 난이도 차이다(SHOULD).
- 상급과 보스의 근거 턴 수가 같더라도 완결 세계 상한은 각각 10과 16이고 탐색 깊이는 각각 2와 3이므로 같은 증거 뒤 보존·평가하는 설명 범위가 다르다(MUST).
- 난이도 차이는 공개 사실의 정확도를 바꾸는 것이 아니라 그 사실을 숨은 완결 세계 제거에 사용하는 시점을 바꾼다(MUST).

## 4. 구애 고정 소유권

- 구애 도구를 가진 세계도 첫 행동 전에는 네 기술 중 합법 기술을 모두 요청에 노출해야 한다(MUST).
- 정상적으로 기술을 사용한 다음 요청부터는 Showdown 요청이 허용한 고정 기술만 탐색해야 한다(MUST).
- 교체와 재등장, 트릭·바꿔치기 계열 도구 교환, 탁쳐서떨구기 등 도구 제거 뒤의 해제·재고정은 Showdown 상태와 요청을 그대로 따라야 한다(MUST).
- Kotlin 액션 생성기가 마지막 공개 기술만 보고 별도 구애 고정을 만들거나 해제해서는 안 된다(MUST NOT).

## 5. 폐기한 대안

- 공개 스탯 범위에 1.5배를 곱해 스카프 여부를 직접 판정하는 방식은 트릭룸·순서 특성·일회성 도구·동률 난수를 다시 구현하게 되므로 폐기한다.
- 한 번 선공했다는 이유만으로 공개 `HELD_ITEM_REVEALED`나 `CONFIRMED choicescarf` 추론을 만드는 방식은 다른 가능한 원인을 지우므로 폐기한다.
- 모든 난이도가 첫 관측부터 같은 세계를 제거하는 방식은 빡대리님이 요청한 난이도별 추론 차이를 없애므로 폐기한다.

## 6. 검증 계약

- 실제 번들 Showdown에서 기본 속도로는 뒤지만 구애스카프 세계에서는 앞서는 동일 포켓몬 쌍을 만들고, 공개 선공 관측 뒤 보스 제품 세션에 스카프 세계만 남아야 한다(MUST).
- 남은 스카프 세계는 첫 사용 기술 하나만 다음 네이티브 요청에 허용해야 한다(MUST).
- 입문은 같은 관측에서도 스카프·비스카프 세계를 모두 보존하고, 표준은 1턴에는 보존하되 2개의 서로 다른 비교 가능 턴 뒤 모순 세계를 제거해야 한다(MUST).
- 실제 Showdown에서 첫 행동 전 무고정, 사용 후 고정, 교체·재등장 뒤 해제와 재고정, 트릭으로 도구를 잃은 뒤 해제와 받은 쪽의 고정, 직접 도구 제거 뒤 해제를 검증해야 한다(MUST).
