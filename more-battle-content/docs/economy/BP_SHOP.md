# BP 상점 44품목 카탈로그와 GUI 결정

> **2026-09-27 정리 메모:** 1절의 탭 순서·카탈로그 경로와 3절의 장바구니는 현재 코드와 다르다(홈 우선 탭, `mbc-bp-shop/{rules,entries}`, 단일 품목 구매). 상세는 [인덱스의 불일치 표](../README.md#현재-코드와-다른-조항)를 본다.

## 1. 결정

- `/mbc open`은 상점을 기본 선택한 공통 콘텐츠 화면을 MUST 연다.
- 고정 탭 표시 순서는 `상점 → PvP → 배틀타워 → 배틀팩토리 → 보스 레이드`여야 한다.
- 첫 카탈로그는 기존 쓰기 계획의 임시 44품목과 가격대를 사용한다. 이 값은 후속 밸런스 결정 전의 운영 기본값이며 영구 밸런스 확정이 아니다.
- 카탈로그는 `data/cobblemon_more_battle_content/bp_shop/catalog/mbc_core.json` 서버 데이터 리소스가 소유한다. 서버 운영자는 데이터팩의 같은 리소스 위치로 품목·가격·정렬·카트 한계를 바꿀 수 있어야 한다.
- 상품 카드는 실제 `ItemStack` 아이콘과 이름을 표시하고, 호버하면 Minecraft가 해당 아이템에 제공하는 기본 툴팁을 MUST 표시한다. 설명 문구를 MBC가 별도로 하드코딩하지 않는다.
- 구매는 서버가 현재 카탈로그 revision, BP 잔액, 카트 한계와 인벤토리 수용 가능 여부를 다시 검증한 뒤 원자적으로 BP를 차감하고 아이템을 지급해야 한다.

## 2. 첫 데이터

- 총 44품목: 민트 21종, 특성캡슐 1종, 대전용 도구 22종이다.
- 가격대는 50 BP 22종, 25 BP 5종, 20 BP 5종, 15 BP 8종, 10 BP 4종이다.
- 카트 기본 한계는 최대 16줄, 품목별 최대 64회, 실제 아이템 총합 최대 64개다.
- `Bottle Cap`은 필수 모드에 대응 아이템이 없어 포함하지 않는다.
- `Adrenaline Orb`는 `mega_showdown:adrenaline_orb`를 사용한다.

정확한 44개 행과 정렬 순서는 제품 JSON을 단일 실행 데이터로 사용한다. 향후 품목을 바꿀 때 Kotlin 화면 코드를 고치지 않고 JSON과 그 계약 테스트를 함께 바꿔야 한다.

## 3. GUI와 부분 배포

- 상점은 공통 상단바·실제 BP·X·고정 탭을 유지하고 그 아래만 상품 목록과 장바구니로 바꾼다.
- 넓은 화면은 상품 목록과 장바구니를 좌우로, 320×240급 화면은 장바구니를 상품 목록 아래에 배치한다.
- 상품 클릭은 해당 품목을 선택하고 장바구니 수량을 1 늘린다. `−`, `+`, 비우기와 구매 동작을 제공한다.
- 기존 `BattleHubContent` 네 ordinal은 부분 배포 호환을 위해 바꾸지 않는다. `SHOP`은 enum 끝에 추가하고 표시 순서만 별도 탭 계약이 소유한다.
- 새 클라이언트가 구 서버에 접속해 상점 전용 패킷을 보낼 수 없으면, 존재하지 않는 ordinal을 보내지 않고 PvP 목록으로 폴백해야 한다.

## 4. 검증 경계

- 구현 전 탭 순서·기본값, 44품목 리소스, 상점 패킷과 넓은/좁은 배치 테스트가 실패하는 것을 확인했다.
- 구현 뒤 본체 449개 단위 테스트, 모듈 빌드, 한·영 번역과 카탈로그 JSON 파싱, JDK 21 JAR 검증이 통과했다.
- Cobblemon 1.7.3과 Mega Showdown 1.9.3 JAR의 아이템 모델 경로를 독립 대조해 44개 중 누락이 없음을 확인했다.
- 실제 서버 데이터 리로드, 게임 안 상점 렌더링·아이템 툴팁·구매·인벤토리 부족과 BP 부족 흐름은 아직 검증하지 않았다.

## 5. 폐기한 대안

- **Kotlin 하드코딩 품목표:** 운영 중 가격·품목 변경에 매번 새 JAR이 필요하므로 사용하지 않는다.
- **MBC 전용 설명 툴팁:** 실제 아이템과 설명이 어긋날 수 있으므로 사용하지 않는다. 아이템 제공 모드의 기본 툴팁을 그대로 사용한다.
- **기존 enum 순서 재배열:** 구 서버·신 클라이언트 부분 배포에서 다른 콘텐츠로 해석되거나 디코드 실패할 수 있어 사용하지 않는다.
