## 1. 표시 계약

- MBC 관리 전투의 행동 선택 화면은 Cobblemon과 설치 애드온이 제공한 기믹 중 현재 MBC 규칙에서 허용된 종류만 표시해야 한다(MUST).
- 배틀타워는 세션에 고정된 `MEGA`, `DYNAMAX`, `TERA` 중 정확히 한 종류만 표시해야 한다(MUST).
- 배틀팩토리는 주요 기믹을 허용하지 않으므로 기믹 버튼을 모두 숨겨야 한다(MUST).
- MBC PvP는 방장이 활성화한 `MEGA`, `DYNAMAX`, `TERA`, `Z_MOVE`만 표시해야 한다(MUST).
- MBC 설정에 선택 항목이 없는 울트라버스트와 이후 알 수 없는 기믹은 MBC 관리 전투에서 숨겨야 한다(MUST).
- MBC가 관리하지 않는 야생·트레이너·PvP 전투의 기믹 표시는 Cobblemon과 해당 애드온의 기존 판단을 그대로 유지해야 한다(MUST NOT 변경).

MBC 허용 여부는 외부 모드가 기믹을 제공할 수 있는지와 별개의 교집합 조건이다. MBC에서 허용했더라도 Cobblemon 또는 Mega Showdown이 현재 포켓몬·도구·상태에서 제공하지 않은 기믹 버튼을 새로 만들어서는 안 된다(MUST NOT).

## 2. 서버 권위와 동기화

- 버튼 비표시는 사용성 계약이며 합법성의 최종 경계가 아니다. 서버는 숨겨진 기믹의 조작 패킷을 받아도 기존 규칙 레지스트리로 거절해야 한다(MUST).
- 서버는 배틀 ID와 허용 기믹 집합을 Cobblemon의 최초 전투 상태·행동 요청보다 먼저 참가 클라이언트에 알려야 한다(MUST).
- 빈 허용 집합은 관리되지 않은 전투와 구별해야 한다(MUST). 빈 집합은 모든 기믹 비표시이고, 정책 자체가 없으면 일반 전투이므로 기존 표시를 유지한다.
- 전투 종료와 연결 종료에서 클라이언트 정책을 정리해야 한다(MUST). 오래된 전투의 종료 통지가 더 새로운 전투 정책을 지워서는 안 된다(MUST NOT).

## 3. 채택하지 않은 방식

- 허용되지 않은 버튼을 비활성 상태로 남기는 방식은 선택할 수 없는 기믹 자체를 화면에서 제거해 달라는 사용자 요구와 다르므로 채택하지 않았다.
- 다이맥스 밴드·키스톤 등 클라이언트 보유품만 다시 검사하는 방식은 MBC 콘텐츠 규칙을 알 수 없고 변조에도 약하므로 채택하지 않았다.
- 모든 Cobblemon 전투에서 버튼을 전역 필터링하는 방식은 MBC 밖의 정상 전투를 바꾸므로 채택하지 않았다.
- 화면에서만 숨기고 서버 제출 검사를 제거하는 방식은 조작 패킷으로 규칙을 우회할 수 있으므로 채택하지 않았다.

## 4. 구현·검증 상태

- 서버 규칙이 `PokemonBattle` 생성 시 붙는 기존 경계에서 허용 집합을 먼저 전송하고, 클라이언트는 배틀 ID별 정책과 Cobblemon `ShowdownMoveset.gimmicks`의 교집합만 버튼 생성에 전달한다.
- Mega Showdown 1.9.3의 `BattleMoveSelectionMixin`은 같은 `gimmickButtons` 목록을 렌더·클릭에 사용하며 별도 기믹 버튼을 추가하지 않는 것을 바이트코드로 확인했다.
- 빈 집합·단일·복수 정책, 일반 전투 보존, 다섯 Cobblemon 기믹의 명시적 매핑과 오래된 종료 통지 회귀를 포함해 본체 단위 테스트 439개가 통과했다.
- 캐시 없는 본체 빌드와 JDK 21 `jar --validate`, 리맵 JAR의 Mixin 대상·클라이언트 필터 호출 바이트코드 확인이 통과했다. 제품 SHA-256은 `0C84DC9918BBD038B4CC982B34C9DB5A6B389AD07CD1C5577E66F98A36F756C8`다.
- 서버·클라이언트에는 배치하지 않았고 실제 전투창은 아직 게임 안에서 검증하지 않았다.
- 2026-08-19 04:00 후속 통합본은 본체 440개 테스트, 본체 빌드와 JDK 21 JAR 검증을 통과했다. SHA-256 `5E55BC072BAE664F95C5D52299367C4B41CE5A6C61596170D4A668D559CFB7E5`를 `cobblemon-dev`와 `dev-server`에 배치했고, 서버는 Java PID 26724·`127.0.0.1:25566`·`Done (1.659s)`까지 기동 검증했다. 바로 앞 항목의 미배치 상태는 이 후속 기록으로 갱신됐지만 실제 전투창 표시는 여전히 게임 내 검증 대기 중이다.
