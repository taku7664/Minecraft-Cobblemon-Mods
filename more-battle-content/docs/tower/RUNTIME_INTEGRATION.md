# 배틀타워 기믹 런타임과 명시적 포기 결정

> **2026-09-27 정리 메모:** 1절의 Cobblemon 1.7.3·Mega Showdown `1.9.3+1.7.3+1.21.1`은 옛 버전이다. 현재는 Cobblemon 1.8.1, Mega Showdown `1.2.0+1.8.1+1.21.1-release`다. 상세는 [인덱스의 불일치 표](../README.md#현재-코드와-다른-조항)를 본다.

## 1. 기믹 제공자

- 본체는 Mega Showdown `1.9.3+1.7.3+1.21.1`을 정확한 버전의 필수 런타임 의존성으로 선언해야 한다(MUST).
- 첫 배틀타워의 `MEGA`, `DYNAMAX`, `TERA`는 위 Mega Showdown 버전이 제공하는 Cobblemon 1.7.3 기믹을 사용해야 한다(MUST).
- 본체 공개 API는 Mega Showdown 구현 클래스를 노출해서는 안 된다(MUST NOT). 기믹별 포켓몬 속성과 전투 호출은 Cobblemon 1.7.3 호환 계층에 격리해야 한다(MUST).
- Mega Showdown이 없거나 버전이 다르면 Fabric 로더 단계에서 시작을 거절해야 한다(MUST). 기믹이 없는 일반 풀로 조용히 대체해서는 안 된다(MUST NOT).

## 2. 명시적 포기와 예기치 않은 종료

- 활성 배틀에서 플레이어가 `/mbc abandon battle_tower`를 실행하면 해당 플레이어의 현재 MBC 배틀 UUID와 Cobblemon `PlayerBattleActor`를 서버가 다시 검증해야 한다(MUST).
- 검증된 명시적 포기는 Cobblemon의 Showdown 포기 경로를 사용하고 배틀타워 패배 1회로 기록해야 한다(MUST).
- 명시적 포기 요청은 같은 활성 배틀에 한 번만 전달해야 한다(MUST). 중복 요청이 패배를 중복 기록해서는 안 된다(MUST NOT).
- 패배 저장이 성공한 뒤 해당 메모리 세션과 등록 팀 스냅샷을 폐기해야 한다(MUST).
- 명시적 포기 요청이 없었던 강제 종료, 무승부와 승패 미확정 종료는 승패를 기록하지 않아야 한다(MUST NOT). 이 경우에만 준비 상태로 돌아갈 수 있다(MAY).
- GUI의 팀 변경 의도는 세션 포기 명령과 다른 동작으로 유지해야 한다(MUST). 활성 배틀 중 GUI 팀 변경은 계속 거절해야 한다(MUST).

## 3. 채택하지 않은 방식

- `PokemonBattle.end()`만 호출하는 방식은 승자·패자 목록을 만들지 않아 명시적 포기를 패배로 정산할 근거가 없으므로 채택하지 않았다.
- 명령 수신 즉시 저장소에 패배를 먼저 쓰는 방식은 실제 Cobblemon 배틀 종료보다 기록이 앞서고 포기 전달 실패 시 롤백 경계가 생기므로 채택하지 않았다.
- 연결 종료와 서버 강제 종료를 모두 패배로 간주하는 방식은 빡대리님이 확정한 “명시적 포기만 패배” 경계를 넘으므로 채택하지 않았다.

## 4. 남은 데이터 결정

Mega Showdown 제공자 결정은 완료됐다. 그러나 기믹별 상대 데이터는 별도 쓰기 승인을 계속 요구한다. 특히 테라 타입, 다이맥스 레벨과 거다이맥스 가능 여부를 세트 데이터로 선언할 형식은 승인 전까지 구현하거나 내장 JSON에 쓰지 않는다.
