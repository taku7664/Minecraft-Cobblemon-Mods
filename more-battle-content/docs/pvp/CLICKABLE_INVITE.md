## 1. 초대 표시와 행동

- 새 클라이언트를 사용하는 초대 대상에게 채팅 한 줄로 `[PvP 초대] <방장>님의 방 [입장] [거절]`을 표시해야 한다(MUST).
- `[입장]`은 해당 `roomId`의 기존 서버 권위 `Join` 요청을 직접 보내야 한다(MUST). 초대 필요, 다른 방 참여 중과 방 상태 검증을 우회해서는 안 된다(MUST NOT).
- `[거절]`은 해당 `roomId`의 초대 권한만 제거하는 `DeclineInvite` 요청을 직접 보내야 한다(MUST). 거절만으로 PvP 룸 목록이나 다른 GUI를 열어서는 안 된다(MUST NOT).
- 버튼은 클라이언트가 서버 명령어 문자열을 조립하거나 실행하는 방식으로 구현해서는 안 된다(MUST NOT).
- 만료되거나 이미 거절한 초대를 다시 누르면 서버가 현재 룸 상태를 기준으로 거절하고 오류를 채팅에 표시해야 한다(MUST).

## 2. 부분 배포 호환성

- 서버는 초대 전용 S2C payload를 받을 수 있는 클라이언트에만 클릭형 알림을 보내야 한다(MUST).
- 구형 클라이언트에는 `/mbc pvp open`으로 확인하라는 기존 텍스트 안내를 보내야 한다(MUST).
- 클릭형 알림을 받은 클라이언트만 새 `DeclineInvite` 요청을 생성할 수 있으므로 구 서버에 새 요청을 보내는 부분 배포 경로를 만들지 않아야 한다(MUST).

## 3. 채택하지 않은 안

- `RUN_COMMAND` 또는 `SUGGEST_COMMAND` 채팅 이벤트로 `/mbc pvp ...` 문자열을 실행하는 안은 GUI·패킷이 애플리케이션 서비스를 직접 호출해야 한다는 공통 계약을 깨므로 채택하지 않는다.
- 거절 뒤 룸 목록을 자동으로 여는 안은 사용자가 채팅에서 초대를 정리하려는 흐름을 방해하므로 채택하지 않는다.
