## 1. 적용 범위

이 문서는 초기 1대1 PvP에 공개·비공개 룸, 팀 프리뷰, 관전과 새 배틀 라운지 차원을 추가한다. 더블은 포켓몬 배틀 형식이며 플레이어 2대2 팀전은 아니다. 향후 다인 플레이어 형식은 MAY 확장하지만 이번 계약에 포함하지 않는다.

과거 프로젝트의 Battle Lounge, 전용 차원, 저장 스키마와 접수 구현은 계속 폐기 상태다. 이 문서의 배틀 라운지는 현재 본체 계약으로 독립 구현한 새 기능이며 옛 파일·코드·자산을 승계하지 않는다(MUST NOT).

## 2. 룸과 권한

- 서버는 PUBLIC과 PRIVATE 룸을 제공해야 한다(MUST).
- PUBLIC 룸은 방 목록에서 직접 참가할 수 있어야 한다(MUST). 진행 중인 PUBLIC 룸도 목록에 남고 새 참가자는 관전자로 입장해야 한다(MUST).
- PRIVATE 룸은 방장의 명시적 초대를 받은 플레이어만 목록에서 보고 참가할 수 있어야 한다(MUST).
- 현재 전투 자리는 LEFT와 RIGHT 각 한 명이다(MUST). 빈 자리에는 참가 행동을 뜻하는 `+`를 표시해야 한다(MUST).
- 룸 구성원은 빈 진영으로 이동하거나 관전석으로 돌아갈 수 있어야 한다(MUST).
- 방장만 공개 범위, 싱글·더블 형식, 허용 기믹과 팀 프리뷰 시작을 변경할 수 있어야 한다(MUST).
- 양쪽 자리가 모두 찬 경우에만 방장이 팀 프리뷰를 시작할 수 있어야 한다(MUST).
- 방장은 GUI로 다른 구성원에게 방장을 넘길 수 있어야 한다(MUST). 방장이 예기치 않게 나가면 가장 먼저 참가한 남은 구성원이 자동으로 방장이 되어야 한다(MUST).

## 3. 기믹 규칙

- 방장은 `MEGA`, `DYNAMAX`, `TERA`, `Z_MOVE`를 각각 독립적으로 켜거나 끌 수 있어야 한다(MUST).
- 한 전투에서 여러 종류의 기믹을 함께 허용할 수 있어야 한다(MUST).
- 각 진영은 활성화된 각 기믹 종류를 전투당 최대 한 번씩 사용할 수 있어야 한다(MUST). 예를 들어 네 종류가 모두 켜져 있으면 한 진영은 메가진화·다이맥스·테라스탈·Z기술을 각각 한 번 사용할 수 있다.
- 꺼진 기믹, 같은 기믹의 두 번째 사용과 한 제출 안의 같은 기믹 중복은 서버가 거절해야 한다(MUST).
- 이 다중 기믹 계약은 PvP에만 적용한다. 배틀타워의 세션 고정 단일 기믹 계약은 변경하지 않는다(MUST NOT).

## 4. 팀 프리뷰와 준비

- 서버가 양쪽 파티의 등록 마릿수, 종족 중복과 지닌 도구 중복을 검증한 뒤 팀 프리뷰를 열어야 한다(MUST).
- 상대에게는 포켓몬 종족만 공개하고 선출 순서와 지닌 도구는 숨겨야 한다(MUST).
- 화면은 LEFT와 RIGHT 진영에 맞춰 양쪽 엔트리를 배치하고 중앙 상단에 남은 선출 시간을 표시해야 한다(MUST).
- 각 참가자는 필요한 엔트리를 고른 뒤 별도의 준비 완료를 눌러야 한다(MUST).
- 한쪽만 준비한 동안에는 준비 취소 후 선출을 바꿀 수 있어야 한다(MUST). 양쪽이 모두 준비하면 서버가 전투를 시작해야 한다(MUST).
- 중앙 하단에는 관전자 머리를 표시해야 한다(MUST). 일반 화면은 한 열을 최대 10행으로 유지하고 초과 인원은 가로 열을 늘려 중앙 정렬해야 한다(MUST). 좁은 화면은 표시 가능한 행 수를 줄이고 같은 가로 확장 규칙을 적용할 수 있다(MAY).

## 5. 새 배틀 라운지

- 서버는 `cobblemon_more_battle_content:battle_lounge` 차원을 제공해야 한다(MUST).
- 경기 공간은 넓은 색유리 원기둥이며 LEFT와 RIGHT 참가자가 중앙을 사이에 두고 서로 바라보도록 배치해야 한다(MUST).
- 경기장 풀은 최초 0개로 시작하고, 기존 동시 사용 최고치를 초과할 때 정확히 한 공간을 추가해야 한다(MUST). 유휴 공간은 낮은 번호부터 재사용해야 한다(SHOULD).
- 서로 다른 경기장은 일반적인 클라이언트 시야에 다른 전투가 들어오지 않을 만큼 떨어져야 한다(MUST). 현재 기준 간격은 2048블록이다.
- 경기장 구조는 서버가 처음 임대할 때 생성하고 같은 번호를 재사용할 때 다시 만들지 않아야 한다(SHOULD).

## 6. 순수 관전과 BattleCam

- 관전자는 서버의 SPECTATOR 게임 모드로 전환해 월드에 보이는 일반 플레이어 몸과 일반 플레이어 조작을 제거해야 한다(MUST).
- 서버는 관전자를 해당 경기장 관전 지점에 고정하고 Cobblemon 관전 세션에 등록해야 한다(MUST).
- 클라이언트는 이동, 공격, 사용, 인벤토리, 핫바와 Cobblemon `R` 포켓몬 내보내기 입력을 소비해야 한다(MUST). 채팅, 화면 캡처와 BattleCam 카메라 키는 막아서는 안 된다(MUST NOT).
- BattleCam은 선택 권장 모드이며 설치 시 해당 모드의 기본 관전 카메라를 사용한다(SHOULD). BattleCam 부재가 서버 관전과 복귀를 막아서는 안 된다(MUST NOT).

## 7. 종료·연결 끊김·복귀

- 참가자와 관전자는 라운지 이동 직전의 차원, 좌표, 시선과 게임 모드를 복귀 지점으로 가져야 한다(MUST).
- 정상 승패, 무효 종료, 관전 이탈과 서버 정상 종료에서 가능한 모든 온라인 플레이어를 원래 위치로 복귀시켜야 한다(MUST).
- 관전자가 진행 중인 공개방을 나가면 Cobblemon 관전을 끝내고 즉시 원래 위치로 복귀시켜야 한다(MUST).
- 복귀가 실패하거나 대상이 오프라인이면 복귀 정보는 성공할 때까지 남아야 한다(MUST). 서버 재시작 뒤에도 이를 보장하려면 8절의 저장 스키마 승인이 필요하다.

## 8. 영속 저장 제안 — 승인 대기

이 절은 아직 `pending`이며 파일 쓰기 승인을 뜻하지 않는다. 승인 전에는 SavedData를 구현하거나 기존 월드에 파일을 만들지 않는다(MUST NOT).

제안 파일은 `cobblemon_more_battle_content_pvp_lounge.dat`이고 스키마는 다음과 같다.

```text
schema: 1
arena_count: int >= 0
pending_returns: list[
  player: UUID
  dimension: resource_location
  x: double
  y: double
  z: double
  yaw: float
  pitch: float
  game_mode: survival | creative | adventure | spectator
]
```

룸과 진행 중인 매치는 저장하지 않는다. 서버 재시작 시 룸은 종료하고, `arena_count`는 최고 동시 사용량으로 보존하며, `pending_returns`는 다음 접속 또는 서버 기동 중 복귀 성공 뒤에만 제거하는 방식을 제안한다.

## 9. GUI 진입

- `/mbc open`과 홀로 터미널은 배틀타워·배틀팩토리·PvP·보스 레이드 탭을 가진 공통 배틀 허브를 열어야 한다(MUST).
- 배틀타워·배틀팩토리·PvP 탭은 각 서버 서비스로 이동해야 한다(MUST). 보스 레이드는 수직 기능이 구현되기 전까지 탭을 보이되 비활성 상태로 표시해야 한다(MUST).
- 터미널에서 허브를 거쳐 배틀타워로 이동해도 터미널 검증 문맥을 잃어서는 안 된다(MUST NOT).

## 10. 채택하지 않은 안

- PvP를 메가진화 한 종류로 고정하는 안은 빡대리님의 다중 기믹 결정과 맞지 않아 폐기한다.
- 옛 Battle Lounge 구현과 저장 데이터를 이동하는 안은 종료 프로젝트 경계를 깨므로 폐기한다.
- 렌더 거리만으로 다른 경기를 숨기는 안은 서버 설정에 따라 실패할 수 있어 폐기하고, 큰 간격과 관전자 위치 고정을 함께 사용한다.
- 클라이언트 입력 차단만으로 순수 관전을 보장하는 안은 패킷 변조와 모드 순서에 약하므로 폐기하고 서버 SPECTATOR 모드를 권위 경계로 사용한다.
