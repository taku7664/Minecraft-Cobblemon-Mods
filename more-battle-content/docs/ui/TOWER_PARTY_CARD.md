# 배틀타워 출전 순서와 파티 카드 후속 결정

| 항목 | 값 |
|---|---|
| Status | `shared` |
| Effective | 2026-08-18 |
| Updates | [`TOWER_PLAY_SCREEN.md`](TOWER_PLAY_SCREEN.md) |
| 주 독자 | 빡대리님과 배틀타워 GUI·서버 상태 구현 담당자 |

## 1. 결정

- 사용자가 포켓몬을 클릭한 순서는 실제 배틀의 출전 순서여야 한다(MUST).
- 서버 상태와 S2C 패킷은 선택 UUID의 순서를 보존해야 하며, 팀 잠금과 실제 배틀 생성은 그 순서를 그대로 사용해야 한다(MUST).
- 선택된 각 카드에는 `(1)`부터 `(3/4)`까지 출전 번호를 표시해야 한다(MUST).
- 파티 카드에는 포켓몬 GUI 초상, 이름, 배틀 레벨, 지닌 도구와 출전 번호를 즉시 노출해야 한다(MUST).
- 원래 레벨과 전체 정보는 툴팁에도 계속 제공해야 한다(SHOULD).
- 좁은 화면에서는 이름과 지닌 도구 문구를 카드 경계 안에서 줄이더라도 출전 번호와 배틀 레벨은 유지해야 한다(MUST).
- 카드의 내레이션에는 선택 여부 또는 출전 번호, 이름, 배틀 레벨과 지닌 도구가 포함돼야 한다(MUST).

## 2. 초상 렌더링 경계

- 외부 포켓몬 스프라이트 묶음을 복제하거나 새 의존성으로 추가하지 않는다(MUST NOT).
- Cobblemon 1.7.3이 제공하는 GUI 프로필 초상 렌더러를 카드의 고정된 2D 영역 안에서 사용한다(MUST).
- 현재 클라이언트 파티에서 같은 UUID를 찾을 수 있으면 실제 개체의 폼과 외형을 사용해야 한다(SHOULD).
- 팀 잠금 뒤 모험 파티가 바뀌어 UUID를 찾을 수 없으면 서버 상태의 종 ID로 기본 초상을 표시할 수 있다(MAY).
- 초상은 카드 경계를 넘어 다른 텍스트나 카드를 덮지 않아야 한다(MUST).

## 3. 시각 방향과 책임

- 첫 구현은 Minecraft·Cobblemon 기본 위젯의 조작감을 유지하고, 선택 상태에 MBC 홀로 터미널과 연결되는 청록색 강조를 사용해야 한다(SHOULD).
- 빡대리님에게 추상적인 “시각 방향”을 선결 조건으로 요구하지 않는다(MUST NOT). GUI 담당자가 실제 화면을 구현해 제시하고 빡대리님이 화면을 보고 조정한다.
- Figma는 정보 구조 보조 자료이며 실제 코드와 게임 화면보다 우선하지 않는다(MUST NOT).

## 4. 채택하지 않은 대안

- 원래 파티 슬롯 순서로 선출하는 방식은 채택하지 않았다. 클릭 행위가 선봉 선택처럼 보이지만 실제 순서를 제어하지 못해 화면과 전투 결과가 어긋나기 때문이다.
- 이름과 배틀 레벨만 있는 텍스트 버튼은 채택하지 않았다. 지닌 도구와 선봉 순서를 비교하려면 툴팁을 반복해서 열어야 하기 때문이다.
- 외부 2D 스프라이트 팩을 포함하는 방식은 채택하지 않았다. 자산 라이선스·폼 누락·Cobblemon 리소스와의 불일치가 생기기 때문이다.

## 5. 검증 상태

- 클릭 순서의 서버 상태·패킷 왕복·실제 배틀 런처 전달과 320×240 카드 내부 배치는 단위 테스트로 검증했다.
- 본체 372개 테스트, 본체 모듈 빌드와 JDK 21 `jar --validate`가 통과했다.
- 실제 Minecraft 화면에서 초상 크기, 글자 잘림, 클릭, 키보드 포커스와 내레이터는 아직 검증하지 않았다.
- 빌드 JAR은 개발 클라이언트나 서버에 배치하지 않았다.
