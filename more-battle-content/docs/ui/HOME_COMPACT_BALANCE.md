## 1. 근거

사용자 실게임 캡처 `화면 캡처 2026-08-19 134433.png`에서 좌측 캐릭터·리더보드 열이 본문 폭 약 62%를 차지했다. 표시 정보량에 비해 두 패널의 빈 공간이 크고, 실제 상품 탐색 영역은 좁았다. 전역 상단 BP와 상점의 관계도 분리돼 있었으며 JSON 카탈로그가 범용인데 제목은 `배틀 아이템`으로 고정돼 있었다.

## 2. 정정 계약

- 일반 화면의 홈 본문은 좌측 캐릭터·리더보드 열 약 36%, 우측 상점 열 약 64%를 사용해야 한다(MUST).
- 320×240급 좁은 화면에서도 상점 폭이 좌측 열보다 커야 한다(MUST).
- 공통 상단바의 BP 배지는 제거해야 한다(MUST). 다른 콘텐츠 탭에서 별도 BP 배지를 다시 만들지 않는다(MUST NOT).
- 실제 BP는 홈의 상점 헤더 오른쪽에 표시해야 한다(MUST).
- 상점 패널 제목은 판매 품목 종류를 가정하지 않는 `상점`이어야 한다(MUST). `배틀 아이템`처럼 현재 JSON 내용에 종속된 제목을 사용하지 않는다(MUST NOT).
- 상점 열이 넓어지는 것은 의도된 결과다. 좌측 열의 기존 빈 공간을 보존하려고 상점 폭을 제한하지 않는다(MUST NOT).

## 3. 구현과 검증

- 공통 프레임에서 `bpBadge` 계약과 렌더링을 제거하고 브랜드가 X 앞까지 사용할 수 있게 했다.
- 홈 레이아웃을 좌측 36%·우측 64%로 바꾸고 좁은 화면 최소 폭을 별도로 보존했다.
- 상점 패널 내부에 실제 `MbcBattleHubClientState.bpBalance` 배지를 추가하고 한·영 제목을 `상점`/`Shop`으로 바꿨다.
- 구현 전 상점 내부 BP 영역이 없어 새 레이아웃 테스트가 컴파일 실패하는 것을 확인했다.
- 구현 후 본체 455개 테스트, 모듈 빌드, 한·영 JSON 파싱과 JDK 21 JAR 검증이 통과했다. 빌드 SHA-256은 `6CB611422B6723566277DAB03E69D095C989C30100C33B40D2B25BF5EDD56A73`이다.
- 2026-08-19 13:52 종료 상태의 `dev-server`와 `cobblemon-dev`에 새 JAR을 배치해 빌드·서버·클라이언트 SHA-256 일치를 확인했다. 직전 JAR은 양쪽 `20260819-135213-before-home-compact-balance` 백업에 보존했다.
- 보이는 `dev-server/run.bat`으로 재기동한 Java PID 39900이 `127.0.0.1:25566`과 `[13:52:48] Done (1.500s)`에 도달했다. 기동 ERROR 9개는 기존 기준선과 같고 MBC 실패 일치는 0개다. 클라이언트는 아직 종료 상태이므로 새 화면의 실게임 캡처 검증은 남아 있다.

## 4. 폐기한 대안

- **전역 BP와 상점 BP 동시 표시:** 같은 값을 중복 강조하므로 폐기했다.
- **`배틀 아이템` 제목 유지:** 데이터팩이 민트·일반 도구 또는 이후 다른 품목을 팔 수 있어 카탈로그 계약과 맞지 않으므로 폐기했다.
- **왼쪽 50% 안팎의 절충 비율:** 캡처에서 확인된 빈 공간을 충분히 줄이지 못하므로 사용하지 않는다.
