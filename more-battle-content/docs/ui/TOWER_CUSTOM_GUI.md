## 1. 결정

- 첫 배틀타워 Play 화면은 Minecraft 기본 버튼을 나열한 화면이 아니라 MBC가 직접 그리는 전용 화면 셸·패널·카드·버튼 표면을 사용해야 한다(MUST).
- 일반 화면은 상단 헤더와 BP 배지, 좌측 6마리 파티 rail, 중앙 진행·형식·기믹 영역, 우측 규칙·선출·오류 영역과 하단 행동 영역으로 구성해야 한다(MUST).
- 320×240 논리 화면에서는 파티 rail을 유지하고 중앙 진행·설정과 우측 상태 영역을 세로로 접어 두 열 안에 배치해야 한다(MUST).
- 파티 카드의 초상·이름·배틀 레벨·지닌 도구·출전 번호와 클릭 순서의 실제 출전 계약은 유지해야 한다(MUST).
- 기본 위젯의 조작감은 포커스·클릭·Enter/Space·툴팁·내레이션 계약으로 유지하되, 바닐라 버튼 텍스처와 리소스팩이 바꾼 버튼 표면을 렌더링해서는 안 된다(MUST NOT).
- 서버 승인·request ID·revision·pending·typed error와 세션 전이는 기존 계약을 그대로 유지해야 한다(MUST).

## 2. 레퍼런스 사용 경계

- Cobblemon Battle Tower 1.10.22의 전용 셸, 파티 rail, 중앙 진행 시각화, 문맥 패널과 하단 행동이라는 정보 구조만 참고한다(MAY).
- 원본의 픽셀 좌표, 색상값, 장식, 애니메이션, 볼 아이콘과 다른 자산은 복제하지 않는다(MUST NOT).
- MBC는 홀로 터미널과 연결되는 짙은 남청색 표면, 청록색 주 강조, 보라색 보조 강조와 금색 BP 강조를 독자적인 값으로 사용한다(SHOULD).

## 3. Play-only 경계

- 이번 화면에는 BP 상점, Challenges, Records와 Guide를 노출하지 않는다(MUST NOT).
- 우측 문맥 패널은 상점 대신 현재 선출 수, 세션 기믹, 팀 규칙, 처리 중 상태와 서버 오류를 표시해야 한다(MUST).
- 후속 패널을 추가할 때는 [`TOWER_PLAY_SCREEN.md`](TOWER_PLAY_SCREEN.md) § 3의 확장 게이트를 먼저 통과해야 한다(MUST).

## 4. 채택하지 않은 대안

- 기본 `Button` 표면 위에 색 띠와 정보를 추가하는 방식은 채택하지 않았다. 활성 리소스팩이 바닐라 버튼 표면을 바꾸면 화면 정체성과 대비가 함께 무너지기 때문이다.
- 레퍼런스 화면을 픽셀 단위로 복제하는 방식은 채택하지 않았다. 라이선스·자산 경계를 침해하고 MBC의 Play-only 계약과 반응형 요구에도 맞지 않는다.

## 5. 검증 조건

- 데이터 전용 레이아웃 테스트가 일반 화면의 3영역과 320×240의 2영역 reflow, 파티 카드 6개, 하단 행동의 무겹침을 검증해야 한다(MUST).
- 스타일 계약 테스트가 화면·패널·버튼 상태와 주·보조·위험 강조를 서로 구분해야 한다(MUST).
- 빌드 뒤 실제 리소스팩이 활성화된 클라이언트 화면에서 바닐라 버튼 표면이 나타나지 않는지 확인해야 한다(MUST).
