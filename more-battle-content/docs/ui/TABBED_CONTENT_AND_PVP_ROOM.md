## 1. 고정 콘텐츠 탭

- 배틀타워·배틀팩토리·PvP의 루트 콘텐츠 화면은 상단에 같은 네 콘텐츠 탭을 계속 표시해야 한다(MUST).
- 사용자가 탭을 선택하면 같은 MBC 셸의 탭 아래 콘텐츠가 바뀌는 것으로 보여야 한다(MUST). 구현 내부에서 서버 상태를 다시 요청하고 Screen 객체를 교체할 수는 있지만 별도 창을 연 것처럼 다른 헤더·탐색 구조를 보여서는 안 된다(MUST NOT).
- 현재 콘텐츠 탭은 선택 상태로 표시해야 하며 보스 레이드는 수직 기능 구현 전까지 보이되 비활성 상태여야 한다(MUST).
- 루트 콘텐츠에는 공통 허브로 돌아가는 `뒤로` 버튼을 두지 않는다(MUST NOT). `ESC`는 GUI 전체를 닫는 Minecraft 기본 동작으로 유지한다(MUST).
- 확인창과 플레이어 선택창처럼 현재 콘텐츠 위에 잠시 여는 하위 화면은 취소·복귀 행동을 제공할 수 있다(MAY).

## 2. PvP 대기실 정보 구조

- 대기실은 위에서부터 `고정 콘텐츠 탭 → 한 줄 설정 → 좌 진영 / 관전자 / 우 진영 → 관리 행동` 순서로 배치해야 한다(MUST).
- 공개 범위 2개, 형식 2개와 기믹 4개는 탭 바로 아래의 한 줄 설정 영역에 있어야 한다(MUST). 진영 모델이나 관전자 목록 공간을 차지해서는 안 된다(MUST NOT).
- 좌·우 진영 패널은 진영명, 플레이어 모델·닉네임과 해당 진영 참가 버튼만 소유해야 한다(MUST).
- `플레이어 초대`, `방장 양도`, `엔트리 선택 시작`, `방 나가기`는 화면 하단 관리 영역에 배치해야 한다(MUST). 초대와 양도는 방장만 사용할 수 있어야 한다(MUST).
- `관전석으로`는 관전자 중앙 패널 하단에 두고, 진영 참가와 같은 자리 이동 행동으로 읽혀야 한다(MUST).

## 3. 플레이어 모델

- 좌·우 플레이어 모델은 마우스 위치를 따라 회전하지 않고 화면 정면을 바라봐야 한다(MUST).
- 같은 플레이어의 렌더 엔티티는 프레임마다 새로 만들지 않고 화면이 열린 동안 유지해야 한다(MUST). 월드 시간에 맞춰 서 있는 기본 유휴 애니메이션이 진행돼야 한다(MUST).
- 모델은 자기 진영 패널 안에서 잘라 그려야 하며 닉네임·참가 버튼을 침범해서는 안 된다(MUST NOT).

## 4. 관전자 표시

- 대기실과 팀 프리뷰의 관전자는 머리 아이콘과 닉네임을 함께 표시해야 한다(MUST).
- 관전자는 위에서 아래로 먼저 채우고 일반 높이에서 한 열은 최대 10행이어야 한다(MUST). 현재 높이가 10행보다 작으면 실제로 들어가는 행 수를 사용한다(MAY).
- 세로 공간이 차면 오른쪽에 열을 하나씩 추가하고 전체 관전자 블록을 중앙 정렬해야 한다(MUST).
- 좁은 열에서는 닉네임을 열 폭에 맞춰 잘라낼 수 있지만 머리만 남기고 이름 전체를 숨겨서는 안 된다(MUST NOT).

## 5. PvP 기본 기믹

- 새 공개방·비공개방과 별도 명령 기반 PvP 도전의 기본 활성 기믹은 `MEGA` 하나여야 한다(MUST).
- `DYNAMAX`, `TERA`, `Z_MOVE`는 기본적으로 꺼져 있어야 한다(MUST).
- 방장은 대기실에서 네 기믹을 각각 독립적으로 켜거나 끌 수 있고, 복수 활성과 종류별 진영당 1회 계약은 유지한다(MUST).

## 6. 채택하지 않은 안

- 콘텐츠마다 다른 상단 헤더를 유지하고 `뒤로`로 허브를 다시 여는 안은 같은 제품 안에서 창이 바뀌는 느낌을 만들므로 폐기한다.
- 초대·양도를 비어 있는 모델 영역에 배치하는 안은 진영 패널의 의미와 모델 가독성을 깨므로 폐기한다.
- 관전자를 머리 아이콘만 표시하는 안은 누가 보고 있는지 구분할 수 없어 폐기한다.
- 모델을 매 프레임 새 `RemotePlayer`로 만들고 마우스 추적 렌더러에 넘기는 안은 자세와 애니메이션이 불안정해 폐기한다.
