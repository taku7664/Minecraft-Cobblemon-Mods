## 1. 근거

사용자 실게임 캡처 `화면 캡처 2026-08-19 135739.png`에서 캐릭터와 리더보드를 36%짜리 좌측 열 안에서 위아래로 나눈 결과, 캐릭터 영역이 세로로 답답하고 전신 표시를 위한 높이가 부족했다. 리더보드 너비는 적절했으므로 이를 줄이지 않고 중앙 독립 열로 옮기는 편이 정보 밀도와 모델 가독성을 함께 보존한다.

## 2. 후속 계약

- 홈 본문은 `캐릭터 → 리더보드 → 상점` 순서의 동일 높이 3열이어야 한다(MUST).
- 리더보드 열은 직전 36% 너비를 유지해야 한다(MUST).
- 캐릭터 열은 리더보드 너비의 약 2/3여야 한다(MUST). 일반 최대 화면에서는 본문 안쪽 너비의 약 24%에 해당한다.
- 캐릭터 모델 뷰포트는 패널 상단부터 닉네임 줄 직전까지 사용하고 머리부터 다리까지 잘리지 않는 전신을 표시해야 한다(MUST).
- 캐릭터 패널의 `내 캐릭터`/`My Character` 제목은 표시하지 않아야 한다(MUST NOT). 닉네임은 패널 하단에 유지한다(MUST).
- 상점은 캐릭터 열이 새로 차지한 만큼 좁아지며 남은 너비를 사용해야 한다(MUST). 리더보드 너비를 줄여 상점 폭을 되돌리지 않는다(MUST NOT).
- 리더보드·상점의 독립 세로 스크롤, BP 배지, 구매 동작과 서버 계약은 바꾸지 않는다(MUST NOT).

## 3. 구현과 검증

- `ShopScreenLayout`을 상하 분할 2열에서 동일 높이 3열로 바꾸고, 320×240급 최소 화면에서도 세 패널 최소 폭을 보존했다.
- 캐릭터 제목 렌더링과 사용하지 않는 한·영 번역 키를 제거했다.
- 구현 전 새 3열 계약 테스트 2개가 기존 코드에서 실패하는 것을 확인했다.
- 구현 후 본체 455개 테스트, 모듈 빌드, 한·영 JSON 파싱과 JDK 21 JAR 검증이 통과했다. 빌드 SHA-256은 `F6CAB749705B980B93ED45524A026F3BA69A3CF7E764423DFA4BF03A5AA3633E`이다.
- 2026-08-19 14:05 종료 상태의 `cobblemon-dev`에 새 JAR을 클라이언트 전용으로 배치해 빌드·클라이언트 SHA-256 일치를 확인했다. 직전 `6CB611422B6723566277DAB03E69D095C989C30100C33B40D2B25BF5EDD56A73`은 `20260819-140519-before-home-three-column`에 보존했다.
- 호환 서버 Java PID 17716과 서버 JAR은 중단·교체하지 않았다. 실제 전신 표시와 3열 비율은 클라이언트 실행 후 캡처로 검증해야 한다.

## 4. 폐기한 대안

- **캐릭터·리더보드 상하 분할 유지:** 캐릭터 전신을 위한 세로 공간 부족을 해결하지 못하므로 폐기했다.
- **리더보드까지 함께 축소:** 현재 리더보드 너비를 유지하라는 사용자 결정과 이름·상세값 가독성에 어긋나므로 폐기했다.
