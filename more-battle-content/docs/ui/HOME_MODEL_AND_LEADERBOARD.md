## 1. 근거

사용자 실게임 캡처 `화면 캡처 2026-08-19 145612.png`에서 캐릭터 패널은 충분히 커졌지만 모델 상반신만 패널 하단에 작게 남고 다리가 잘렸다. Minecraft 1.21.1 `InventoryScreen.renderEntityInInventory` 바이트코드를 다시 확인한 결과, 엔티티 높이 절반 이동과 Z축 180도 회전으로 전달 좌표가 전신의 화면 중심이 되는데 MBC가 이를 `bottom`으로 잘못 이름 붙여 뷰포트 하단을 넘겼다.

같은 화면의 제목과 서버 payload는 배틀타워 싱글·더블만 제공했다. 공통 `BattleRecordService`에는 이미 배틀팩토리와 PvP 기록도 저장되므로 홈 허브에서 타워만 노출할 이유가 없다. 보스 레이드는 기록 수직 기능이 아직 구현되지 않아 이 결정에 포함하지 않는다.

## 2. 모델 정정 계약

- 홈 캐릭터 모델의 렌더 좌표는 캐릭터 뷰포트의 가로·세로 중심이어야 한다(MUST).
- 모델 스케일은 실제 엔티티 신장과 뷰포트 너비를 함께 사용해 계산하고, 전신이 뷰포트 안에 남아야 한다(MUST).
- 일반 최대 홈 화면에서 전신 높이는 모델 뷰포트 높이의 최소 65%를 차지해야 한다(MUST). 현재 계산값은 약 72%다.
- 닉네임 줄은 모델 뷰포트 밖 패널 하단에 유지해야 한다(MUST).
- 공유 렌더러의 좌표 의미를 `bottom`으로 다시 해석하지 않아야 한다(MUST NOT). PvP 대기실 좌·우 모델도 자신의 가위 영역 중심을 전달해야 한다(MUST).

## 3. 허브 리더보드 계약

- 제목은 범용 `리더보드`/`Leaderboard`여야 한다(MUST).
- 구현된 기록 콘텐츠 선택은 `타워 / 팩토리 / PvP`여야 한다(MUST).
- 타워는 싱글·더블 2개 보드를 제공하고 최고 랭크→진행→누적 승리 순으로 정렬해야 한다(MUST).
- 팩토리는 싱글·더블과 `Lv.50 / 오픈` 조합 4개 보드를 제공하고 최고 연승 층→누적 승리→최고 연승→적은 패배 순으로 정렬해야 한다(MUST).
- PvP는 싱글·더블 2개 보드를 제공하고 누적 승리→최고 연승→적은 패배 순으로 정렬해야 한다(MUST).
- 완전 동점은 모든 보드에서 `1, 1, 3` 경쟁 순위를 사용해야 한다(MUST).
- 보스 레이드 기록 탭은 실제 기록 저장·정산 수직 기능이 생기기 전까지 만들지 않아야 한다(MUST NOT).

## 4. 부분 배포와 검증

- 기존 `home_leaderboard_state` 타워 payload는 구 클라이언트 호환용으로 유지한다(MUST).
- 새 `home_leaderboard_catalog`은 타워 2·팩토리 4·PvP 2의 총 8개 보드를 추가 전송한다(MUST).
- 서버는 클라이언트가 등록한 payload만 보내야 하며, 새 클라이언트가 구 서버에 연결되면 기존 타워 보드로 폴백해야 한다(MUST).
- 구현 전 모델 중심·점유율, 3단 필터 레이아웃, 팩토리·PvP 정렬, 8보드 catalog와 codec 계약이 실패하는 것을 확인했다.
- 구현 후 본체 463개 테스트, 모듈 빌드, 한·영 JSON 파싱과 JDK 21 JAR 검증이 통과했다. 통합 본체 SHA-256은 `26C07D1C2B3634FCDF818BBB59C56B5D143AC558E380B51241067BD7514A4FF7`이다.
- 현재 소스의 공개 AI 계약과 함께 Better AI 86개 테스트·빌드·JAR 검증도 통과했으며 대응 Better AI SHA-256은 `9C0898A84E97CD9C5A2F4D3B0E02FC9D9BEA862FCE8DF068983F7CBB3BACDB70`이다.
- 통합 본체 `26C07D1C2B3634FCDF818BBB59C56B5D143AC558E380B51241067BD7514A4FF7`은 개발 서버와 종료 상태의 `cobblemon-dev` 클라이언트에 모두 배치했다. 클라이언트의 이전 본체 `F6CAB749705B980B93ED45524A026F3BA69A3CF7E764423DFA4BF03A5AA3633E`는 `mod-backups/20260819-152000-before-home-model-leaderboards`에 보존했다. 서버는 Java PID 34908로 `127.0.0.1:25566`을 수신 중이며, 실제 전신 점유율과 8개 리더보드 전환은 다음 클라이언트 실행에서 시각 검증해야 한다.

## 5. 폐기한 대안

- **하단 좌표 유지 후 스케일만 확대:** 잘리는 전신 절반도 함께 커지므로 폐기했다.
- **타워 제목만 `리더보드`로 변경:** 서버 데이터 범위는 그대로라 사용자 문제를 숨길 뿐 해결하지 못하므로 폐기했다.
- **미구현 보스 레이드 빈 탭 추가:** 실제 기록이 없는 가짜 기능이므로 폐기했다.
