## 1. 변경 이유

스키마 3의 `move_slots`, `held_items`, `nature_pool`은 한 템플릿 안에서 기술·도구·성격을 다시 조합하는 MBC 고유 구조였다. 본가 배틀팩토리는 완성된 프리셋을 먼저 정의하고, 무작위성은 프리셋 내부가 아니라 어떤 프리셋이 후보로 뽑히는지에만 적용한다.

MBC는 2026-08-22부터 이 원칙을 따른다. 포켓몬 수가 본가 당시보다 크게 늘어난 점을 반영해 Cobblemon 1.7.3에 실제 구현된 501종·폼에 네 프리셋씩 총 2,004개를 제공한다.

## 2. 스키마 4 계약

- 제품 JSON은 `schema_version: 4`를 사용해야 한다(MUST).
- 렌탈 한 세트는 종·폼, 특성, 정확히 네 기술, 지닌 도구 하나, 성격 하나, 노력치와 AI용 공개 역할 정보를 모두 고정해야 한다(MUST).
- `move_slots`, `held_items`, `nature_pool` 같은 내부 후보 필드를 두면 안 된다(MUST NOT).
- 드래프트와 NPC 팀 선발은 완성 세트만 무작위로 골라야 하며, 선택된 세트의 기술·도구·성격을 다시 추첨하면 안 된다(MUST NOT).
- 트레이너 신원과 렌탈 팀은 분리해야 한다(MUST). NPC도 해당 라운드에서 플레이어에게 제공되는 것과 같은 완성 렌탈 풀을 사용한다(MUST).
- 초기 후보와 NPC 팀은 같은 종족과 같은 지닌 도구를 중복해서는 안 된다(MUST).
- 라운드별 균일 개체값과 교환 횟수에 따른 다음 풀 렌탈 제공은 완성 세트 선택과 별도인 본가 진행 규칙으로 유지한다(MUST).

## 3. 데이터 규모와 생성 근거

- 내장 카탈로그는 84명의 트레이너와 2,004개의 완성 렌탈세트를 포함한다.
- 501종·폼마다 정확히 네 개의 고정 프리셋을 제공한다.
- 라운드별 풀 크기는 `120 / 210 / 320 / 397 / 320 / 268 / 369`다.
- 생성기는 Cobblemon 1.7.3 JAR 안의 Showdown 랜덤 배틀 역할 데이터와 정확한 종·폼 learnset·특성 목록을 함께 읽는다.
- 생성 결과는 고정 JSON으로 저장한다. 게임 실행 중 생성기를 호출하거나 후보를 다시 조합하지 않는다(MUST NOT).

## 4. 호환과 종료 선언

- 스키마 1·2·3 읽기 호환은 2026-08-22에 종료한다.
- 스키마 1·2·3을 스키마 4처럼 묵시적으로 해석하는 경로는 다시 추가하지 않는다(MUST NOT).
- 과거 스키마 문서는 결정 이력으로만 남으며 현행 구현 계약으로 사용하지 않는다.
- 서버 데이터팩이 과거 팩토리 카탈로그를 덮어쓰고 있다면 스키마 4의 완성 세트 형식으로 직접 갱신해야 한다(MUST).

## 5. 검증

- 스키마 4 전용 로더, 후보 필드 거절, 과거 스키마 거절을 실패 테스트부터 구현했다.
- 2,004세트 전체의 정확한 네 기술, 고정 도구·성격, 종·폼별 네 프리셋을 검증한다.
- 모든 기술과 특성을 Cobblemon 1.7.3의 정확한 종·폼 데이터와 대조하고, 성격과 도구도 같은 런타임 JAR의 등록 자료와 대조한다.
- 모든 진행 풀의 싱글·더블 선발과 10,000회 드래프트·상대 팀 시뮬레이션에서 종족·도구 중복 금지와 프리셋 불변성을 검증한다.

## 6. 채택하지 않은 대안

- **기술 후보 중 네 개 추첨:** 본가의 완성 프리셋 구조가 아니며 표시·전투 구성의 예측 가능성을 해치므로 폐기했다.
- **성격·도구만 랜덤 유지:** 같은 프리셋의 실제 능력치와 역할이 매번 달라져 완성 세트라는 계약을 깨므로 폐기했다.
- **기존 391세트의 단일 후보만 평탄화:** 형식만 고치고 반복 노출 문제를 남기므로 폐기했다.
- **트레이너별 전용 렌탈 풀 유지:** NPC가 플레이어와 같은 라운드 렌탈 풀을 사용한다는 본가 구조와 어긋나므로 폐기했다.
