# Cobblemon Battle Tower 레퍼런스 분석 정리표

> **Updates:** 현재 MBC 채택 결정은 [`TERMINAL_AND_BP.md`](../architecture/TERMINAL_AND_BP.md)가 이 표의 초기 블럭 폐기·BP 선택 결정을 갱신한다.

이 문서는 [`BATTLE_TOWER_REFERENCE_ANALYSIS.md`](BATTLE_TOWER_REFERENCE_ANALYSIS.md)의 결정을 빠르게 조회하기 위한 별도 표다. 세부 근거와 분석 한계는 상세 문서를 따른다.

## 1. 증거와 신뢰도

| 항목 | 결과 | 신뢰도 |
|---|---|---|
| 분석 버전 | Fabric 1.10.22 / Modrinth `PkRUcN3J` | 높음 |
| 로컬 파일 동일성 | Modrinth SHA-512와 일치 | 높음 |
| JAR 구조 | Java 21 검증, 목록·메타데이터·디컴파일 교차 확인 | 높음 |
| 공개 기능 | Modrinth 설명과 구현 교차 확인 | 높음 |
| GUI 시각 | 갤러리 원본 3장과 렌더 코드 교차 확인 | 높음 |
| 런타임 체감 | 게임 실행 안 함 | 미검증 |
| 보안 위험 | 정적 경로 확인, 공격 재현 안 함 | 중간~높음 |
| 라이선스 | Modrinth와 JAR 모두 ARR | 높음 |

## 2.1 Boss Mode 분석·채택표

| 관찰 영역 | 1.10.22 동작 | MBC 결정 |
|---|---|---|
| 콘텐츠 성격 | 일반 트레이너전과 분리된 1~3인 공유 보스전 | PvE `보스 레이드(협동 레이드형)`로 채택 |
| 파티 구성 | 1인 6마리, 2인 각 3마리, 3인 각 2마리 | 1~3인은 그대로 채택. MBC는 4인을 추가하며 파티 수·HP 보정은 보스 레이드 결정 문서 11장을 따름 |
| 체력 | 참가자별 전투 피해를 하나의 보스 HP에 합산하고 전원에게 동기화 | 서버 권위 공유 HP와 단일 phase revision을 MUST로 정의 |
| 참가자 전멸 | 한 명만 전멸하면 대기하고 남은 참가자는 계속함 | 개인 `ELIMINATED_WAITING` 상태 채택 |
| 포기·연결 종료 | 한 명의 포기나 연결 종료로 전체 도전 실패 | 그대로 확정하지 않음. 복구·공정성 정책 결정 필요 |
| 진행 | 41개 고정 층, 이후 전체 풀 무작위 | 데이터 기반 보스 진행 경로로 변형 |
| 단계 전환 | 특정 층에서 1형태 승리 후 더 강한 2형태와 새 연출로 전환 | 선택적 다단계 전이 정의로 채택 |
| HP 배율 | 1~41층 15배, 이후 20배. 참가 인원은 배율에 영향 없음 | 원본 수치 폐기. 밸런스 데이터로 새로 작성하되 인원 수를 인자로 받는 산식으로 선언 |
| 매칭 | 같은 층·레벨·전설 허용·팀 모드·인원 설정만 매칭, 5분 만료 | 명시적 queue key와 timeout 계약 채택 |
| 의존성 | Boss Mode에 Mega Showdown 필요 | 초기 콘텐츠의 필수 의존 여부는 별도 결정 |
| 보상·기록 | 보스 전용 BP 계산과 Boss 최고 층·연승 기록 | BP 경제는 공통 사용, 보스별 지급량은 보스 밸런스 단계에서 결정, 기록 capability는 채택 |
| 구현 방식 | 참가자별 전투와 공유 HP를 다수 Mixin으로 결합 | 원본 구현 폐기. 호환 계층과 보스 세션을 분리 |
| 자산·편성 | 고정 보스, 음악, 시각 효과와 커스텀 기술 포함 | 복사 금지. 새 데이터와 자산으로 독립 제작 |

## 3. GUI 결정표

| 원본 UI 요소 | 장점 | 문제 | 새 계약 |
|---|---|---|---|
| 380×260 고정 패널 | 밀도 높고 일관됨 | 번역·해상도 대응 취약 | 최소 폭에 따라 3→2→1열 reflow |
| 좌측 파티 rail | 전투 준비 상태 즉시 인식 | 폭이 좁고 색 의존 | 모델/아이콘 폴백, 텍스트 검증 배지 |
| 중앙 타워 | 목표와 진척이 강하게 보임 | 타워 소재에 종속 | 콘텐츠별 `ProgressRenderer` |
| 우측 상점 | 보상 소비가 가까움 | 플레이 핵심과 경쟁 | BP 잔액은 공통 표시하고 상점 패널은 확정된 화면 범위에 맞춰 노출 |
| 상단 4탭 | 플레이·과제·기록·도움 연결 | 화면별 헤더 중복, 폭 부족 | 공통 shell navigation |
| 값 클릭 순환 | 공간을 적게 씀 | 선택지와 다음 값이 보이지 않음 | segmented control 또는 dropdown |
| disabled tooltip | 실패 이유 제공 | 필수 정보가 hover에 숨음 | 본문 필드 오류 + tooltip 보조 |
| hover 기반 hitbox | 구현 단순 | render와 click 결합 | widget/layout이 독립 hitbox 소유 |
| 100ms 눌림 효과 | 반응감 | 서버 처리 상태를 뜻하지 않음 | pending spinner, 결과와 revision 표시 |
| 색상 강조 | 분위기와 구분이 강함 | 색각·접근성 문제 | 색 + 아이콘 + 문구 중 2개 이상 |
| Esc 닫기 차단 | 우발 닫기 방지 | 사용자가 갇혔다고 느낄 수 있음 | Back/Esc 정책과 손실 확인 분리 |

## 4. 구현 위험표

| 발견 | 원본 경로 | 심각도 | MBC 방지책 |
|---|---|---:|---|
| 음수 구매 수량 거부 없음 | C2S purchase → `cost * quantity` → `spendBP` | 높음 | 양수·상한·오버플로 서버 검증 |
| 품목별 구매 패킷 | GUI 장바구니 반복 전송 | 높음 | 카트 전체 단일 transaction |
| 검증 전 run 활성화 | `startRun()` 후 snapshot 비교 | 높음 | 사전 검증 후 한 번에 session commit |
| 구조화 실패 응답 없음 | mutation 성공 때만 sync | 높음 | typed result와 request ID |
| 임의 blockPos 가능성 | start payload가 좌표 포함 | 중간~높음 | 서버 발급 진입 컨텍스트 |
| 클라이언트 낙관 초기화 | 포기·구매 클릭 직후 로컬 clear | 중간 | 서버 ack 후 state 반영 |
| 직접 DAT 덮어쓰기 | UUID별 NBT save | 중간 | 임시 파일 + atomic replace + backup |
| 4,600줄 manager | 세션·보스·복구·연동 집중 | 높음 | session/arena/match/recovery adapter 분리 |
| 2,690줄 screen | layout/render/input/network 집중 | 높음 | shell/view state/controller/widget 분리 |
| 반사 호출 다수 | Mega Showdown, Cobblemon GUI, registry | 높음 | integration adapter에 격리 |
| 25개 Mixin 등록 | Cobblemon/Showdown 내부 개입 | 높음 | 최소 Mixin, 버전별 계약 테스트 |
| 미등록 Mixin 클래스 3개 | JAR에는 있으나 config에 없음 | 낮음 | 빌드 residue 검사 |
