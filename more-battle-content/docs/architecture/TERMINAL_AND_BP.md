## 1. 정정 배경

이전 문서는 “배틀 블럭도 없이 한 모드로 통합한다”는 결정을 물리적 진입 블럭까지 제거한다는 뜻으로 잘못 확대 해석했다. 정확한 결정은 별도 Battle Block 모드나 블럭 중심 모듈 경계를 만들지 않고, `Cobblemon: More Battle Content` 본체가 선택형 UX 장치인 홀로 배틀 터미널을 직접 제공한다는 뜻이다.

이 문서는 위 오해를 정정하고 홀로 터미널, 명령어와 BP 경제의 활성 계약을 확정한다. 과거 분석 기록은 증거로 보존하되 현재 제품 계약은 이 문서가 우선한다.

## 2. 홀로 배틀 터미널

- **MUST:** 본체는 월드에 설치하고 상호작용할 수 있는 홀로 배틀 터미널 블럭을 제공한다.
- **MUST:** 터미널은 콘텐츠 규칙을 소유하지 않는 선택형 UX 어댑터다. 터미널이 없거나 파괴돼도 명령어를 통한 주요 기능과 이미 시작된 세션이 중단돼서는 안 된다.
- **MUST:** 첫 구현의 월드 외형은 전용 PNG 텍스처와 Blockbench 모델 자산을 요구하지 않는 클라이언트 코드 생성 홀로그램으로 만든다. 서버에는 선택·상호작용·위치 검증을 위한 실제 블럭과 블럭 엔티티가 존재한다.
- **MUST:** 코드 렌더러는 반투명 기하, 색상, 밝기, 스캔 또는 맥동 효과로 터미널을 표시한다. 렌더링 실패가 서버 로직, 명령어와 배틀 진행에 영향을 주어서는 안 된다.
- **MUST:** 블럭 엔티티에는 터미널 식별자와 표시 설정처럼 UX에 필요한 최소 상태만 둔다. 파티, BP 잔액, 진행도와 활성 배틀 세션을 블럭 엔티티에 저장해서는 안 된다.
- **MUST:** 터미널 우클릭은 서버가 거리, 차원, 블럭 존재와 사용 권한을 검증한 뒤 서버 발급 `entryContextId`로 공통 Battle Hub를 연다.
- **MUST:** 월드와 인벤토리의 터미널 표현은 같은 절차적 시각 언어를 사용한다. 인벤토리 표현은 내장 엔티티형 아이템 렌더러 등 코드 경로를 사용하며 전용 텍스처 자산을 구현 전제조건으로 삼지 않는다.
- **MUST NOT:** ARR 레퍼런스의 터미널 모델, 텍스처, 트레이너 스킨, 색상 배치와 애니메이션을 복사하거나 변형 이식해서는 안 된다.
- **SHOULD:** 애니메이션 값은 정점마다 현실 시간을 다시 읽지 않고 게임 시간과 프레임 보간값에서 렌더 단위로 한 번 계산한다.
- **MAY:** 실제 클라이언트 검증 뒤 홀로그램의 형태, 색상과 움직임을 교체하거나 독자 자산을 추가할 수 있다. 이 변경은 서버 서비스와 저장 형식에 영향을 주지 않아야 한다.

## 3. 명령어와 GUI의 동등한 기능 경로

- **MUST:** 터미널, GUI 패킷과 명령어는 동일한 본체 애플리케이션 서비스를 호출한다.
- **MUST NOT:** 터미널이나 GUI가 문자열 명령어를 조립해 명령 디스패처를 우회 호출해서는 안 된다.
- **MUST:** 블럭 없이도 명령어로 콘텐츠 열기, 상태 확인, 시작, 재개와 포기를 수행할 수 있어야 한다. 정확한 하위 명령 이름은 구현 전에 명령 계약 테스트로 고정한다.
- **MUST:** 터미널에서 시작한 요청과 명령어에서 시작한 요청은 같은 검증, 멱등성, 세션 전이와 오류 형식을 사용한다.
- **MUST:** 물리적 터미널에서 연 화면은 검증된 터미널 위치를 귀환·근접 전투 문맥으로 사용할 수 있다. 명령어로 시작한 화면은 서버가 발급한 비블럭 진입 문맥을 사용하며 임의 클라이언트 좌표를 신뢰하지 않는다.

## 4. Battle Point 경제

- **MUST:** BP 통화는 본체의 공통 시스템으로 유지한다.
- **MUST:** BP 시스템은 플레이어 잔액, 멱등 거래 원장, 거래 이력, 콘텐츠 보상 정산과 BP 상점을 제공한다.
- **MUST:** 배틀타워 승리·승급을 포함한 콘텐츠 보상은 고유 정산 ID를 사용해 중복 지급을 막는다.
- **MUST:** BP 상점의 품목과 가격은 서버 데이터로 정의하고 구매는 카트 전체를 한 번의 서버 권위 트랜잭션으로 처리한다.
- **MUST:** 구매 수량은 양수와 서버 상한을 검증하고 비용 계산의 정수 오버플로와 잔액 부족을 거부한다.
- **MUST:** 일반 플레이어는 자신의 잔액과 거래 이력을 조회할 수 있다.
- **MUST:** BP 변경 명령은 `/mbc bp add`, `/mbc bp remove`, `/mbc bp set` 아래에 두며 별도 `/mbc admin` 네임스페이스를 만들지 않는다.
- **MUST:** `add`, `remove`, `set`은 Minecraft 명령 권한 레벨 2 이상만 실행할 수 있다. 다른 플레이어의 잔액·이력 조회도 같은 권한 검사를 적용한다.
- **MUST:** 명령어와 상점은 같은 BP 서비스와 거래 원장을 사용한다.
- **SHOULD:** 콘텐츠별 BP 지급량, 승급 보너스, 상점 품목과 가격은 코드가 아니라 서버 데이터로 조정한다.

## 5. 유지되는 결정 게이트

BP와 상점의 **존재 여부** 및 터미널 **진입 방식**은 더 이상 열린 결정이 아니다. 다음 세부 항목만 빡대리님 결정 전까지 해당 구현 범위를 차단한다.

1. **결정자:** 빡대리님  
   **대상:** 첫 배틀타워 MVP에서 Challenges, Records, Guide와 BP 상점 패널을 어느 순서까지 노출할지  
   **시점:** 첫 실제 Screen 범위 확정 전

2. **결정자:** 빡대리님  
   **대상:** 기존 월드의 BP 잔액·거래 이력·타워 진행도를 새 저장 형식으로 변환할지  
   **시점:** 마이그레이터 구현 전  
   **열린 이유:** 새 BP 시스템 존치와 과거 데이터 자동 변환은 별개이며, 중복 지급과 기록 오염을 피하려면 원본 저장 데이터 확인이 필요하다.

3. **결정자:** 빡대리님  
   **대상:** 최종 BP 지급량, 승급 보너스와 첫 기본 상점 카탈로그  
   **시점:** 배틀타워 밸런스 데이터 확정 전
